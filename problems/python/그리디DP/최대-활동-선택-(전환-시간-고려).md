# 최대 활동 선택 (전환 시간 고려)
*python · 그리디/DP · 보통 · 정렬, DP, 탐욕 알고리즘*

## 입출력 환경

Python 환경에서 sys.stdin.read().split() 또는 반복문을 사용하여 입력을 받습니다.

## 문제

당신은 여러 개의 작업을 수행할 수 있는 엔지니어입니다. 각 작업은 시작 시간, 종료 시간, 그리고 해당 작업을 마친 후 다음 작업을 준비하는 데 필요한 최소 '전환 시간'을 가집니다. 

여러 작업 중 선택할 수 있는 작업의 최대 개수를 구하는 것이 목표입니다. 

작업 $i$가 종료된 시간 $E_i$와 다음 작업 $j$의 시작 시간 $S_j$가 주어졌을 때, 작업 $i$ 다음에 작업 $j$를 수행하려면 $S_j$가 $E_i + C_i$보다 크거나 같아야 합니다. 여기서 $C_i$는 작업 $i$의 전환 시간입니다.

만약 선택된 작업 순서가 $T_1, T_2, ..., T_k$라면, 다음 조건이 만족되어야 합니다:
1. $T_1$은 시작 가능.
2. $T_{i+1}$의 시작 시간은 $T_i$의 종료 시간과 $T_i$의 전환 시간을 합한 값보다 크거나 같아야 한다.

작업 정보는 (시작 시간 $S$, 종료 시간 $E$, 전환 시간 $C$)의 튜플로 주어집니다.

## 입력

첫 번째 줄에 작업의 총 개수 N이 주어집니다. 
다음 N줄에 걸쳐 각 작업의 정보 (S, E, C)가 공백으로 구분되어 주어집니다. (S <= E)

## 출력

선택할 수 있는 최대 작업 개수(정수)를 출력합니다.

## 제약 조건

1 <= N <= 1000
1 <= S, E, C <= 1000
(시간 복잡도는 O(N^2) 또는 O(N log N) 이내여야 합니다.)

## 예제 1

**입력**
```
4
1 3 2
3 5 1
6 8 3
10 12 1
```

**출력**
```
3
```

*작업 1(1, 3, 2) -> 작업 2(3, 5, 1) -> 작업 3(6, 8, 3) 순서로 최대 3개 선택 가능.*

## 예제 2

**입력**
```
3
1 2 1
2 3 1
3 4 1
```

**출력**
```
3
```

*모든 작업이 연속적으로 연결되어 최대 3개를 선택할 수 있다.*

## 힌트

- 활동 선택 문제는 일반적으로 그리디 알고리즘이나 DP로 풀 수 있습니다.
- 작업 순서가 중요하므로, 어떤 기준으로 작업을 정렬할지 고민해 보세요. (예: 종료 시간, 시작 시간 등)


## 알고리즘 요약

이 문제는 동적 계획법(Dynamic Programming, DP)을 활용하여 해결할 수 있습니다. 먼저 작업을 종료 시간(E) 기준으로 정렬합니다. 이후, 배열 $DP[i]$를 'i번째 작업을 마지막으로 포함하는 최대 작업 개수'로 정의하고, $DP[i]$를 계산하기 위해 $i$보다 작은 모든 작업 $j$를 검사합니다. 만약 작업 $j$ 다음에 작업 $i$를 수행할 수 있다면, $DP[i] = 	ext{max}(DP[i], DP[j] + 1)$로 갱신합니다.

## 풀이 해설

### 💡 아이디어
이 문제는 순서가 중요한 최장 경로 문제와 유사합니다. 단순히 종료 시간이 빠른 순서대로 선택하는 그리디 방식으로는 최적해가 보장되지 않으며, 특정 작업의 선택이 다음 작업의 가능성을 크게 제한할 수 있기 때문에 DP가 적합합니다.

### ⚙️ 단계
1. **정렬:** 작업을 반드시 특정 순서로 정렬해야 합니다. 이 문제에서는 작업의 종료 시간(E)을 기준으로 오름차순 정렬하는 것이 효율적입니다. 이렇게 하면, $DP[i]$를 계산할 때 $j < i$인 모든 작업 $j$는 $i$보다 종료 시간이 빠르다는 것을 보장받습니다.
2. **DP 배열 초기화:** $DP$ 배열을 준비합니다. $DP[i]$는 'i번째 작업을 마지막으로 포함하는 최대 작업 개수'를 저장합니다. 모든 $DP[i]$는 최소 1 (자기 자신)로 초기화합니다.
3. **DP 전이 (Transition):** $i=0$부터 $N-1$까지 반복합니다. $i$번째 작업을 마지막으로 하는 경우를 계산하기 위해, $j=0$부터 $i-1$까지 모든 $j$를 검사합니다.
    *   **조건 확인:** $j$번째 작업 다음에 $i$번째 작업을 수행할 수 있는지 확인합니다. 조건은 $S_i 	ext{ (i의 시작 시간)} 	ext{ } 	ext{>= } 	ext{ } E_j 	ext{ (j의 종료 시간)} + C_j 	ext{ (j의 전환 시간)}$ 입니다.
    *   **갱신:** 만약 조건이 만족되면, 이는 $j$를 끝점으로 하는 경로에 $i$를 추가할 수 있다는 의미입니다. 따라서 $DP[i] = 	ext{max}(DP[i], DP[j] + 1)$로 갱신합니다.
4. **최종 결과:** 모든 $DP[i]$ 값 중 최댓값이 우리가 찾고자 하는 최대 작업 개수입니다.

### ⏱️ 시간 복잡도
- 정렬: $O(N 	imes 	ext{log} N)$ (여기서 N은 작업 개수)
- DP 계산: 이중 반복문 구조로 $O(N^2)$입니다.
- 전체 시간 복잡도는 $O(N^2)$로, $N 	ext{이 } 1000$일 때 충분히 효율적입니다.

## 참고 코드 (python)

```python
import sys

# 재귀 깊이 제한을 늘려 혹시 모를 문제를 방지
sys.setrecursionlimit(2000)

def solve():
    # 입력을 한 번에 읽고 공백 기준으로 분리
    input_data = sys.stdin.read().split()
    if not input_data: 
        return 0
    
    N = int(input_data[0])
    tasks = []
    
    # (S, E, C) 형태로 저장
    for i in range(N):
        s = int(input_data[i * 3 + 1])
        e = int(input_data[i * 3 + 2])
        c = int(input_data[i * 3 + 3])
        tasks.append((s, e, c))

    # 1. 종료 시간(E)을 기준으로 오름차순 정렬
    # tasks[i] = (S, E, C) 이므로, 인덱스 1을 기준으로 정렬합니다.
    tasks.sort(key=lambda x: x[1])

    # 2. DP 배열 초기화
    # dp[i] = i번째 작업을 마지막으로 하는 최대 작업 개수
    dp = [1] * N
    
    max_count = 0

    # 3. DP 계산
    for i in range(N):
        S_i, E_i, C_i = tasks[i]
        current_max = 1
        
        for j in range(i):
            S_j, E_j, C_j = tasks[j]
            
            # j 다음에 i를 수행할 수 있는지 확인
            # 조건: S_i >= E_j + C_j
            if S_i >= E_j + C_j:
                # j까지의 최대 개수에 1을 더하여 갱신
                current_max = max(current_max, dp[j] + 1)
        
        dp[i] = current_max
        max_count = max(max_count, dp[i])

    return max_count

if __name__ == "__main__":
    # 테스트를 위해 sys.stdin에 예제 입력이 주어지지 않은 경우를 대비하여 주석 처리
    # 실제 제출 환경에서는 이 부분이 실행됨
    print(solve())
```
