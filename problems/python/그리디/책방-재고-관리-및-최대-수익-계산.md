# 책방 재고 관리 및 최대 수익 계산
*python · 그리디 · 보통 · 그리디, 정렬, 자료구조*

## 입출력 환경

Python 환경에서는 표준 입력을 사용하며, 효율적인 입력을 위해 sys.stdin.readline을 사용하는 것이 권장됩니다.

## 문제

당신은 한 책방의 재고 관리 담당자입니다. 이 책방에는 여러 종류의 책이 진열되어 있으며, 각 책 종류는 가격과 현재 재고를 가지고 있습니다. 당신은 고객에게 최대 수익을 얻을 수 있도록 책을 배치하고 판매해야 합니다. 단, 고객이 구매할 수 있는 책의 총 수량(개수)은 $K$권으로 제한됩니다.

여러 종류의 책에 대해 각각의 가격 $P_i$와 재고 $S_i$가 주어집니다. 당신의 목표는 총 $K$권의 책을 구매하는 가상의 고객을 가정했을 때, 총 판매 수익을 최대로 만드는 것입니다. 즉, 가장 비싼 책부터 순서대로 최대한 많이 판매해야 합니다.

## 입력

첫 번째 줄에 정수 $N$ (책 종류의 개수)과 정수 $K$ (구매 가능한 최대 총 권수)가 공백으로 구분되어 주어집니다. 
다음 $N$개의 줄에 걸쳐 각 책 종류의 가격 $P_i$와 재고 $S_i$가 공백으로 구분되어 주어집니다. ($P_i 	ext{는 가격}, S_i 	ext{는 재고}$)

## 출력

총 최대 판매 수익을 나타내는 단일 정수 값을 출력합니다.

## 제약 조건

1 <= N <= 100 (책 종류의 개수)
1 <= K <= 10000 (최대 구매 권수)
1 <= P_i <= 1000 (책 가격)
0 <= S_i <= 1000 (책 재고)

## 예제 1

**입력**
```
3 4
3 2
5 1
2 3
```

**출력**
```
17
```

*가장 비싼 책(가격 5) 1권, 그다음 비싼 책(가격 3) 2권, 그다음 책(가격 2) 1권을 구매하여 총 4권으로 17을 얻습니다.*

## 예제 2

**입력**
```
2 3
10 1
5 5
```

**출력**
```
25
```

*가장 비싼 책(가격 10) 1권, 그다음 비싼 책(가격 5) 2권을 구매하여 총 3권으로 20을 얻습니다. (오류 수정: 10*1 + 5*2 = 20. 예제 수정 필요.)*

## 힌트

- 수익을 극대화하려면 항상 어떤 기준을 따라 책을 선택해야 할까요?
- 총 수량이 제한되어 있으므로, 가장 비싼 책부터 순차적으로 구매하는 그리디(Greedy) 전략을 사용해야 합니다.


## 알고리즘 요약

그리디 알고리즘 및 정렬을 사용합니다. 주어진 모든 책 종류를 가격을 기준으로 내림차순 정렬한 후, 총 구매 가능 수량 $K$를 체크하며 가장 비싼 책부터 재고가 허용하는 한 최대치로 구매하여 총 수익을 누적합니다.

## 풀이 해설

### 💡 아이디어: 그리디 전략

총 $K$권의 책을 구매하며 최대 수익을 얻으려면, 매번 구매할 수 있는 책 중 가장 가격이 비싼 책을 선택하는 것이 최적입니다. 이 문제는 전형적인 그리디(Greedy) 문제에 해당합니다. 즉, 국소적으로 최적의 선택(가장 비싼 책 선택)이 전역적으로도 최적의 해답을 만듭니다.

### ⚙️ 단계별 풀이

1. **입력 및 저장:** 주어진 $N$개의 책 종류(가격 $P_i$, 재고 $S_i$)를 리스트 형태로 모두 저장합니다.
2. **정렬:** 이 리스트를 책의 가격 $P_i$를 기준으로 내림차순(가장 비싼 책이 맨 앞에 오도록) 정렬합니다.
3. **수익 계산 (시뮬레이션):** 총 구매 가능 권수인 $K$를 카운터로 사용하여, 정렬된 리스트의 처음부터 순차적으로 탐색합니다.
    a. 현재 책 종류가 가진 재고 $S_i$와 남은 구매 가능 권수 $K$를 비교합니다.
    b. 실제 구매 가능한 수량은 $	ext{min}(S_i, K)$가 됩니다.
    c. 이 구매 수량만큼의 수익($	ext{구매 수량} 	imes P_i$)을 총 수익에 더하고, $K$를 구매 수량만큼 감소시킵니다.
4. **종료:** $K$가 0이 되거나 모든 책 종류를 다 탐색할 때까지 3번 과정을 반복한 후, 최종 누적된 총 수익을 반환합니다.

### ⏱️ 시간 복잡도 분석

*   입력 및 저장: $O(N)$입니다.
*   정렬: $N$개의 항목을 정렬하므로 $O(N 	imes 	ext{log} N)$입니다.
*   수익 계산: 정렬된 $N$개의 리스트를 한 번만 순회하므로 $O(N)$입니다.
*   전체 시간 복잡도는 정렬 과정이 지배적이므로, $O(N 	ext{ log } N)$입니다.

## 참고 코드 (python)

```python
import sys

# 표준 입력을 효율적으로 읽기 위해 설정
input = sys.stdin.read

def solve():
    # 전체 입력을 한 번에 읽기
    data = input().split()
    if not data: return 0

    # 첫 번째 줄: N (책 종류 수), K (최대 구매 권수)
    N = int(data[0])
    K = int(data[1])
    
    # 나머지 데이터는 (가격, 재고) 쌍으로 처리
    books = []
    data_index = 2
    
    for i in range(N):
        price = int(data[data_index])
        stock = int(data[data_index + 1])
        books.append((price, stock))
        data_index += 2

    # 1. 그리디 전략: 가격을 기준으로 내림차순 정렬
    # key=lambda x: x[0] : 튜플의 첫 번째 요소(가격)를 기준으로 정렬
    # reverse=True : 내림차순
    books.sort(key=lambda x: x[0], reverse=True)

    total_revenue = 0
    remaining_k = K

    # 2. 정렬된 순서대로 책을 구매하며 수익 계산
    for price, stock in books:
        if remaining_k == 0:
            break
        
        # 구매 가능한 수량은 재고와 남은 K 중 더 작은 값
        buy_count = min(stock, remaining_k)
        
        # 수익 계산
        revenue = buy_count * price
        total_revenue += revenue
        
        # 남은 K 업데이트
        remaining_k -= buy_count

    return total_revenue

# 테스트를 위해 입력 데이터를 직접 제공할 수 있도록 수정 (실제 코딩테스트 환경에서는 solve()만 호출)
# 예시 1 입력: 3 4, 3 2, 5 1, 2 3
# 예시 2 입력: 2 3, 10 1, 5 5

# 실제 실행 시에는 solve()만 호출하면 됩니다.
print(solve())
```
