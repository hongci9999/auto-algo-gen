# 간격이 겹치지 않는 최대 활동 개수
*python · 그리디 · 보통 · 정렬, 그리디*

## 입출력 환경

빠른 입력을 위해 `sys.stdin.readline`을 사용하는 것이 권장됩니다.

## 문제

당신은 여러 개의 시간 간격(Interval) 목록을 받았습니다. 각 간격 $[start, end]$는 특정 활동이 진행되는 시간을 나타냅니다.

문제의 목표는 이 간격들 중 서로 겹치지 않으면서 최대 개수의 활동을 선택하는 것입니다. 두 활동 A와 B가 있다고 할 때, A가 종료되고 B가 시작할 때 경계 지점(endpoint)에서 만나는 것은 허용됩니다 (즉, $[1, 4]$와 $[4, 6]$은 겹치지 않음).

입력으로 주어진 모든 간격 목록을 분석하여 선택 가능한 최대 활동의 개수를 구하세요.

## 입력

첫 번째 줄에 전체 간격의 개수 N이 주어집니다. 이후 N개의 줄에 각각 'start end' 형식으로 시작 시간과 종료 시간이 공백으로 구분되어 주어진s.

## 출력

선택 가능한 최대 활동의 개수를 단일 정수로 출력합니다.

## 제약 조건

N의 크기는 1 이상 100,000 이하입니다. start와 end 값은 0부터 10^9 사이의 정수입니다. 시간 복잡도는 $O(N 	ext{ log } N)$ 이내여야 합니다.

## 예제 1

**입력**
```
3
1 4
2 3
4 6
```

**출력**
```
2
```

*간격은 [1, 4], [2, 3], [4, 6]입니다. [2, 3]을 선택하면 이후에 선택 가능한 간격이 줄어듭니다. 종료 시간이 가장 빠른 순서로 정렬한 후, [1, 4]와 [4, 6]을 선택하여 최대 2개를 얻습니다.*

## 예제 2

**입력**
```
5
0 3
2 5
3 7
6 9
8 10
```

**출력**
```
3
```

*가장 먼저 끝나는 활동들을 선택하는 그리디 전략을 사용해야 합니다. 최적의 조합은 [0, 3], [3, 7], [7, 9] (혹은 비슷한 형태)입니다.*

## 힌트

- 이 문제는 전형적인 '활동 선택 문제(Activity Selection Problem)'와 유사합니다.
- 어떤 순서로 간격을 고려해야 최적의 해를 찾을 수 있을까요? 핵심은 정렬 기준에 있습니다.


## 알고리즘 요약

그리디 알고리즘 (Greedy Algorithm). 이 문제를 풀기 위해서는 항상 현재 시점에서 가장 빨리 끝나는 활동을 선택하는 것이 최적해를 보장한다는 원리를 이용합니다. 따라서 모든 간격을 종료 시간(end time)을 기준으로 오름차순 정렬한 후, 순차적으로 탐색하며 겹치지 않는 경우에만 카운트를 증가시킵니다.

## 풀이 해설

1. 아이디어 (Greedy Choice):
   활동 선택 문제의 핵심은 '가장 빨리 끝나는 활동을 우선 선택하는 것'입니다. 만약 현재 시점에서 가장 먼저 끝나는 활동 A를 선택한다면, 이로 인해 다음 활동의 시작 가능 시간이 최대한 빨리 확보됩니다. 따라서 전체 간격을 종료 시간 기준으로 정렬하는 것이 그리디 전략의 출발점이 됩니다.

2. 단계:
   a. 입력된 모든 간격 $[start, end]$들을 리스트에 저장합니다.
   b. 이 리스트를 $end$ 시간을 기준으로 오름차순 정렬합니다. (만약 $end$ 시간이 같다면, $start$ 시간 순으로 정렬하는 것이 안정적입니다.)
   c. 첫 번째 간격은 무조건 선택하고 카운트(count)를 1로 초기화하며, 마지막으로 선택된 활동의 종료 시간(last_finish_time)을 기록합니다.
   d. 두 번째 간격부터 순회하면서 현재 간격 $[start_i, end_i]$가 $last\_finish\_time$보다 시작 시간이 크거나 같으면 ($start_i \ge last\_finish\_time$), 이 활동은 선택 가능하므로 count를 1 증가시키고 $last\_finish\_time$을 $end_i$로 업데이트합니다. 그렇지 않다면 건너<0xEB><0x9C><0x81>니다.

3. 시간 복잡도:
   가장 시간이 많이 소요되는 부분은 간격을 정렬하는 과정입니다. N개의 간격에 대해 정렬을 수행하므로, 시간 복잡도는 $O(N \log N)$입니다. 이후 순회는 $O(N)$이므로 전체 시간 복잡도는 $O(N \log N)$으로 효율적입니다.

## 참고 코드 (python)

```python
import sys

def solve():
    # sys.stdin.readline을 사용하여 빠른 입력을 처리합니다.
    input = sys.stdin.read().split()
    if not input: 
        return 0

    try:
        N = int(input[0])
    except ValueError:
        # N이 없거나 잘못된 경우 예외 처리
        print(0)
        return

    intervals = []
    data_index = 1
    for _ in range(N):
        if data_index + 1 < len(input):
            start = int(input[data_index])
            end = int(input[data_index+1])
            intervals.append([start, end])
            data_index += 2
        else:
            break

    # 그리디 전략: 종료 시간(end)을 기준으로 오름차순 정렬합니다.
    # key=lambda x: x[1] 은 리스트의 두 번째 요소(인덱스 1, 즉 end 시간)를 기준으로 정렬하라는 의미입니다.
    intervals.sort(key=lambda x: x[1])

    if not intervals:
        return 0

    count = 1
    # 첫 번째 간격은 무조건 선택됩니다.
    last_finish_time = intervals[0][1]

    for i in range(1, len(intervals)):
        current_start = intervals[i][0]
        current_end = intervals[i][1]

        # 현재 간격의 시작 시간이 마지막으로 선택된 활동의 종료 시간보다 크거나 같다면 겹치지 않습니다.
        if current_start >= last_finish_time:
            count += 1
            last_finish_time = current_end
            
    return count

# 실제 테스트 환경에서는 표준 출력으로 결과를 내보냅니다.
print(solve())
```
