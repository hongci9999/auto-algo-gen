# 최대 활동 선택 문제
*python · 그리디 · 보통 · 그리디, 정렬*

## 입출력 환경

입력은 표준 입력으로부터 받으며, 성능을 위해 sys.stdin.readline을 사용하는 것이 좋습니다.

## 문제

당신은 여러 개의 활동을 수행할 수 있습니다. 각 활동은 시작 시간과 종료 시간을 가집니다. 단, 하나의 활동을 하는 동안에는 다른 활동을 할 수 없습니다. 주어진 활동들 중에서 서로 겹치지 않으면서 가장 많은 활동을 선택하는 최대 개수를 구하세요.

(활동 A와 활동 B가 겹친다는 것은, 두 활동의 시간 구간 $[Start_A, End_A]$와 $[Start_B, End_B]$가 어느 지점에서라도 겹치는 경우를 의미합니다. 만약 한 활동이 끝나는 순간 다른 활동이 시작하는 경우(예: End_A = Start_B)는 겹치지 않는 것으로 간주합니다.)

## 입력

첫째 줄에 활동의 총 개수 N이 주어집니다. 
다음 N줄에 걸쳐 각 활동의 시작 시간 $S_i$와 종료 시간 $E_i$가 순서대로 주어집니다. (S_i와 E_i는 1 이상 100,000 이하의 정수입니다.)

## 출력

선택할 수 있는 최대 활동의 개수를 한 정수로 출력합니다.

## 제약 조건

N은 1부터 100,000 이하의 정수입니다. 시작 시간과 종료 시간은 1부터 100,000 이하의 정수입니다. 시간 복잡도는 $O(N 	ext{ log } N)$ 이하를 목표로 합니다.

## 예제 1

**입력**
```
3
1 4
2 5
4 6
```

**출력**
```
2
```

*활동 (1, 4)와 (4, 6)을 선택할 수 있습니다. 최대 2개입니다.*

## 예제 2

**입력**
```
4
0 10
0 1
1 2
2 3
```

**출력**
```
3
```

*활동 (0, 1), (1, 2), (2, 3)을 선택하는 것이 최대입니다.*

## 예제 3

**입력**
```
5
1 2
1 3
2 4
3 5
4 6
```

**출력**
```
3
```

*활동 (1, 2), (2, 4), (4, 6) 또는 (1, 2), (2, 3), (3, 5)가 가능합니다. 최대 3개입니다.*

## 힌트

- 모든 활동을 선택할 수 없으므로, 탐욕적인 접근(Greedy)을 고려해 보세요.
- 무엇을 기준으로 정렬해야 최적의 해답을 얻을 수 있을지 생각해야 합니다.


## 알고리즘 요약

활동 선택 문제의 전형적인 그리디 알고리즘 문제입니다. 최대의 활동을 선택하기 위해서는, 현재 가능한 활동들 중에서 가장 빨리 끝나는 활동을 선택하는 것이 가장 많은 후속 활동을 선택할 기회를 주기 때문에 최적입니다. 따라서, 활동들을 '종료 시간'을 기준으로 오름차순 정렬한 후, 순차적으로 탐욕적으로 선택합니다.

## 풀이 해설

이 문제는 그리디(탐욕) 알고리즘을 사용하여 해결할 수 있습니다. 핵심 아이디어는 '남은 시간 동안 가능한 활동을 최대한 많이 선택'하는 것입니다. 따라서, 현재 선택하는 활동은 다음 활동을 시작할 수 있는 시간을 최대한 빨리 확보해 주는 활동이어야 합니다.

**1. 정렬 기준 설정:** 활동을 종료 시간(End Time)을 기준으로 오름차순 정렬해야 합니다. 이렇게 해야 항상 가장 빨리 끝나는 활동부터 고려할 수 있습니다.

**2. 그리디 선택 과정:**
*   첫 번째 활동을 선택하고, 이 활동의 종료 시간을 `last_finish_time`으로 설정합니다.
*   두 번째 활동부터 순회하며, 현재 활동의 시작 시간($S_i$)이 `last_finish_time`보다 크거나 같다면 (즉, 겹치지 않는다면), 이 활동을 선택합니다.
*   활동을 선택할 때마다, `last_finish_time`을 현재 활동의 종료 시간($E_i$)으로 업데이트하고, 선택된 활동 개수를 1 증가시킵니다.
*   이 과정을 모든 활동에 대해 반복하면, 주어진 제약 조건 하에서 최대의 활동 개수를 찾을 수 있습니다.

**3. 시간 복잡도:** 활동을 읽고 저장하는 데 $O(N)$이 걸리며, 가장 큰 부분은 활동을 종료 시간 기준으로 정렬하는 과정($O(N 	ext{ log } N)$)입니다. 이후 순회하며 선택하는 과정은 $O(N)$이므로, 전체 시간 복잡도는 $O(N 	ext{ log } N)$입니다.

## 참고 코드 (python)

```python
import sys

def solve():
    # sys.stdin.read()를 사용하여 모든 입력을 한 번에 읽어옵니다.
    data = sys.stdin.read().split()
    if not data: return
    
    # 첫 번째 요소는 N (활동 개수)
    try:
        N = int(data[0])
    except IndexError:
        return
        
    activities = []
    # 나머지 데이터는 (S, E) 쌍으로 구성되어 있습니다.
    # data[1:] 슬라이싱을 사용하여 나머지 N*2 개 데이터를 처리합니다.
    for i in range(N):
        start_time = int(data[1 + i * 2])
        end_time = int(data[2 + i * 2])
        activities.append((start_time, end_time))
    
    # 핵심: 종료 시간을 기준으로 오름차순 정렬합니다. (A[i][1]이 종료 시간)
    # key=lambda a: a[1]을 사용하여 두 번째 원소(종료 시간)를 기준으로 정렬합니다.
    activities.sort(key=lambda x: x[1])
    
    count = 0
    # 마지막으로 선택된 활동의 종료 시간을 기록합니다. 초기값은 아주 작은 수로 설정합니다.
    last_finish_time = -1
    
    for start, end in activities:
        # 현재 활동의 시작 시간이 마지막 활동의 종료 시간보다 크거나 같으면 (겹치지 않으면)
        if start >= last_finish_time:
            count += 1
            # 이 활동을 선택했으므로, 마지막 종료 시간을 업데이트합니다.
            last_finish_time = end
            
    print(count)

if __name__ == "__main__":
    solve()
```
