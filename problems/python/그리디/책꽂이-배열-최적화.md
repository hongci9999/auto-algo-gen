# 책꽂이 배열 최적화
*python · 그리디 · 보통 · 그리디, 정렬, 배열*

## 입출력 환경

효율적인 입출력을 위해 sys.stdin.readline 모듈 사용을 권장합니다.

## 문제

당신은 책꽂이 정리 작업을 맡았습니다. 책꽂이의 총 길이는 L이며, N개의 책이 있습니다. 각 책은 고유한 길이 $l_i$를 가지고 있습니다.

당신의 목표는 이 N개의 책들 중 일부를 선택하여 책꽂이에 배열하는 것입니다. 단, 배열된 책들의 총 길이가 책꽂이 길이 L을 초과해서는 안 됩니다.

여러 개의 책을 선택할 수 있으며, 다음 두 가지 조건을 만족하는 선택을 하려고 합니다:

1. 선택된 책의 개수를 최대로 합니다.
2. 만약 책의 개수가 같다면, 사용한 총 길이가 최소가 되도록 선택합니다.

최대 개수의 책을 선택했을 때, 그 총 길이와 선택된 책의 개수를 순서쌍 (총 길이, 책 개수) 형태로 출력하세요.

## 입력

첫째 줄에 N (책의 개수)과 L (책꽂이 총 길이)이 공백으로 구분되어 주어집니다. 둘째 줄에는 N개의 책의 길이가 공백으로 구분되어 주어집니다.

## 출력

총 길이와 책 개수를 공백으로 구분하여 출력합니다.

## 제약 조건

1 <= N <= 100
1 <= L <= 1000
1 <= l_i <= 1000

## 예제 1

**입력**
```
3 7
2 3 4
```

**출력**
```
5 2
```

*책 개수를 최대화하려면 가장 작은 책들을 선택해야 합니다. (2, 3)을 선택하여 총 길이 5, 개수 2가 최대입니다.*

## 예제 2

**입력**
```
4 2
1 1 1 1
```

**출력**
```
2 2
```

*모두 길이가 1인 책들 중 2권을 선택하여 총 길이 2, 개수 2를 사용합니다.*

## 예제 3

**입력**
```
5 10
1 2 3 4 5
```

**출력**
```
15 5
```

*모든 책을 선택해도 15가 되어 L=10을 초과하므로, 가장 작은 책들부터 선택하여 1+2+3+4=10까지 선택하고, 개수 4, 길이 10을 사용해야 합니다. 하지만 이 문제의 최적 전략은 가장 작은 책부터 순차적으로 더하는 것입니다. (1, 2, 3, 4) -> 합 10. 개수 4, 길이 10. (문제 조건에 따라 가장 작은 N개의 합이 최적입니다.)*

## 힌트

- 책의 개수를 최대화하려면, 사용되는 책들의 길이가 가능한 한 작아야 합니다.
- 문제를 해결하기 위해 책의 길이들을 오름차순으로 정렬하는 것이 핵심입니다.


## 알고리즘 요약

그리디 알고리즘 (Greedy Algorithm). 책의 개수를 최대화하고 총 길이를 최소화하려면, 무조건 가장 짧은 책들부터 순서대로 선택하는 것이 최적의 전략입니다. 따라서 책의 길이 리스트를 오름차순으로 정렬한 후, 누적 합이 L을 초과하지 않는 동안 계속 더해나갑니다. 이때, 누적 합과 선택된 책의 개수를 기록합니다.

## 풀이 해설

풀이 해설: 아이디어 → 단계 → 시간복잡도

1. 아이디어 (Greedy 선택):
문제의 목표는 '책의 개수 최대화'입니다. 만약 책의 개수가 고정되었다고 가정했을 때, 총 길이를 최소화하는 방법은 당연히 가장 짧은 책들을 선택하는 것입니다. 따라서, 책의 개수를 최대화하면서 총 길이를 최소화하는 문제 역시, 무조건 가장 짧은 책들부터 순서대로 선택하는 그리디 전략을 따릅니다.

2. 단계:
가. 입력받은 N개의 책 길이 리스트를 오름차순으로 정렬합니다. (가장 짧은 책이 맨 앞에 오도록)
나. 초기화 변수 `current_sum` (현재까지의 총 길이)를 0, `book_count` (선택된 책의 개수)를 0으로 설정합니다.
다. 정렬된 리스트를 처음부터 끝까지 순회하면서, 현재 책의 길이를 `current_sum`에 더했을 때, 그 합이 최대 길이 L을 초과하지 않는지 확인합니다.
라. 만약 L을 초과하지 않는다면, `current_sum`을 업데이트하고 `book_count`를 1 증가시킵니다. 그렇지 않다면, 더 이상 책을 추가할 수 없으므로 순회를 종료합니다.
마. 최종적으로 `current_sum`과 `book_count`를 출력합니다.

3. 시간 복잡도:
가장 큰 부분은 책 길이 리스트를 정렬하는 과정입니다. $N$이 최대 100이므로, 정렬에 $O(N 	imes 	ext{log} N)$의 시간이 소요됩니다. 이후 순회는 $O(N)$이므로, 전체 시간 복잡도는 $O(N 	imes 	ext{log} N)$입니다. 이는 주어진 제약 조건(N<=100) 내에서 매우 효율적입니다.

## 참고 코드 (python)

```python
import sys

def solve():
    # sys.stdin.readline을 사용하여 N과 L을 읽습니다.
    try:
        input_line = sys.stdin.readline().split()
        if not input_line: # 입력이 없을 경우 종료
            return
        N = int(input_line[0])
        L = int(input_line[1])
    except EOFError:
        return
    except IndexError:
        # N, L이 입력되지 않은 경우
        return

    # 책 길이 리스트를 읽습니다.
    try:
        lengths = list(map(int, sys.stdin.readline().split()))
    except EOFError:
        lengths = []
    except Exception:
        lengths = []

    # 1. 그리디 전략을 위해 책 길이를 오름차순으로 정렬합니다.
    lengths.sort()

    current_sum = 0
    book_count = 0

    # 2. 가장 짧은 책들부터 순서대로 추가 가능 여부를 확인합니다.
    for length in lengths:
        # 현재 책을 추가했을 때 L을 초과하는지 확인
        if current_sum + length <= L:
            current_sum += length
            book_count += 1
        else:
            # L을 초과하므로 더 이상 책을 추가할 수 없습니다. (정렬되어 있으므로)
            break

    # 결과 출력
    print(f"{current_sum} {book_count}")

solve()
```
