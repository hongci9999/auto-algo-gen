# 최대 합을 갖는 조건부 부분 배열 찾기
*python · 슬라이딩 윈도우 · 보통 · 슬라이딩 윈도우, 배열, 그리디*

## 입출력 환경

실제 코딩 테스트 환경을 가정하여, 모든 입력은 표준 입력을 통해 받으며, 결과는 표준 출력으로 내보냅니다. (Python의 sys.stdin.read() 사용 권장)

## 문제

정수 배열 A와 세 개의 정수 L, K가 주어집니다. 여기서 L은 부분 배열의 고정된 길이이며, K는 조건을 만족하는 최소 임계값입니다.

당신은 길이 L인 모든 연속 부분 배열(Subarray)을 탐색해야 합니다. 이 중 다음 두 조건을 모두 만족하는 부분 배열을 찾아야 합니다:
1. 부분 배열의 길이가 L이다.
2. 부분 배열 내의 모든 원소 중 적어도 하나가 K보다 크거나 같다.

만족하는 모든 부분 배열들 중, 원소들의 합이 가장 큰 값(최댓값)을 반환하세요. 만약 조건을 만족하는 부분 배열이 하나도 없다면, -1을 반환합니다.

## 입력

첫째 줄에 정수 N, 정수 L, 정수 K가 공백으로 구분되어 주어집니다. (N: 배열 길이, L: 윈도우 크기, K: 임계값)
둘째 줄에는 공백으로 구분된 N개의 정수 배열 A가 주어집니다.

## 출력

조건을 만족하는 부분 배열들의 합 중 가장 큰 값(최댓값)을 한 정수로 출력합니다.

## 제약 조건

1. N: 1 <= N <= 10^5
2. L: 1 <= L <= N
3. K: -10^9 <= K <= 10^9
4. 배열 A의 원소: -10^9 <= A[i] <= 10^9
5. 시간 복잡도는 O(N) 내외여야 합니다.

## 예제 1

**입력**
```
4 3 4
1 5 2 8
```

**출력**
```
15
```

*길이 3인 윈도우 중, 조건(원소 >= 4)을 만족하는 것은 [5, 2, 8]이며 합은 15입니다.*

## 예제 2

**입력**
```
5 3 5
1 2 3 4 5
```

**출력**
```
12
```

*조건을 만족하는 윈도우는 [3, 4, 5] 뿐이며, 합은 12입니다.*

## 예제 3

**입력**
```
5 3 10
1 2 3 4 5
```

**출력**
```
-1
```

*임계값 K=10보다 큰 원소가 포함된 윈도우가 없으므로 -1을 반환합니다.*

## 힌트

- 고정된 크기의 윈도우를 다루므로 슬라이딩 윈도우 기법을 사용합니다.
- 매 윈도우마다 합과 조건 만족 여부를 확인해야 합니다. 모든 윈도우를 순회하며 시간을 최적화하는 것이 중요합니다.


## 알고리즘 요약

고정 크기 슬라이딩 윈도우 (Fixed-Size Sliding Window) + 조건 검사
1. 초기 윈도우 (길이 L)의 합과 조건 만족 여부를 확인합니다.
2. 다음 윈도우로 이동할 때, 이전 윈도우의 합에서 빠지는 원소와 새로 들어오는 원소를 이용하여 O(1) 시간 복잡도로 합을 갱신합니다.
3. 매 단계마다 현재 윈도우가 조건을 만족하는지 확인하고, 만족한다면 최대 합을 갱신합니다. 조건 만족 여부를 효율적으로 체크하기 위해 '윈도우 내 K 이상 원소의 개수'를 카운팅하는 변수를 유지합니다.

## 풀이 해설

풀이 해설: 아이디어 → 단계 → 시간복잡도

**아이디어:**
문제는 길이가 고정된 윈도우를 슬라이딩하며, 특정 조건을 만족하는 윈도우의 최대 합을 찾는 것입니다. 모든 윈도우를 순회하며 합을 계산하는 것은 $O(N 	imes L)$의 시간이 걸릴 수 있습니다. 하지만 윈도우의 크기가 고정되어 있으므로, 슬라이딩 윈도우 기법을 적용하여 각 윈도우의 합을 $O(1)$ 시간 복잡도로 갱신할 수 있습니다.

**단계:**
1. **초기화:** 최대 합(`max_sum`)을 매우 작은 값(-infinity)으로, 조건을 만족하는 윈도우의 유무를 나타내는 플래그(`found`)를 `False`로 설정합니다.
2. **첫 번째 윈도우 처리 (i=0부터 L-1):** 첫 번째 윈도우의 합을 계산하고, 이 윈도우에 K 이상의 원소가 있는지 확인합니다. 조건을 만족하면 `max_sum`을 갱신하고 `found`를 `True`로 설정합니다.
3. **슬라이딩 (i=L부터 N-1):** 윈도우를 한 칸 이동할 때마다, 이전 윈도우의 합에서 빠지는 원소 `A[i-L]`를 빼고, 새로 들어오는 원소 `A[i]`를 더하여 현재 합을 $O(1)$로 갱신합니다.
4. **조건 검사 (핵심):** 윈도우 이동 시, 조건 검사도 효율적으로 해야 합니다. 윈도우 내에 K 이상인 원소가 몇 개 있는지 카운트하는 변수(`count`)를 유지합니다. A[i-L]이 빠질 때 조건에 영향을 주는지, A[i]가 들어올 때 조건에 영향을 주는지 판단하여 `count`를 갱신합니다.
5. **최댓값 갱신:** 만약 `count`가 0보다 크다면 (즉, 조건 만족), 현재 합이 `max_sum`보다 크다면 `max_sum`을 갱신합니다.
6. **결과 반환:** 루프가 끝난 후, `found`가 `False`라면 -1을 반환하고, 그렇지 않다면 `max_sum`을 반환합니다.

**시간 복잡도:**
전체 배열을 $O(N)$번 순회하며, 각 단계에서 상수 시간 $O(1)$ 연산만 수행하므로 총 시간 복잡도는 $O(N)$입니다.

**공간 복잡도:**
추가 배열을 사용하지 않으므로 $O(1)$입니다.

## 참고 코드 (python)

```python
import sys

def solve():
    # 표준 입력 전체를 읽어 처리
    input_data = sys.stdin.read().split()
    if not input_data: 
        return -1
    
    # 첫 줄: N, L, K
    N = int(input_data[0])
    L = int(input_data[1])
    K = int(input_data[2])
    
    # 두 번째 줄: 배열 A
    A = [int(x) for x in input_data[3:]]

    # 케이스 체크: N < L 이거나 배열이 비어있을 경우
    if N < L or not A: 
        return -1

    max_sum = -float('inf')
    found = False
    current_sum = 0
    # 윈도우 내 K 이상 원소의 개수
    count = 0

    # 1. 초기 윈도우 (i=0부터 L-1) 설정
    for i in range(L):
        current_sum += A[i]
        if A[i] >= K: 
            count += 1
    
    if count > 0: 
        max_sum = current_sum
        found = True

    # 2. 슬라이딩 윈도우 시작 (i=L부터 N-1)
    for i in range(L, N):
        # 윈도우 이동: A[i-L]이 빠지고, A[i]가 들어옴
        
        # 빠지는 원소 (left_val)
        left_val = A[i - L]
        if left_val >= K: 
            count -= 1
        current_sum -= left_val
        
        # 들어오는 원소 (right_val)
        right_val = A[i]
        current_sum += right_val
        if right_val >= K: 
            count += 1
            
        # 3. 조건 검사 및 최대 합 갱신
        if count > 0: 
            if current_sum > max_sum: 
                max_sum = current_sum
            found = True

    # 결과 반환
    return max_sum if found else -1

# 테스트 실행 (실제 코딩 테스트 환경에서는 print(solve())만 제출)
# print(solve())
```
