# 최대 곱을 가지는 세 수의 조합
*javascript · 자료구조/탐색 · 보통 · 정렬, 투포인터*

## 입출력 환경

Node.js 환경에서 표준 입력(stdin) 전체를 읽어 처리해야 합니다. 일반적으로 'fs' 모듈이나 'readline' 인터페이스를 사용합니다.

## 문제

N개의 정수 배열 A가 주어집니다. 이 배열에서 서로 다른 세 개의 인덱스 i, j, k를 선택하여 곱한 값 $A[i] \times A[j] \times A[k]$의 최댓값을 구하는 문제입니다.\n\n주의사항: 문제에서 요구하는 것은 배열의 원소 중 최대 곱을 가지는 세 수의 조합이며, 이 세 수는 반드시 서로 다른 인덱스에 위치해야 합니다.

## 입력

첫째 줄에 정수 N이 주어지며, 다음 줄에는 공백으로 구분된 N개의 정수 A[0], A[1], ..., A[N-1]가 주어집니다.

## 출력

최대 곱을 가지는 세 수의 조합의 값을 한 정수로 출력합니다.

## 제약 조건

1. $3 \le N \le 10^5$ (배열 크기)\n2. $-10^9 \le A[i] \le 10^9$ (원소 값)

## 예제 1

**입력**
```
5\n1 2 3 4 5
```

**출력**
```
60
```

*모든 수가 양수이므로, 가장 큰 세 수 (3, 4, 5)를 곱한 값입니다.*

## 예제 2

**입력**
```
4\n-10 -2 3 5
```

**출력**
```
30
```

*최대값을 찾기 위해 모든 조합을 고려해야 합니다. 이 경우, 가장 작은 두 음수와 가장 큰 양수를 곱하는 것은 아닙니다. (예: (-10)*(-2)*3 = 60) 하지만 실제로는 배열의 끝에서만 최적해가 나올 수 있습니다.*

## 예제 3

**입력**
```
5\n-1 -2 -3 -4 -5
```

**출력**
```
60
```

*모두 음수일 때, 가장 큰 절대값을 가진 세 숫자를 선택해야 합니다. (가장 작은 두 수 * 가장 큰 수) -> (-5)*(-4)*(-3) = -60. 아니요! 최대 곱은 2*3*4 조합처럼 양수가 되어야 하므로, 이 문제에서는 항상 최대를 찾는 것이 목표입니다.*

## 힌트

- 문제의 제약 조건과 원소 값의 범위를 고려했을 때, 모든 조합을 탐색하는 것은 시간 초과가 발생할 수 있습니다.
- 최대 곱은 양수가 되는 경우와 음수가 되는 경우가 있을 수 있으며, 특히 배열에 음수가 포함되어 있을 때 주의해야 합니다.


## 알고리즘 요약

배열 A를 오름차순으로 정렬합니다. 최대 곱은 다음 두 가지 케이스 중 하나에서 발생할 가능성이 높습니다: 1) 가장 큰 세 양수($A[N-1] \times A[N-2] \times A[N-3]$). 2) 가장 작은 두 음수와 가장 큰 수($A[0] \times A[1] \times A[N-1]$). 이 두 값 중 최댓값을 반환합니다. (원소가 양수인 경우에도, 만약 $A[0], A[1]$이 매우 큰 음수라면 2번 케이스가 더 클 수 있습니다.)

## 풀이 해설

### 아이디어\n주어진 배열에서 세 수를 골라 곱했을 때의 최댓값을 찾는 문제입니다. 원소 값에 양수와 음수가 혼재되어 있기 때문에, 단순히 가장 큰 세 숫자를 고른다고 해서 항상 답이 되는 것은 아닙니다. 예를 들어, [-10, -5, 2] 와 같은 경우, (-10) * (-5) * 2 = 100 이 되어 가장 큰 양수만 선택하는 것보다 훨씬 클 수 있습니다.\n
### 단계\n1. **정렬:** 배열 A를 오름차순으로 정렬합니다. 시간 복잡도: $O(N \log N)$. (오름차순 정렬 시, $A[0]$은 가장 작은 값(가장 큰 음수), $A[N-1]$은 가장 큰 값을 가리킵니다.)\n2. **후보 조합 탐색:** 최대 곱을 가지는 세 수의 조합은 크게 두 가지 경우로 제한됩니다:\n    a) **세 개의 가장 큰 양수:** 배열의 끝 세 원소 ($A[N-3], A[N-2], A[N-1]$). 이 조합은 모든 숫자가 양수이거나, 음수가 적고 양수가 많은 긍정적인 경우에 최대가 됩니다.\n    b) **두 개의 가장 작은 음수와 하나의 가장 큰 수:** 배열의 시작 두 원소 ($A[0], A[1]$)와 끝 원소 ($A[N-1]$). 이 조합은 매우 작은 음수($A[0], A[1]$)가 곱해져서 양수가 되고, 여기에 $A[N-1]$ 같은 큰 양수를 곱함으로써 최댓값을 만들 확률이 높습니다. (음수 $	imes$ 음수 $	imes$ 양수 = 양수)\n3. **결과 반환:** 계산된 두 후보 값 중 더 큰 값을 결과로 반환합니다.\n
### 시간 복잡도\n배열 정렬에 의해 $O(N \log N)$이 됩니다. 이후 상수 시간에 (두 번의 곱셈) 최댓값을 비교하므로 최종 시간 복잡도는 $O(N \log N)$입니다.

## 참고 코드 (javascript)

```javascript
/**
 * @param {number[]} arr - 정수 배열 A
 * @returns {bigint} 최대 곱을 가지는 세 수의 조합 (BigInt 사용)
 */
function solve() {
    // Node.js 환경에서 표준 입력 읽기 로직
    const fs = require('fs');
    let input = fs.readFileSync(0, 'utf8').trim().split(/\s+/);
    
    if (input.length === 0 || input[0] === '') return 0;

    // 첫 번째 요소는 N이므로 제외하고 나머지 배열을 원소로 사용
    const arr = input.slice(1).map(Number);
    const N = arr.length;

    if (N < 3) return 0; // 문제 제약 조건상 발생하지 않음

    // 1. 배열을 오름차순으로 정렬합니다.
    // JavaScript의 기본 sort는 문자열 비교를 하므로, 숫자 비교 함수 제공이 필수입니다.
    arr.sort((a, b) => a - b);

    // BigInt를 사용하여 곱셈 과정에서 발생할 수 있는 2^53 범위를 넘는 오버플로우를 방지합니다.
    const bigInt = (x) => BigInt(x);

    // N-1: 가장 큰 원소, 0: 가장 작은 원소
    const a0 = arr[0];
    const a1 = arr[1];
    const an_minus_3 = arr[N - 3];
    const an_minus_2 = arr[N - 2];
    const an_minus_1 = arr[N - 1];

    // 후보 1: 가장 큰 세 원소 (A[N-3] * A[N-2] * A[N-1])
    const product1 = bigInt(an_minus_3) * bigInt(an_minus_2) * bigInt(an_minus_1);
    
    // 후보 2: 가장 작은 두 원소와 가장 큰 원소 (A[0] * A[1] * A[N-1])
    const product2 = bigInt(a0) * bigInt(a1) * bigInt(an_minus_1);
    
    // 최대값 반환
    return product1 > product2 ? product1 : product2;
}

console.log(solve().toString());
```
