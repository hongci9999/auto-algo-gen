# 고정 크기 부분 배열의 최대 합
*javascript · 투포인터 · 보통 · 배열, 슬라이딩 윈도우*

## 입출력 환경

Node.js 환경에서 전체 입력을 한 번에 읽어와 처리하는 방식을 가정합니다. (예: `readline` 모듈 또는 전체 `fs.readFileSync` 사용)

## 문제

정수 배열 A와 양의 정수 K가 주어집니다. 배열 A에서 길이가 K인 모든 연속된 부분 배열을 고려했을 때, 그 합이 가장 큰 부분 배열의 합을 구하는 문제입니다. A의 원소 값은 음수일 수 있습니다.

예시: A = [1, 2, 3, 4, 5], K = 3
부분 배열의 합: [1, 2, 3] -> 6, [2, 3, 4] -> 9, [3, 4, 5] -> 12.
최대 합은 12입니다.

## 입력

첫 번째 줄에 정수 N과 정수 K가 공백으로 구분되어 주어집니다. 두 번째 줄에는 N개의 정수 원소가 공백으로 구분되어 주어집니다.

## 출력

가장 큰 부분 배열의 합을 하나의 정수로 출력합니다.

## 제약 조건

1. $1 	ext{ } 	ext{.} N 	ext{ } 	ext{:} 1 	ext{ } 	ext{.} 10^5$
2. $1 	ext{ } 	ext{.} K 	ext{ } 	ext{:} 1 	ext{ } 	ext{.} N$
3. 배열 원소 $A_i$: $-10^9 	ext{ } 	ext{.} 10^9$
4. 시간 복잡도는 $O(N)$ 또는 $O(N 	imes K)$를 넘지 않아야 합니다.

## 예제 1

**입력**
```
5 3
1 2 3 4 5
```

**출력**
```
12
```

*슬라이딩 윈도우를 이용하여 모든 길이 3의 부분 배열 합을 계산한 최대값입니다.*

## 예제 2

**입력**
```
6 2
10 -5 2 7 -1 3
```

**출력**
```
9
```

*가장 큰 합을 갖는 부분 배열은 [2, 7]로 합이 9입니다.*

## 예제 3

**입력**
```
5 5
-1 -2 -3 -4 -5
```

**출력**
```
-15
```

*K가 N과 같을 때, 전체 배열의 합이 최대 합입니다.*

## 힌트

- 매번 K개의 원소를 더하는 방식(O(N*K))은 시간 초과를 유발할 수 있습니다.
- 이전 윈도우의 합에서 빠지는 원소와 새로 들어오는 원소를 이용하면 계산을 최적화할 수 있습니다.


## 알고리즘 요약

슬라이딩 윈도우 (Sliding Window) 기법을 사용합니다. 초기 윈도우의 합을 계산한 후, 다음 윈도우로 이동할 때마다 이전 윈도우의 가장 왼쪽 원소는 빼고, 새로운 오른쪽 원소는 더하는 방식으로 현재 합을 $O(1)$ 시간에 갱신합니다. 이를 통해 전체 시간 복잡도를 $O(N)$으로 줄일 수 있습니다.

## 풀이 해설

### 아이디어
이 문제는 '슬라이딩 윈도우' 기법을 적용하여 풀 수 있습니다. 단순히 모든 길이 K의 부분 배열을 순회하며 합을 구하면 시간 복잡도가 $O(N 	imes K)$가 되어 시간 초과가 발생할 수 있습니다. 따라서, 현재 윈도우의 합을 매번 다시 계산하는 대신, 윈도우가 한 칸 이동할 때마다 합을 $O(1)$ 시간에 갱신하는 것이 핵심 아이디어입니다.

### 단계
1. **초기화 (첫 번째 윈도우):** 배열의 처음 K개 원소($A[0]$부터 $A[K-1]$까지)를 더하여 초기 `currentSum`을 계산합니다. 이 값을 초기 `maxSum`으로 설정합니다.
2. **슬라이딩:** 인덱스 $i$를 $K$부터 배열의 끝($N-1$)까지 순회합니다. 이 $i$는 윈도우의 '오른쪽 끝'을 나타냅니다.
3. **합 갱신:** 새로운 윈도우의 합은 이전 윈도우의 합에서 윈도우의 가장 왼쪽 원소($A[i-K]$)를 빼고, 현재 오른쪽 원소($A[i]$)를 더하여 계산합니다: `currentSum = currentSum - A[i-K] + A[i]`.
4. **최대값 갱신:** 갱신된 `currentSum`과 현재까지 기록된 `maxSum`을 비교하여 `maxSum`을 업데이트합니다: `maxSum = max(maxSum, currentSum)`.
5. **종료:** 모든 원소 순회가 끝나면 `maxSum`이 정답입니다.

### 시간 복잡도
시간 복잡도는 배열을 $O(N)$번만 순회하며, 각 단계에서 상수 시간 $O(1)$ 연산만 수행하므로, 전체 시간 복잡도는 $O(N)$입니다. 공간 복잡도는 추가 배열을 사용하지 않으므로 $O(1)$입니다.

## 참고 코드 (javascript)

```javascript
/**
 * Node.js 환경에서 전체 입력을 받는다고 가정합니다.
 * 예시 입력 구조: 라인 1 (N K), 라인 2 (A[0] A[1] ...)
 */
function solve() {
    const fs = require('fs');
    // 실제 환경에 맞게 입력 처리 부분을 수정해야 합니다. 여기서는 예제 입력을 가정합니다.
    // const input = fs.readFileSync(0, 'utf8').trim().split('\n');
    
    // 테스트를 위한 가상의 입력 설정 (N, K, Array A)
    // (N, K)는 첫 번째 라인, A는 두 번째 라인
    const inputData = ["5 3", "1 2 3 4 5*"]; 
    if (process.argv.length > 2) {
        // 실제 파일 시스템에서 읽어올 경우의 처리 (여기서는 주석 처리)
    }
    
    const [headerLine, arrayLine] = inputData;
    const [N, K] = headerLine.split(' ').map(Number);
    // 원소들이 공백으로 구분되어 있다고 가정하고 파싱
    const A = arrayLine.split(' ').map(Number);

    if (A.length < K) {
        console.log(0);
        return;
    }

    // 1. 초기 윈도우 합 계산 (A[0] ~ A[K-1])
    let currentSum = 0;
    for (let i = 0; i < K; i++) {
        currentSum += A[i];
    }

    let maxSum = currentSum;

    // 2. 슬라이딩 시작 (i는 현재 윈도우의 오른쪽 끝 인덱스)
    // i는 K부터 N-1까지 순회하며, 윈도우를 한 칸씩 오른쪽으로 이동시킵니다.
    for (let i = K; i < N; i++) {
        // 3. 합 갱신 (O(1)):
        // 이전 윈도우의 가장 왼쪽 원소 (A[i-K])를 빼고, 새로운 원소 (A[i])를 더합니다.
        currentSum = currentSum - A[i - K] + A[i];
        
        // 4. 최대값 갱신
        maxSum = Math.max(maxSum, currentSum);
    }

    console.log(maxSum);
}

// 참고: 실제 환경에서는 입력 파싱 로직을 Node.js 표준 입력 방식으로 수정해야 합니다.
// 예: readline 모듈을 사용하여 N, K와 배열 A를 순차적으로 읽어와야 합니다.
// solve();
```
