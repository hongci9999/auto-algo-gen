# 두 수의 합 제한
*javascript · 투포인터 · 보통 · 정렬, 투포인터*

## 입출력 환경

Node.js 환경에서 전체 입력을 문자열로 읽어 처리해야 합니다. 입력은 N, A 배열 (공백 구분), K 순서로 들어옵니다.

## 문제

정수 배열 A와 정수 K가 주어집니다. 배열 A에서 인덱스 i와 j에 위치하며, i < j를 만족하는 모든 쌍 (i, j)에 대해 A[i] + A[j] <= K를 만족하는 쌍의 총 개수를 구하세요. 단, 배열의 원소는 중복될 수 있습니다.

예시: A = [1, 3, 2], K = 4. 쌍은 (1, 3), (1, 2), (3, 2)입니다. 합이 4 이하인 쌍은 (1, 3) (합 4), (1, 2) (합 3)입니다. 총 2개입니다.

## 입력

첫 번째 줄에 정수 N (배열의 길이)이 주어집니다. 두 번째 줄에 N개의 정수 원소가 공백으로 구분되어 주어집니다. 세 번째 줄에 정수 K가 주어집니다.

## 출력

총 쌍의 개수를 하나의 정수 값으로 출력합니다.

## 제약 조건

1 <= N <= 100,000
-10^9 <= A[i], K <= 10^9

## 예제 1

**입력**
```
3
1 3 2
4
```

**출력**
```
2
```

*합이 4 이하인 쌍은 (1, 3)과 (1, 2)입니다.*

## 예제 2

**입력**
```
5
1 2 3 4 5
7
```

**출력**
```
9
```

*합이 7 이하인 쌍은 (1, 2), (1, 3), (1, 4), (1, 5), (2, 3), (2, 4), (2, 5), (3, 4), (3, 5)입니다. (5는 제외)
정렬 후: 1+2, 1+3, 1+4, 1+5, 2+3, 2+4, 2+5, 3+4, 3+5. 총 9개.*

## 힌트

- 문제 조건을 만족하는 쌍의 개수를 세야 합니다.
- 배열을 정렬하면 투 포인터 기법을 적용하기 유리해집니다.


## 알고리즘 요약

배열 A를 오름차순으로 정렬합니다. 이후 두 포인터(Left와 Right)를 설정합니다. Left는 배열의 시작(최솟값)에, Right는 배열의 끝(최댓값)에 둡니다. 두 원소 A[Left]과 A[Right]의 합을 확인하며, 합이 K 이하일 경우, A[Left]과 A[Right]을 포함하여 A[Left]과 Right 포인터가 가리키는 모든 원소(Left+1부터 Right까지)가 K 이하의 합을 만들 수 있으므로, 현재 Left와 Right 사이의 거리만큼 쌍의 개수를 더하고 Left 포인터를 오른쪽으로 이동시킵니다. 합이 K를 초과하면, A[Right]이 너무 크다는 의미이므로 Right 포인터를 왼쪽으로 이동시킵니다.

## 풀이 해설

이 문제는 '합이 K 이하인 쌍의 개수'를 찾는 문제입니다. 원소의 순서가 중요하지 않고 오직 합만 중요하므로, 먼저 배열 A를 오름차순으로 정렬하는 것이 가장 효율적인 접근 방법입니다.

**1단계: 정렬 (Sorting)**
배열 A를 오름차순으로 정렬합니다. 시간 복잡도: O(N log N).

**2단계: 투 포인터 설정 (Two Pointers)**
두 개의 포인터, `L` (Left)과 `R` (Right)을 설정합니다. `L`은 0부터 시작하고, `R`은 N-1부터 시작합니다.

**3단계: 반복 및 계산 (Iteration)**
`L < R`인 동안 다음 로직을 반복합니다:
1. **합 계산:** `Sum = A[L] + A[R]`을 계산합니다.
2. **Case 1: Sum <= K (조건 만족)**
   만약 합이 K 이하이면, 현재 `A[L]`과 `A[R]`을 포함하여, `A[L]`과 `A[L+1]`부터 `A[R]`까지 모든 원소와 합이 K 이하가 될 가능성이 있습니다. (왜냐하면 A[L]과 A[L+1]...A[R]은 모두 A[L] <= A[R]이기 때문입니다.)
   따라서, 현재 `A[L]`을 기준으로 K 이하의 합을 만드는 쌍은 $R - L$개입니다. 이 값을 총 개수에 더합니다. 이후, 다음 쌍을 탐색하기 위해 `L`을 오른쪽으로 한 칸 이동시킵니다. (L++)
3. **Case 2: Sum > K (조건 불만족)**
   합이 K보다 크다면, 현재 `A[R]`은 너무 크다는 의미입니다. 따라서 합을 줄이기 위해 `R`을 왼쪽으로 한 칸 이동시킵니다. (R--)

**시간 복잡도:** 정렬에 $O(N 	ext{ log } N)$이 소요되며, 두 포인터가 배열을 한 번씩만 순회하므로 나머지 과정은 $O(N)$입니다. 따라서 전체 시간 복잡도는 $O(N 	ext{ log } N)$입니다.

## 참고 코드 (javascript)

```javascript
/**
 * Node.js 환경에서 표준 입력으로 N, A 배열, K를 받기 위한 구조입니다.
 * 실제 테스트 환경에서는 전체 입력을 한 번에 받는다고 가정하고 구현합니다.
 */

const readline = require('readline');

async function solve() {
    const rl = readline.createInterface({
        input: process.stdin,
        output: process.stdout,
        terminal: false
    });

    let lines = [];
    for await (const line of rl) {
        lines.push(line);
    }

    if (lines.length < 3) return;

    // 1. 입력 파싱
    const N = parseInt(lines[0].trim());
    const A = lines[1].trim().split(' ').map(Number);
    const K = parseInt(lines[2].trim());

    // 2. 정렬 (O(N log N))
    // JavaScript의 sort는 문자열 비교를 기본으로 하므로, 숫자를 명시적으로 비교해야 합니다.
    A.sort((a, b) => a - b);

    let count = 0;
    let L = 0; // Left pointer (시작)
    let R = N - 1; // Right pointer (끝)

    // 3. 투 포인터 탐색 (O(N))
    while (L < R) {
        const sum = A[L] + A[R];

        if (sum <= K) {
            // Case 1: A[L] + A[R] <= K
            // A[L]을 기준으로 K 이하의 합을 만들 수 있는 쌍은 A[L]과 A[L+1]부터 A[R]까지의 모든 원소와 만들 수 있습니다.
            // 원소의 개수 = R - L
            count += (R - L);
            
            // 다음 쌍을 찾기 위해 L을 오른쪽으로 이동시킵니다.
            L++;
        } else {
            // Case 2: A[L] + A[R] > K
            // 합이 너무 크므로, R을 왼쪽으로 이동시켜 작은 원소와 다시 시도합니다.
            R--;
        }
    }

    console.log(count);
}

solve();
```
