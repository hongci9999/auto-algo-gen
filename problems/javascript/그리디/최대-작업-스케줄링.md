# 최대 작업 스케줄링
*javascript · 그리디 · 보통 · 정렬, 탐욕 알고리즘*

## 입출력 환경

JavaScript (Node.js) 환경을 가정합니다. 모든 입력은 표준 입력(stdin)을 통해 한 번에 받습니다.

## 문제

당신은 여러 개의 작업(Task)을 할당받았습니다. 각 작업은 시작 시간과 종료 시간이 주어집니다. 두 작업이 겹치지 않으면서(즉, 한 작업이 끝나기 전에 다음 작업이 시작하지 않아야 함) 수행할 수 있는 최대 작업의 개수를 구하는 문제입니다.

작업의 개수 N은 최대 100,000개이며, 시간은 1부터 1,000,000까지입니다.

## 입력

첫 번째 줄에는 작업의 총 개수 N이 주어집니다. 다음 N개의 줄에는 각 작업의 시작 시간(S)과 종료 시간(E)이 공백으로 구분되어 주어집니다. (S E)

## 출력

최대 작업 개수를 하나의 정수 형태로 출력합니다.

## 제약 조건

N <= 100,000. 시간 값은 1 <= S, E <= 1,000,000.

## 예제 1

**입력**
```
4
1 3
2 5
6 8
7 9
```

**출력**
```
2
```

*가장 먼저 끝나는 작업(1-3)을 선택한 후, 다음으로 겹치지 않는 작업(6-8)을 선택하여 총 2개를 수행합니다.*

## 예제 2

**입력**
```
5
1 2
2 3
3 4
1 4
5 6
```

**출력**
```
4
```

*가장 먼저 끝나는 순서대로 (1-2), (2-3), (3-4), (5-6)을 선택하는 것이 최적입니다. (주의: 끝나는 시간이 같은 경우, 시작 시간이 빠른 것을 선택해도 무방합니다.)*

## 힌트

- 탐욕적인 접근(Greedy Approach)을 생각해야 합니다.
- 어떤 순서로 작업을 선택해야 최대 개수를 보장할 수 있는지 고민해 보세요. 일반적으로 '종료 시간'으로 정렬하는 것이 효과적입니다.


## 알고리즘 요약

탐욕 알고리즘을 이용합니다. 주어진 작업들을 종료 시간이 빠른 순서대로 정렬합니다. 정렬된 목록을 순회하며, 현재 작업의 시작 시간이 이전에 선택한 작업의 종료 시간보다 크거나 같으면 해당 작업을 선택하고, 선택된 작업의 종료 시간을 갱신합니다. 이 과정을 통해 최대 작업 개수를 찾을 수 있습니다.

## 풀이 해설

💡 아이디어: 이 문제는 '활동 선택 문제(Activity Selection Problem)'의 전형적인 예시이며, 탐욕 알고리즘으로 해결할 수 있습니다. 최대의 개수를 얻기 위해서는, 매번 '가장 빨리 끝나는 작업'을 선택하는 것이 최적의 선택입니다. 만약 가장 빨리 끝나는 작업을 건너뛰고 더 긴 작업이나 시작 시간이 빠른 작업을 선택한다면, 다음 작업을 선택할 수 있는 시간적 여유가 줄어들어 전체 개수가 줄어들 위험이 있습니다.

⚙️ 단계:
1. 정렬: 모든 작업 리스트를 '종료 시간(End Time)'을 기준으로 오름차순 정렬합니다. 종료 시간이 같은 작업은 시작 시간 순으로 정렬해도 무방합니다.
2. 선택: 변수 `count`를 0으로, `lastEndTime`을 매우 작은 값(-1)으로 초기화합니다.
3. 순회 및 결정: 정렬된 작업 리스트를 처음부터 끝까지 순회합니다. 현재 작업의 시작 시간이 `lastEndTime`보다 크거나 같으면, 이 작업은 이전 작업과 겹치지 않으므로 선택합니다. 선택했다면, `count`를 1 증가시키고, `lastEndTime`을 현재 작업의 종료 시간으로 갱신합니다.
4. 결과: 모든 순회가 끝나면 `count`가 최대 작업 개수입니다.

⏱️ 시간 복잡도: O(N log N). N개의 작업을 정렬하는 데 O(N log N)이 소요되며, 이후 순회는 O(N)이므로 전체 시간 복잡도는 정렬에 의해 결정됩니다.

## 참고 코드 (javascript)

```javascript
function solve(inputString) {
    if (!inputString) return 0;
    
    // Node.js 환경에서 입력 문자열을 가정하고 파싱
    const lines = inputString.trim().split('\n').filter(line => line.length > 0);
    if (lines.length === 0) return 0;
    
    // 첫 줄은 N (작업 개수)
    const N = parseInt(lines[0].trim());
    let tasks = [];
    
    // 나머지 N줄은 작업 정보 (S E)
    for (let i = 1; i <= N; i++) {
        const line = lines[i].trim().split(' ').map(Number);
        tasks.push({ start: line[0], end: line[1] });
    }

    // 1. 그리디 전략: 종료 시간(end)을 기준으로 오름차순 정렬
    tasks.sort((a, b) => a.end - b.end);

    let count = 0;
    // 마지막으로 선택된 작업의 종료 시간을 저장. 시작 시간보다 작게 초기화.
    let lastEndTime = -1;

    // 2. 순회 및 선택
    for (const task of tasks) {
        // 현재 작업이 이전 작업의 종료 시간 이후에 시작하는지 확인
        if (task.start >= lastEndTime) {
            count++;
            // 선택했으므로, lastEndTime을 현재 작업의 종료 시간으로 갱신
            lastEndTime = task.end;
        }
    }

    return count;
}

// 실제 테스트 환경에 맞춰 solve 함수만 호출하도록 구성
```
