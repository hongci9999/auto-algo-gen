# 최소 길이 L 구간 커버리지
*javascript · 그리디 · 보통 · 그리디, 정렬, 배열*

## 입출력 환경

Node.js 환경에서 'readline' 모듈을 사용하여 입력받는다고 가정합니다. 입력은 텍스트 형태로 주어지며, 두 줄을 처리해야 합니다.

## 문제

당신은 1차원 좌표 평면 상에 위치한 여러 개의 점(Point) 집합 $P$를 가지고 있습니다. 이 점들 전체를 덮기 위해, 길이가 $L$인 구간(Interval)을 사용하여 최소한의 개수로 덮어야 합니다. 

주어진 점들을 모두 포함하도록 하는 최소 길이 $L$ 구간의 개수를 구하세요. 각 구간은 $[start, end]$ 형태로 표현되며, $end - start = L$을 만족해야 합니다. 모든 점을 덮는 과정에서 구간들은 겹쳐도 상관없습니다.

점의 좌표 값은 매우 클 수 있으므로, 정밀도 문제에 유의해야 합니다. (모든 입력 좌표는 정수입니다.)

## 입력

첫 번째 줄에는 점의 개수 $N$과 구간의 길이 $L$이 공백으로 구분되어 주어집니다. (정수)
두 번째 줄에는 $N$개의 점 좌표가 공백으로 구분되어 주어집니다. (정수)

## 출력

모든 점을 덮기 위해 필요한 최소 구간의 개수를 정수 형태로 출력합니다.

## 제약 조건

1. $1 	ext{ ≤ } N 	ext{ ≤ } 10^5$
2. $1 	ext{ ≤ } L 	ext{ ≤ } 10^9$
3. $1 	ext{ ≤ } 	ext{좌표} 	ext{ ≤ } 10^9$
4. 시간 복잡도는 $O(N 	ext{ log } N)$ 또는 $O(N)$ 이내여야 합니다.

## 예제 1

**입력**
```
4 3
1 2 5 6
```

**출력**
```
2
```

*좌표를 정렬하면 [1, 2, 5, 6]입니다. 첫 구간은 [1, 4]로 1과 2를 덮고, 다음 구간은 [5, 8]로 5와 6을 덮어 총 2개가 필요합니다.*

## 예제 2

**입력**
```
3 5
10 20 30
```

**출력**
```
3
```

*점들이 충분히 떨어져 있어, 각 점마다 별도의 구간이 필요합니다. [10, 15], [20, 25], [30, 35]로 3개가 필요합니다.*

## 예제 3

**입력**
```
5 10
1 2 3 4 5
```

**출력**
```
1
```

*점들이 연속적으로 모여 있어 하나의 구간 [1, 11]로 모두 덮을 수 있습니다.*

## 힌트

- 문제를 풀기 전에 입력된 점들을 반드시 오름차순으로 정렬해야 합니다.
- 그리디 알고리즘을 사용하여, 현재 덮이지 않은 가장 왼쪽의 점을 포함하는 구간을 최대한 오른쪽으로 확장하는 것이 최적의 선택입니다.


## 알고리즘 요약

이 문제는 전형적인 그리디(Greedy) 알고리즘 문제입니다. 핵심 아이디어는 '가장 왼쪽의 미처리 점을 포함하는 구간을 최대한 오른쪽으로 확장하여 커버리지 효율을 극대화'하는 것입니다. 먼저 점들을 오름차순으로 정렬합니다. 가장 왼쪽의 미처리 점 $P_i$를 찾습니다. 이 점을 포함하고 길이가 $L$인 구간은 $[P_i, P_i + L]$입니다. 이 구간이 덮을 수 있는 가장 오른쪽 점 $P_j$를 찾아냅니다. $P_j$까지 커버했으므로, 다음 미처리 점 $P_{j+1}$부터 다시 과정을 반복합니다. 이 과정을 반복하는 횟수가 최소 구간의 개수가 됩니다.

## 풀이 해설

문제 해결 과정은 크게 세 단계로 나뉩니다.

1. **정렬**: 입력으로 받은 모든 점들의 좌표를 오름차순으로 정렬합니다. 이는 가장 왼쪽의 미처리 점을 효율적으로 찾기 위함입니다.
2. **그리디 선택 (반복)**: 최소 구간의 개수를 세기 위해 반복문을 사용합니다. 현재 처리해야 할 가장 왼쪽의 점 $P_{start}$를 가리키는 인덱스를 설정합니다. 이 $P_{start}$를 포함하는 구간은 $[P_{start}, P_{start} + L]$이 됩니다.
3. **커버리지 확장 및 이동**: 이 구간 $[P_{start}, P_{start} + L]$이 덮을 수 있는 가장 오른쪽 점을 찾습니다. 이 점의 인덱스를 $P_{end}$라고 합니다. 이 구간은 $P_{start}$부터 $P_{end}$까지의 모든 점을 덮었습니다. 따라서 최소 구간의 개수를 1 증가시키고, 다음 탐색은 $P_{end}$의 다음 점인 $P_{end+1}$부터 시작해야 합니다. 이 과정을 모든 점을 덮을 때까지 반복합니다.

**시간 복잡도**: 점의 개수 $N$이 최대 $10^5$이므로, 초기 정렬 단계에서 $O(N 	ext{ log } N)$ 시간이 소요됩니다. 이후 그리디 탐색은 한 번만 배열을 순회하므로 $O(N)$ 시간이 소요됩니다. 따라서 전체 시간 복잡도는 $O(N 	ext{ log } N)$입니다.

## 참고 코드 (javascript)

```javascript
/**
 * Node.js 환경에서 표준 입력을 처리하는 템플릿입니다.
 * 실제 코딩 테스트에서는 readline 모듈이나 fs 모듈을 사용하여 입력을 받습니다.
 */

function solve() {
    const fs = require('fs');
    // 테스트 환경을 위해 예제 입력 문자열을 직접 사용합니다. 실제 환경에서는 fs.readFileSync(0, 'utf8') 등을 사용해야 합니다.
    // 예시 입력: 4 3\n1 2 5 6
    const input = fs.readFileSync(0, 'utf8').trim().split('\n');

    if (input.length < 2) return;

    // 1. 입력 파싱 (N, L)
    const [N_str, L_str] = input[0].split(' ');
    const N = parseInt(N_str);
    const L = parseInt(L_str);

    // 2. 점 좌표 배열 파싱
    let points = input[1].split(' ').map(Number);

    // 3. 필수 단계: 점들을 오름차순으로 정렬
    points.sort((a, b) => a - b);

    if (N === 0) {
        console.log(0);
        return;
    }

    let count = 0; // 최소 구간 개수
    let i = 0;    // 현재 처리해야 할 가장 왼쪽 점의 인덱스

    while (i < N) {
        count++;
        
        // 1. 현재 구간의 시작점 (가장 왼쪽 미처리 점)
        const startPoint = points[i];
        // 2. 이 점을 포함하는 구간의 끝점 (최대 커버리지)
        const coverageEnd = startPoint + L;

        // 3. 그리디 탐색: 이 구간 [startPoint, coverageEnd]가 덮을 수 있는 가장 오른쪽 점을 찾는다.
        let j = i;
        while (j < N && points[j] <= coverageEnd) {
            j++;
        }
        
        // j는 이제 덮을 수 있는 범위의 바로 다음 인덱스를 가리킨다.
        // 따라서 다음 탐색은 j부터 시작해야 한다.
        i = j; 
    }

    console.log(count);
}

// 실제 실행 시, Node.js의 표준 입력 처리를 가정합니다.
solve();
```
