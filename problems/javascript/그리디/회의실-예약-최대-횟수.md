# 회의실 예약 최대 횟수
*javascript · 그리디 · 보통 · 정렬, 그리디, 활동선택문제*

## 입출력 환경

Node.js 환경에서 동작한다고 가정하며, 문제 풀이 함수는 이미 전처리된 배열 형태의 입력을 받습니다.

## 문제

당신은 회의실 예약 시스템을 관리하는 개발자입니다. 주어진 N개의 회의 요청 목록이 있습니다. 각 회의는 시작 시간과 종료 시간을 가지며, 회의는 시간이 겹치지 않아야만 같은 회의실을 사용할 수 있습니다. 

목표는 주어진 요청들 중에서 시간을 겹치지 않으면서 최대 횟수의 회의를 예약하는 것입니다. 

요청 목록은 `[[start1, end1], [start2, end2], ..., [startN, endN]]` 형태로 주어집니다. 시간은 정수형이며, 종료 시간이 다음 회의의 시작 시간과 같아도 겹치지 않는 것으로 간주합니다 (예: [1, 3], [3, 5]는 가능).

## 입력

배열 형태의 2차원 배열. 각 내부 배열은 [시작 시간, 종료 시간]을 나타냅니다. 예: [[0, 30], [5, 10], [15, 20]]

## 출력

최대로 예약 가능한 회의의 횟수 (정수)

## 제약 조건

N은 1부터 10^5까지입니다. 시작 시간과 종료 시간은 0부터 10^9 사이의 정수입니다. 시간 복잡도는 O(N log N) 이내여야 합니다.

## 예제 1

**입력**
```
[[0, 30], [5, 10], [15, 20]]
```

**출력**
```
2
```

*가장 먼저 끝나는 회의들을 선택하는 것이 유리합니다. [5, 10] -> [15, 20] (총 2개)*

## 예제 2

**입력**
```
[[1, 2], [2, 3], [3, 4], [1, 4]]
```

**출력**
```
3
```

*시간이 겹치지 않게 [1, 2], [2, 3], [3, 4] 순으로 예약하는 것이 최적입니다.*

## 힌트

- 이 문제는 전형적인 '활동 선택 문제(Activity Selection Problem)'입니다.
- 탐욕적인(Greedy) 접근 방식을 사용해야 합니다. 어떤 기준으로 정렬하는 것이 가장 효과적일지 고민해 보세요.


## 알고리즘 요약

활동 선택 문제의 그리디 알고리즘. 모든 활동을 종료 시간(End Time) 기준으로 오름차순 정렬한 후, 가장 먼저 끝나는 활동을 선택하고, 다음 활동은 이 활동의 종료 시간 이후에 시작하는 활동들 중에서 가장 먼저 끝나는 것을 선택하는 과정을 반복합니다.

## 풀이 해설

### 💡 아이디어
이 문제는 그리디 알고리즘(탐욕적 접근)을 사용하여 해결할 수 있습니다. 활동 선택 문제의 핵심은 '남은 자원(시간)을 최대한 많이 확보하는 것'입니다. 따라서, 매번 회의를 선택할 때 가장 먼저 끝나는 회의를 선택하는 것이 가장 많은 남은 시간을 확보하게 해주고, 결과적으로 최대 횟수를 보장합니다.

### ⚙️ 단계
1. **정렬 (Sorting):** 주어진 모든 회의 요청 리스트를 '종료 시간(End Time)'을 기준으로 오름차순 정렬합니다. 종료 시간이 같으면 시작 시간 순으로 정렬해도 무방합니다.
2. **선택 (Selection):** 첫 번째 회의 (가장 먼저 끝나는 회의)는 무조건 선택합니다. 예약된 회의 횟수 카운터를 1로 초기화하고, 마지막으로 선택된 회의의 종료 시간을 기록합니다.
3. **순회 및 검증 (Iteration):** 정렬된 리스트를 처음부터 끝까지 순회합니다. 현재 회의의 시작 시간이 '마지막으로 선택된 회의의 종료 시간'보다 크거나 같다면 (즉, 겹치지 않는다면), 이 회의를 선택하고 횟수를 1 증가시키며, 마지막 선택 시간을 업데이트합니다.
4. **결과 반환:** 반복이 끝난 후의 횟수가 최대 예약 횟수입니다.

### ⏱️ 시간 복잡도
- 정렬 단계: O(N log N)
- 순회 단계: O(N)
- 총 시간 복잡도: O(N log N)
- 공간 복잡도: O(1) (추가 배열 사용을 고려하지 않을 경우)

## 참고 코드 (javascript)

```javascript
/**
 * @param {number[][]} requests - [[start, end], ...] 형태의 회의 요청 배열
 * @returns {number} 최대 예약 가능 횟수
 */
const maxMeetings = (requests) => {
    if (!requests || requests.length === 0) {
        return 0;
    }

    // 1. 종료 시간(End Time)을 기준으로 오름차순 정렬
    // 만약 종료 시간이 같다면, 시작 시간을 기준으로 오름차순 정렬해도 무방합니다.
    requests.sort((a, b) => {
        // a[1]은 종료 시간, b[1]은 종료 시간
        return a[1] - b[1];
    });

    let count = 0;
    // 마지막으로 선택된 회의가 끝나는 시간을 저장합니다.
    // 초기값으로 -1을 주어 모든 회의를 시작 가능하게 합니다.
    let lastFinishTime = -1; 

    // 2. 그리디 선택 과정
    for (const meeting of requests) {
        const startTime = meeting[0];
        const endTime = meeting[1];

        // 현재 회의의 시작 시간이 마지막 선택 회의의 종료 시간보다 크거나 같으면 (겹치지 않으면)
        if (startTime >= lastFinishTime) {
            count++;
            // 선택했으므로, 다음 회의를 위해 종료 시간을 업데이트합니다.
            lastFinishTime = endTime;
        }
    }

    return count;
};

// --- 테스트 케이스 실행 예시 ---

// Sample 1: [[0, 30], [5, 10], [15, 20]] -> 2
const sample1 = [[0, 30], [5, 10], [15, 20]];
console.log(`Sample 1 Result: ${maxMeetings(sample1)}`); // 예상 출력: 2

// Sample 2: [[1, 2], [2, 3], [3, 4], [1, 4]] -> 3
const sample2 = [[1, 2], [2, 3], [3, 4], [1, 4]];
console.log(`Sample 2 Result: ${maxMeetings(sample2)}`); // 예상 출력: 3

// Sample 3: 모든 회의가 겹치는 경우
const sample3 = [[1, 5], [1, 5], [1, 5]];
console.log(`Sample 3 Result: ${maxMeetings(sample3)}`); // 예상 출력: 1
```
