# 자원 할당 최대화
*javascript · 그리디 · 보통 · 정렬, 그리디, 시간 간격*

## 입출력 환경

Node.js 환경에서 전체 입력을 받아 처리하는 방식을 가정합니다. 표준 입력(stdin)에서 모든 데이터를 읽어와야 합니다.

## 문제

당신은 여러 작업을 수행할 수 있는 한정된 자원(시간)을 가지고 있습니다. 각 작업은 시작 시간과 종료 시간이 주어집니다. 한 번에 하나의 작업만 수행할 수 있으며, 두 작업이 겹치는 시간 동안에는 동시에 진행할 수 없습니다.

주어진 작업 목록 중에서, 서로 시간이 겹치지 않으면서 최대한 많은 작업을 수행할 수 있는 최대 개수를 구하시오.

*주의: 만약 작업 A가 [1, 3]이고 작업 B가 [3, 5]라면, 두 작업은 시간 3에서 끝과 시작이 같으므로 겹치지 않는 것으로 간주합니다. 즉, 작업 A의 종료 시간은 작업 B의 시작 시간보다 작거나 같아야 합니다.*

## 입력

첫째 줄에 작업의 총 개수 N이 주어집니다. 이후 N개의 줄에 걸쳐 각각 작업의 시작 시간(S)과 종료 시간(E)이 공백으로 구분되어 주어집니다. (S, E) 쌍의 형태로 입력됩니다.

## 출력

최대한 많은 작업을 수행할 수 있는 최대 작업 개수(정수)를 출력합니다.

## 제약 조건

1. N의 범위: 1 <= N <= 10^5
2. 시간 범위: 1 <= S, E <= 10^9
3. 시간 복잡도: O(N log N) 이하를 목표로 합니다.

## 예제 1

**입력**
```
3
1 4
2 5
6 7
```

**출력**
```
2
```

*시간이 겹치지 않게 선택 가능한 조합은 ([1, 4], [6, 7])이나 ([2, 5], [6, 7]) 등이며, 최대 2개입니다.*

## 예제 2

**입력**
```
5
1 3
2 4
3 5
1 6
5 7
```

**출력**
```
3
```

*최적의 순서는 [1, 3] -> [3, 5] -> [5, 7]로, 총 3개의 작업을 수행할 수 있습니다.*

2. 일반적으로 '겹치지 않는 간격 선택' 문제는 '종료 시간' 기준으로 정렬하는 것이 핵심입니다.


## 알고리즘 요약

이 문제는 전형적인 '활동 선택 문제(Activity Selection Problem)'의 변형입니다. 그리디(Greedy) 알고리즘을 사용하며, 최적의 선택은 '가장 빨리 끝나는 작업'을 선택하는 것입니다. 따라서 모든 작업을 종료 시간(E)을 기준으로 오름차순 정렬한 후, 첫 번째 작업을 선택하고, 그 작업의 종료 시간보다 크거나 같은 시작 시간을 가진 작업들 중에서 다음으로 빨리 끝나는 작업을 반복적으로 선택해 나갑니다.

## 풀이 해설

풀이 아이디어: 활동 선택 문제는 '가장 적은 자원으로 최대의 활동을 선택'하는 그리디 문제의 대표적인 예시입니다. 이 문제에서도 마찬가지로, 다음에 수행할 작업을 선택할 때 '종료 시간이 가장 빠른 작업'을 선택하는 것이 남은 시간을 가장 효율적으로 아끼고 다음 작업을 시도할 기회를 극대화합니다.

단계:
1. **정렬:** 주어진 N개의 모든 작업 간격(S, E)을 '종료 시간(E)'을 기준으로 오름차순 정렬합니다. 만약 종료 시간이 같다면 시작 시간 순으로 정렬해도 무방합니다.
2. **선택 및 카운트:** 첫 번째 작업을 선택합니다. 이 작업의 종료 시간을 `last_end_time` 변수에 저장합니다. (현재 선택된 작업 개수 = 1)
3. **반복:** 정렬된 리스트를 순회하며, 현재 작업(S_i, E_i)에 대해 다음 조건을 확인합니다:
    a. $S_i 	ext{ (현재 작업 시작 시간)} 	ext{ } 	ext{>=} 	ext{ } last\_end\_time 	ext{ (이전에 선택된 작업 종료 시간)}$ 
    b. 위의 조건이 참일 경우, 이 작업은 이전 작업과 겹치지 않으므로 선택합니다. 따라서 `last_end_time`을 $E_i$로 업데이트하고, 작업 개수를 1 증가시킵니다.
4. **결과:** 반복이 끝난 후의 작업 개수가 최대 수행 가능한 작업의 개수입니다.

시간 복잡도: 정렬에 $O(N 	imes 	ext{log} N)$ 시간이 소요되며, 이후 선형 탐색에 $O(N)$ 시간이 소요되므로, 전체 시간 복잡도는 $O(N 	ext{ log } N)$입니다.

## 참고 코드 (javascript)

```javascript
/**
 * 활동 선택 문제 (Activity Selection Problem)를 그리디 방식으로 해결합니다.
 * @param {Array<Array<number>>} tasks - [[S1, E1], [S2, E2], ...] 형태의 작업 배열
 * @returns {number} 최대 작업 개수
 */
function solve(tasks) {
    if (!tasks || tasks.length === 0) {
        return 0;
    }

    // 1. 그리디 선택 기준: 종료 시간(E)을 기준으로 오름차순 정렬
    // [S, E] 형태이므로, 배열의 인덱스 1(E)을 기준으로 정렬합니다.
    tasks.sort((a, b) => a[1] - b[1]);

    let count = 0;
    // 마지막으로 선택된 작업의 종료 시간을 저장할 변수. 초기값은 아주 작은 수로 설정합니다.
    let lastEndTime = -Infinity;

    // 2. 정렬된 리스트를 순회하며 작업 선택
    for (const task of tasks) {
        const startTime = task[0];
        const endTime = task[1];

        // 현재 작업의 시작 시간이 마지막 선택된 작업의 종료 시간보다 크거나 같으면
        // (즉, 겹치지 않으면) 선택 가능합니다.
        if (startTime >= lastEndTime) {
            count++;
            lastEndTime = endTime; // 선택했으므로, 이 작업의 종료 시간을 업데이트합니다.
        }
    }

    return count;
}

// --- 입출력 처리 부분 (Node.js 환경 가정) ---

function main() {
    const fs = require('fs');
    // 동기적으로 모든 입력을 읽어옵니다.
    const input = fs.readFileSync(0, 'utf8').trim().split('\n').map(line => line.trim()).filter(line => line.length > 0);
    
    if (input.length === 0) return;

    // 첫 줄은 N (작업 개수)
    const N = parseInt(input[0]);
    let tasks = [];

    // 나머지 N줄이 작업 [S, E] 쌍입니다.
    for (let i = 1; i <= N; i++) {
        const parts = input[i].split(' ').map(Number);
        if (parts.length === 2) {
            tasks.push(parts); // [Start, End] 형태로 저장
        }
    }

    const result = solve(tasks);
    console.log(result);
}

// main(); // 실제 제출 시 주석 해제하여 사용하도록 안내합니다.
```
