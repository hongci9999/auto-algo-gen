# 최대 작업 개수 선택
*javascript · 그리디 · 보통 · 정렬, 그리디, 활동선택문제*

## 입출력 환경

Node.js 환경에서 전체 입력을 읽어 처리하는 방식으로 작성합니다. (예: fs.readFileSync 또는 readline 모듈 사용)

## 문제

당신은 N개의 작업 목록을 받았습니다. 각 작업은 시작 시간과 종료 시간을 가집니다. 작업을 수행할 때, 두 작업은 시간 간격이 겹치면 동시에 수행할 수 없습니다.

주어진 작업들 중에서 서로 시간 간격이 겹치지 않도록 최대 몇 개의 작업을 선택할 수 있는지 구하는 문제입니다.

(작업 A의 종료 시간이 작업 B의 시작 시간과 같아도 겹치지 않으므로, [1, 3]과 [3, 5]는 연속으로 수행 가능합니다.)

## 입력

첫 번째 줄에 작업의 총 개수 N (1 ≤ N ≤ 100,000)이 주어집니다.
다음 N개의 줄에 각각 '시작 시간 종료 시간' 형태로 작업 정보가 주어집니다. (시간은 0부터 10^9 사이의 정수입니다.)

## 출력

선택 가능한 최대 작업 개수를 하나의 정수로 출력합니다.

## 제약 조건

N은 최대 100,000이며, 시간 값은 10^9를 넘지 않습니다. 시간 복잡도는 O(N log N)을 목표로 합니다.

## 예제 1

**입력**
```
3
0 6
1 3
4 5
```

**출력**
```
2
```

*가장 빨리 끝나는 [1, 3]과 그 이후에 시작하는 [4, 5]를 선택하여 2개를 만들 수 있습니다.*

## 예제 2

**입력**
```
4
1 2
3 4
1 4
2 3
```

**출력**
```
3
```

*가장 먼저 끝나는 [1, 2], 그리고 이어서 [2, 3], [3, 4] 순서로 선택하여 최대 3개를 만들 수 있습니다.*

## 알고리즘 요약

활동 선택 문제(Activity Selection Problem)의 고전적인 그리디 알고리즘을 사용합니다. 선택의 기준은 '가장 빨리 끝나는 작업'입니다. 작업을 종료 시간 기준으로 오름차순 정렬한 후, 첫 번째 작업을 선택하고, 이후 선택할 작업은 직전에 선택한 작업의 종료 시간보다 크거나 같은 시작 시간을 가지는 작업 중 가장 빨리 끝나는 것을 선택해 나갑니다.

## 풀이 해설

💡 아이디어:
이 문제는 '활동 선택 문제'의 전형적인 예시입니다. 여러 활동(작업)이 주어졌을 때, 시간 간격이 겹치지 않도록 최대한 많은 활동을 선택하는 것이 목표입니다. 그리디 알고리즘을 적용해야 합니다.

✅ 그리디 선택 기준:
최대 개수를 확보하려면, 매 순간 가장 빨리 끝나는 작업을 선택하는 것이 가장 유리합니다. 왜냐하면 일찍 끝날수록 남은 시간대가 길어져서, 이후에 더 많은 작업을 수용할 기회가 많아지기 때문입니다.

🛠️ 단계:
1. **정렬 (Sorting):** 주어진 모든 작업 리스트를 '종료 시간'을 기준으로 오름차순 정렬합니다. 만약 종료 시간이 같다면, 시작 시간 순으로 정렬해도 무방합니다.
2. **초기화 (Initialization):** 최대 개수 카운트를 0으로 설정하고, 마지막으로 선택된 작업의 종료 시간을 초기화합니다. (예: -1 또는 매우 작은 값).
3. **순회 및 선택 (Iteration & Selection):** 정렬된 리스트를 순회합니다. 현재 작업의 시작 시간이 마지막으로 선택된 작업의 종료 시간보다 크거나 같다면, 이 작업을 선택하고 최대 개수 카운트를 1 증가시키며, 마지막 선택된 작업의 종료 시간을 현재 작업의 종료 시간으로 업데이트합니다.
4. **결과 반환:** 순회가 끝난 후의 최대 개수 카운트를 반환합니다.

⏱️ 시간 복잡도:
가장 시간이 많이 걸리는 부분은 N개의 작업을 정렬하는 과정입니다. 따라서 시간 복잡도는 O(N log N)이며, 이는 N이 최대 10만일 때 충분히 효율적입니다.

## 참고 코드 (javascript)

```javascript
/**
 * Node.js 환경에서 표준 입력을 받아 처리하는 함수입니다.
 * 이 코드는 모든 입력을 문자열 배열 형태로 받아 처리한다고 가정합니다.
 */
function solve(lines) {
    if (!lines || lines.length === 0) return 0;

    // 첫 줄은 N (작업 개수)
    const N = parseInt(lines[0].trim());
    if (N === 0) return 0;

    // 1. 작업 배열을 파싱
    let tasks = [];
    for (let i = 1; i <= N; i++) {
        const line = lines[i].trim();
        if (line) {
            const [start, end] = line.split(' ').map(Number);
            tasks.push({ start: start, end: end });
        }
    }

    // 2. 그리디 전략: 종료 시간(end)을 기준으로 오름차순 정렬
    // 종료 시간이 같으면 시작 시간 순으로 정렬하는 것이 일반적이지만, 여기서는 종료 시간만 기준으로 해도 충분합니다.
    tasks.sort((a, b) => a.end - b.end);

    let count = 0;
    // 마지막으로 선택된 작업의 종료 시간. 초기값은 가장 이른 시간보다 작은 값으로 설정합니다.
    let lastEndTime = -1; 

    // 3. 순회 및 선택
    for (const task of tasks) {
        // 현재 작업의 시작 시간이 마지막 작업의 종료 시간과 같거나 크면, 겹치지 않으므로 선택 가능합니다.
        if (task.start >= lastEndTime) {
            count++;
            lastEndTime = task.end; // 선택했으므로, 이 작업의 종료 시간을 업데이트합니다.
        }
    }

    return count;
}

/**
 * 실제 Node.js 환경에서 입력을 처리하는 예시 구조입니다.
 * (테스트 환경에 맞게 입력 처리 부분을 수정해야 할 수 있습니다.)
 */
function main() {
    // 예시: 모든 입력을 받은 배열을 가정합니다. (테스트 환경에 맞게 수정 필요)
    const inputLines = require('fs').readFileSync(0, 'utf8').trim().split('\n');
    
    const result = solve(inputLines);
    console.log(result);
}

// main(); // 실제 실행 시 주석 해제
```
