# 최대 비중복 이벤트 스케줄링
*javascript · 그리디 · 보통 · 정렬, 그리디*

## 입출력 환경

Node.js 환경에서 모든 입력을 받아서 처리하는 방식으로 가정합니다. 입력된 데이터는 [[start1, end1], [start2, end2], ...] 형태의 배열로 접근 가능하다고 간주하세요.

## 문제

여러 개의 이벤트가 있습니다. 각 이벤트는 시작 시간(Start)과 종료 시간(End)을 가집니다. 주어진 이벤트들 중에서 서로 시간적으로 겹치지 않으면서, 가장 많은 개수의 이벤트를 선택하는 최대 스케줄링 개수를 구하는 문제입니다.

두 이벤트 A와 B가 있다고 할 때, 두 이벤트의 구간 [A_start, A_end]와 [B_start, B_end]가 겹치지 않으려면, 둘 중 어느 쪽이든 끝나는 시점과 다른 쪽이 시작하는 시점이 같거나 다르면 됩니다. (즉, 종료 시간이 다음 시작 시간보다 작거나 같아야 합니다.)

## 입력

첫 번째 줄에 이벤트의 개수 N이 주어집니다. 이후 N개의 줄에 걸쳐 각 이벤트의 시작 시간(Start)과 종료 시간(End)이 공백으로 구분되어 순서대로 입력됩니다. (N <= 10^5, Start와 End는 1 이상 10^9 이하의 정수입니다.)

## 출력

선택할 수 있는 최대 이벤트 개수를 하나의 정수로 출력합니다.

## 제약 조건

이벤트 개수 N은 1부터 100,000까지이며, 시간 값(Start/End)은 1 이상 10^9 이하입니다. 시간 복잡도는 O(N log N) 이내여야 합니다.

## 예제 1

**입력**
```
4
1 3
2 5
6 7
8 9
```

**출력**
```
3
```

*이벤트 (1, 3), (6, 7), (8, 9)가 선택 가능하며, 최대 개수는 3개입니다.*

## 예제 2

**입력**
```
5
1 4
2 5
6 8
3 6
9 10
```

**출력**
```
3
```

*이벤트 (1, 4), (3, 6)은 겹치고, 가장 적절한 조합은 (1, 4)와 (6, 8), 그리고 (9, 10)입니다.*

## 힌트

- 모든 이벤트를 순서대로 확인하는 것은 비효율적일 수 있습니다.
- 최종적으로 선택되는 이벤트들은 반드시 시간 순으로 정렬되어야 합니다. 어떤 기준으로 정렬해야 가장 많은 개수를 보장할 수 있을까요?


## 알고리즘 요약

그리디 알고리즘 (Greedy Algorithm)과 정렬(Sorting)을 사용합니다. 이 문제의 핵심은 '종료 시간이 가장 빠른' 활동을 우선적으로 선택하는 것입니다. 모든 이벤트를 종료 시간 기준으로 오름차순 정렬한 후, 가장 먼저 시작할 수 있는 이벤트부터 차례대로 선택해 나갑니다.

## 풀이 해설

아이디어: 이 문제는 전형적인 활동 선택 문제(Activity Selection Problem)이며, 그리디 알고리즘을 통해 최적의 해를 찾을 수 있습니다.

단계 1. 정렬 기준 확립: 가장 많은 개수의 이벤트를 선택하기 위해서는, 매번 현재 시점에서 '가장 빨리 끝나는' 이벤트를 선택하는 것이 항상 최적인(Optimal) 그리디 선택입니다. 따라서 모든 이벤트 쌍을 종료 시간(End Time) 기준으로 오름차순 정렬합니다.

단계 2. 탐욕적 선택 (Greedy Selection): 첫 번째로 정렬된 이벤트는 무조건 선택합니다. 이 이벤트의 종료 시간을 '마지막으로 끝난 시간'으로 기록합니다. 이후, 남아있는 이벤트들 중 '현재 시작 시간이 마지막으로 끝난 시간보다 크거나 같은' 가장 빠른 이벤트부터 순차적으로 선택하고, 그 이벤트의 종료 시간을 업데이트합니다.

단계 3. 반복 및 카운팅: 정렬된 배열을 한 번만 순회하면서 조건을 만족하는 모든 이벤트를 세어 최종 개수를 반환합니다.

시간 복잡도 분석:
1. 정렬 단계: N개의 이벤트를 종료 시간 기준으로 정렬하므로 $O(N 	imes 	ext{log} N)$이 소요됩니다.
2. 탐색 단계: 정렬된 배열을 한 번만 순회하므로 $O(N)$이 소요됩니다.
전체 시간 복잡도는 지배적인 정렬 시간인 $O(N 	ext{ log } N)$입니다.

## 참고 코드 (javascript)

```javascript
/**
 * @param {Array<[number, number]>} events - [[start1, end1], [start2, end2], ...] 형태의 이벤트 배열
 * @returns {number} 최대 선택 가능한 이벤트 개수
 */
function solve(events) {
    if (!events || events.length === 0) {
        return 0;
    }

    // 단계 1: 종료 시간(End Time, 인덱스 1)을 기준으로 오름차순 정렬합니다.
    // 이는 그리디 알고리즘의 핵심입니다. 가장 빨리 끝나는 활동부터 선택해야 합니다.
    events.sort((a, b) => { 
        // a[1]은 종료 시간
        return a[1] - b[1]; 
    });

    let count = 0; // 선택된 이벤트 개수
    let lastEndTime = -Infinity; // 마지막으로 끝난 시간 (초기값)

    // 단계 2: 정렬된 배열을 순회하며 그리디하게 선택합니다.
    for (const event of events) {
        const startTime = event[0];
        const endTime = event[1];

        // 현재 이벤트의 시작 시간이 마지막으로 끝난 시간보다 크거나 같으면, 겹치지 않습니다.
        if (startTime >= lastEndTime) {
            // 선택! 카운트를 증가시키고, 종료 시간을 업데이트합니다.
            count++;
            lastEndTime = endTime;
        }
    }

    return count;
}
```
