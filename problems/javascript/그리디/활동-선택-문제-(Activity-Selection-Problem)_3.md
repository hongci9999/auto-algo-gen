# 활동 선택 문제 (Activity Selection Problem)
*javascript · 그리디 · 보통 · 정렬, 그리디*

## 입출력 환경

Node.js 환경에서 표준 입력(stdin)을 통해 JSON 형식의 활동 배열 문자열을 받습니다. (예: '[["1", "4"], ["2", "5"], ["6", "8"]]')

## 문제

당신은 여러 개의 활동 일정을 관리하는 시스템을 개발해야 합니다. 각 활동은 시작 시간과 종료 시간을 가집니다. 활동 간에 시간 중복이 발생하지 않도록 최대 몇 개의 활동을 선택할 수 있는지 구하는 문제입니다.

두 활동 [s1, e1]과 [s2, e2]가 있다고 할 때, 이들이 겹치지 않으려면 (e1 <= s2) 또는 (e2 <= s1)이어야 합니다. 즉, 종료 시간이 다음 시작 시간보다 작거나 같아야 합니다.

## 입력

활동 일정 리스트를 받습니다. 각 활동은 [시작 시간, 종료 시간] 형태의 배열로 주어지며, 모든 활동이 하나의 리스트에 포함됩니다. 예: [[1, 4], [2, 5], [6, 8]]

## 출력

선택 가능한 최대 활동 개수를 정수 하나로 출력합니다.

## 제약 조건

활동의 개수 N은 최대 10^5개입니다. 시간 복잡도는 O(N log N) 이하로 해결해야 합니다.

## 예제 1

**입력**
```
[[1, 4], [2, 5], [6, 8]]
```

**출력**
```
2
```

*가장 먼저 끝나는 활동 [1, 4]를 선택한 후, 다음에 겹치지 않는 [6, 8]을 선택하여 총 2개가 최대입니다.*

## 예제 2

**입력**
```
[[1, 2], [2, 3], [3, 4]]
```

**출력**
```
3
```

*모든 활동이 순차적으로 겹치지 않으므로, 모두 선택 가능합니다.*

## 예제 3

**입력**
```
[[1, 10], [2, 3], [4, 5]]
```

**출력**
```
2
```

*만약 [1, 10]을 선택하면 다른 활동을 선택할 수 없습니다. [2, 3]과 [4, 5]를 선택하는 것이 최대입니다.*

## 힌트

- 어떤 활동을 선택할지 결정할 때, '가장 빨리 끝나는 활동'을 선택하는 것이 그리디 전략의 핵심입니다.
- 시간 복잡도를 개선하려면 활동들을 적절한 기준으로 정렬해야 합니다.


## 알고리즘 요약

그리디 알고리즘 (Greedy Algorithm) + 정렬 (Sorting)

1. 모든 활동을 종료 시간(End Time)을 기준으로 오름차순 정렬합니다.
2. 정렬된 목록을 순회하며, 현재 활동이 이전에 선택한 활동의 종료 시간보다 크거나 같다면(즉, 겹치지 않는다면) 선택하고 카운트를 증가시킵니다.
3. 이 과정을 반복하여 최대 활동 개수를 구합니다.

## 풀이 해설

풀이 해설: 아이디어 → 단계 → 시간복잡도

**아이디어:** 활동 선택 문제와 같이 최대의 개수를 선택해야 하는 문제는 그리디(탐욕적) 알고리즘으로 접근할 수 있습니다. 이 문제의 경우, 어떤 활동을 먼저 선택할지 결정할 때, 전체 선택 가능한 활동의 개수를 최대화하려면 '가장 빨리 끝나는 활동'을 먼저 선택하는 것이 가장 유리합니다. 가장 빨리 끝나는 활동을 먼저 처리하면, 남은 시간 동안 더 많은 활동을 선택할 수 있는 여유 공간을 확보할 수 있기 때문입니다.

**단계:**
1. **정렬:** 주어진 모든 활동 리스트를 두 번째 원소(종료 시간)를 기준으로 오름차순 정렬합니다. (O(N log N))
2. **초기화:** 선택된 활동 개수(count)를 0으로, 마지막으로 선택된 활동의 종료 시간(lastEndTime)을 매우 작은 값(예: -1)으로 초기화합니다.
3. **순회 및 선택:** 정렬된 활동 리스트를 처음부터 끝까지 순회합니다.
4. **조건 확인:** 현재 활동의 시작 시간이 `lastEndTime`보다 크거나 같은지 확인합니다. (즉, 겹치지 않는지 확인)
5. **선택:** 만약 겹치지 않는다면, 이 활동을 선택합니다. `count`를 1 증가시키고, `lastEndTime`을 현재 활동의 종료 시간으로 업데이트합니다.
6. **결과:** 순회가 끝난 후의 `count`가 최대 활동 개수입니다.

**시간복잡도:** 시간 복잡도는 주로 정렬에 의해 결정됩니다. N개의 활동이 있을 때, 종료 시간 기준 정렬에 O(N log N)이 소요되며, 이후 한 번의 선형 순회(O(N))만 하므로 전체 시간 복잡도는 O(N log N)입니다.

## 참고 코드 (javascript)

```javascript
/**
 * 활동 선택 문제 해결 (그리디 알고리즘)
 * @param {number[][]} activities - [[start1, end1], [start2, end2], ...] 형태의 활동 배열
 * @returns {number} 최대 선택 가능한 활동의 개수
 */
function solveActivitySelection(activities) {
    if (!activities || activities.length === 0) {
        return 0;
    }

    // 1. 종료 시간(End Time, 인덱스 1)을 기준으로 오름차순 정렬합니다. (O(N log N))
    // JS의 sort는 기본적으로 문자열 비교를 하므로, 비교 함수를 반드시 제공해야 합니다.
    const sortedActivities = [...activities].sort((a, b) => {
        return a[1] - b[1]; // 종료 시간 비교: a[1] - b[1]
    });

    let count = 0; // 선택된 활동 개수
    let lastEndTime = -Infinity; // 마지막으로 선택된 활동의 종료 시간

    // 2. 정렬된 배열을 순회하며 그리디하게 활동 선택 (O(N))
    for (const activity of sortedActivities) {
        const startTime = activity[0];
        const endTime = activity[1];

        // 현재 활동의 시작 시간이 마지막 종료 시간보다 크거나 같으면 겹치지 않으므로 선택합니다.
        if (startTime >= lastEndTime) {
            count++;
            lastEndTime = endTime; // 마지막 종료 시간을 업데이트
        }
    }

    return count;
}

// --- Node.js 입출력 예시 ---
// 실제 코딩테스트에서는 입력 파싱 로직이 필요합니다. 
// 여기서는 테스트를 위해 직접 배열을 전달받아 실행하는 형태로 구성합니다.

// 예제 1: [[1, 4], [2, 5], [6, 8]]
const sample1 = [[1, 4], [2, 5], [6, 8]];
console.log(`예제 1 결과: ${solveActivitySelection(sample1)}`); // 예상 출력: 2

// 예제 2: [[1, 2], [2, 3], [3, 4]]
const sample2 = [[1, 2], [2, 3], [3, 4]];
console.log(`예제 2 결과: ${solveActivitySelection(sample2)}`); // 예상 출력: 3

// 예제 3: [[1, 10], [2, 3], [4, 5]]
const sample3 = [[1, 10], [2, 3], [4, 5]];
console.log(`예제 3 결과: ${solveActivitySelection(sample3)}`); // 예상 출력: 2
```
