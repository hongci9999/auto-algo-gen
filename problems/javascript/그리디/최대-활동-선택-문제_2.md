# 최대 활동 선택 문제
*javascript · 그리디 · 보통 · 정렬, 그리디*

## 입출력 환경

Node.js 환경에서 전체 입력을 받기 위해 'readline' 또는 'fs' 모듈을 사용하여 모든 입력을 한 번에 처리해야 합니다.

## 문제

당신은 여러 개의 활동(task)을 관리하는 스케줄러를 개발해야 합니다. 각 활동은 시작 시간(start)과 종료 시간(end)을 가집니다. 주어진 활동 목록에서 서로 시간적으로 겹치지 않으면서 가장 많은 수의 활동을 선택하는 최대 활동 집합의 크기를 구하세요. 활동의 시간은 정수이며, 한 활동이 끝나는 시점과 다른 활동이 시작하는 시점이 같아도 겹치지 않는 것으로 간주합니다.

예시: 활동 A가 [1, 4]이고, 활동 B가 [4, 6]이라면, 이 두 활동은 겹치지 않습니다.

## 입력

첫째 줄에 활동의 개수 N이 주어집니다. 다음 N줄에 걸쳐 각 활동의 시작 시간과 종료 시간이 공백으로 구분되어 주어집니다. (start end)

## 출력

선택할 수 있는 최대 활동의 개수를 정수 형태로 출력합니다.

## 제약 조건

1 <= N <= 10^5
1 <= start, end <= 10^9
시간 복잡도는 O(N log N) 이하를 목표로 합니다.

## 예제 1

**입력**
```
3
1 4
2 5
4 6
```

**출력**
```
2
```

*활동 [1, 4]와 [4, 6]을 선택하는 것이 최대입니다.*

## 예제 2

**입력**
```
4
1 2
2 3
3 4
1 3
```

**출력**
```
3
```

*가장 끝나는 시간을 기준으로 선택하면 [1, 2], [2, 3], [3, 4]를 선택할 수 있습니다.*

## 힌트

- 모든 활동을 선택할 수는 없습니다. 시간 겹침 여부를 확인해야 합니다.
- 이 문제는 그리디(탐욕적) 알고리즘으로 접근해야 하며, 어떤 기준으로 정렬하는지가 핵심입니다.


## 알고리즘 요약

그리디 알고리즘. 활동 선택 문제의 최적 해는 항상 '가장 빨리 끝나는 활동'을 선택하는 것에서 시작합니다. 따라서 모든 활동을 종료 시간(end time)을 기준으로 오름차순 정렬한 후, 순차적으로 선택합니다.

## 풀이 해설

풀이 해설: 아이디어 → 단계 → 시간복잡도

1. 아이디어:
이 문제는 전형적인 그리디 알고리즘 문제입니다. 활동을 선택할 때, 현재 선택한 활동이 가장 빨리 끝나는 활동을 선택하는 것이 항상 최적의 선택을 보장합니다. 만약 가장 빨리 끝나는 활동을 선택하지 않고 다른 활동을 선택한다면, 그 활동은 최소한 현재 선택된 활동보다 늦게 끝나기 때문에, 이후에 선택할 수 있는 후보 활동의 범위가 줄어들거나 같아지게 됩니다. 따라서, 활동들을 종료 시간(end time)을 기준으로 오름차순 정렬한 후, 순차적으로 최대 활동 집합을 구성합니다.

2. 단계:
a. 입력 받은 N개의 활동 목록을 저장합니다.
b. 활동 목록을 '종료 시간'을 기준으로 오름차순 정렬합니다. (만약 종료 시간이 같다면, 시작 시간으로 정렬해도 무방합니다.)
c. 초기화: 선택된 활동의 개수(count)를 0으로 설정하고, 마지막으로 선택된 활동의 종료 시간(last_end)을 매우 작은 값(예: -1)으로 설정합니다.
 d. 순회 및 선택: 정렬된 활동 목록을 처음부터 끝까지 순회합니다. 현재 활동의 시작 시간이 'last_end'보다 크거나 같으면 (즉, 겹치지 않으면), 이 활동을 선택합니다. 선택했다면, count를 1 증가시키고, last_end를 현재 활동의 종료 시간으로 업데이트합니다.
 e. 최종 count가 답이 됩니다.

3. 시간 복잡도:
- 입력 처리 및 저장: O(N)
- 정렬: O(N log N) (가장 큰 병목)
- 순회 및 선택: O(N)
- 총 시간 복잡도는 O(N log N)입니다.

## 참고 코드 (javascript)

```javascript
/**
 * Node.js 환경에서 동작하는 최대 활동 선택 문제 풀이
 * @param {Array<Array<number>>} tasks - [start, end] 형태의 활동 배열
 * @returns {number} 최대 활동 개수
 */
function solve(tasks) {
    if (!tasks || tasks.length === 0) {
        return 0;
    }

    // 1. 종료 시간(end time, 인덱스 1)을 기준으로 오름차순 정렬 (그리디 핵심)
    // JavaScript의 sort()는 기본적으로 문자열 비교를 하므로, 비교 함수를 반드시 제공해야 합니다.
    tasks.sort((a, b) => a[1] - b[1]);

    let count = 0;
    let lastEnd = -Infinity; // 매우 작은 값으로 초기화

    // 2. 정렬된 리스트를 순회하며 겹치지 않는 활동을 선택
    for (const task of tasks) {
        const startTime = task[0];
        const endTime = task[1];

        // 현재 활동의 시작 시간이 마지막으로 선택된 활동의 종료 시간보다 크거나 같은지 확인
        if (startTime >= lastEnd) {
            // 겹치지 않으므로 선택
            count++;
            // lastEnd를 현재 활동의 종료 시간으로 업데이트
            lastEnd = endTime;
        }
    }

    return count;
}

// Node.js 표준 입력을 처리하는 로직
function main() {
    const fs = require('fs');
    // 동기 방식으로 전체 입력을 읽어옵니다. (테스트 환경에 최적화)
    const input = fs.readFileSync(0, 'utf8').trim().split('\n');

    if (input.length === 0 || input[0] === '') {
        console.log(0);
        return;
    }

    // 첫 줄은 N (활동 개수)입니다.
    const N = parseInt(input[0].trim());
    let tasks = [];

    // 다음 N줄부터 활동 데이터를 파싱합니다.
    for (let i = 1; i <= N; i++) {
        const line = input[i].trim();
        if (line) {
            const parts = line.split(' ').map(Number);
            // [start, end] 형태로 저장
            tasks.push(parts);
        }
    }

    const result = solve(tasks);
    console.log(result);
}

// main(); // 실제 실행 환경에서는 주석 해제 필요

// 테스트를 위해 임시로 main 함수를 호출합니다.
// 이 코드는 실제 채점 환경의 입력 처리 방식에 따라 수정될 수 있습니다.
// 예시 1 테스트:
const tasks1 = [[1, 4], [2, 5], [4, 6]];
console.log(`테스트 1 결과: ${solve(tasks1)}`); // 예상 출력: 2

// 예시 2 테스트:
const tasks2 = [[1, 2], [2, 3], [3, 4], [1, 3]];
console.log(`테스트 2 결과: ${solve(tasks2)}`); // 예상 출력: 3
```
