# 최대 합을 가지는 부분 배열 개수
*javascript · 슬라이딩 윈도우 · 보통 · 배열, Two Pointers, 슬라이딩 윈도우*

## 입출력 환경

Node.js 환경에서 전체 입력을 읽어 처리하는 방식으로 구현합니다. 입력은 표준 입력(stdin)으로부터 받습니다.

## 문제

정수 배열 `A`와 정수 값 `S`가 주어집니다. 여기서, 합이 `S`보다 크지 않은 (즉, $\text{sum} \le S$) 모든 연속된 부분 배열의 개수를 구하는 문제입니다.

부분 배열은 최소한 하나의 원소를 포함해야 하며, 주어진 배열의 인접한 원소들로만 구성됩니다. 모든 원소는 양수입니다.

## 입력

첫째 줄에는 정수 $N$과 정수 $S$가 공백으로 구분되어 주어집니다.$N$은 배열 `A`의 크기이며, $S$는 최대 합의 기준값입니다.
둘째 줄에는 공백으로 구분된 $N$개의 양의 정수 원소들이 순서대로 주어지는 배열 `A`가 주어집니다.

## 출력

단일 정수 값. 조건을 만족하는 부분 배열의 총 개수를 출력합니다.

## 제약 조건

$1 \le N \le 200,000$, $1 \le S \le 10^9$. 배열 `A`의 원소값은 모두 양의 정수입니다.

## 예제 1

**입력**
```
3 8
1 3 5
```

**출력**
```
5
```

*합이 8 이하인 부분 배열: [1], [3], [5], [1, 3] (4), [3, 5] (8). 총 5개.*

## 예제 2

**입력**
```
4 6
2 1 3 4
```

**출력**
```
7
```

*합이 6 이하인 부분 배열: [2], [1], [3], [4] (X), [2, 1] (3), [1, 3] (4), [2, 1, 3] (6). 총 7개.*

## 힌트

- 원소의 합이 커지는 경향을 이용하는 것이 효율적입니다.
- 슬라이딩 윈도우(Sliding Window) 기법을 사용하면 시간 복잡도를 $O(N)$으로 줄일 수 있습니다.


## 알고리즘 요약

슬라이딩 윈도우 (Sliding Window). 배열의 원소들을 순차적으로 탐색하며, 현재 합이 주어진 목표 값 $S$를 초과하지 않도록 하는 가장 오른쪽 끝점(right pointer)을 확장하고, 조건을 위반하면 왼쪽 끝점(left pointer)을 이동시켜 창 크기를 줄여나갑니다. 특정 위치 `i`까지의 부분 배열 개수를 효율적으로 계산합니다.

## 풀이 해설

1. 아이디어: 이 문제는 '합이 $S$ 이하인 최대 길이의 윈도우'를 찾고, 그 윈도우가 시작할 수 있는 모든 지점을 카운트하는 방식으로 접근해야 합니다. 즉, 현재 위치 `i`를 끝점으로 하는 가장 긴 유효한 부분 배열을 찾으면, 이 부분 배열은 반드시 시작점 $j$부터 $i$까지의 모든 부분 배열(즉, $(i-j+1)$개)을 포함합니다.
2. 단계: 
   a. 두 개의 포인터 `left`와 `right`를 0으로 초기화하고, 현재 합 `currentSum`을 0으로 초기화합니다. 
   b. `right` 포인터를 배열의 끝까지 이동시키면서 `currentSum`에 `A[right]` 값을 더합니다. (윈도우 확장)
   c. 만약 `currentSum`이 $S$를 초과하게 되면, 윈도우가 너무 커진 것이므로 가장 왼쪽 원소 `A[left]`를 빼서 `currentSum`을 감소시키고, `left` 포인터를 오른쪽으로 이동시킵니다. (윈도우 축소)
   d. 현재 위치 `right`까지 도달했다는 것은, `A[0...right]`부터 시작하여 합이 $S$ 이하인 모든 부분 배열이 유효하다는 의미가 아닙니다. 대신, 조건을 만족하는 가장 긴 윈도우의 길이가 $(right - left + 1)$임을 알 수 있습니다.
   e. 핵심: 현재 윈도우 `A[left...right]`가 합 조건 $\le S$를 만족한다면, 이 윈도우는 시작점 $l \in [0, right]$ 부터 끝점 $r=right$까지의 모든 부분 배열 $(r-l+1)$을 포함합니다. 따라서, 매 순간 `right` 포인터를 한 칸 이동할 때마다, 현재 유효한 윈도우의 크기(`right - left + 1`)만큼 카운트를 증가시킵니다.
   f. 이 과정을 반복하면 시간 복잡도는 $O(N)$이 됩니다.
3. 시간복잡도: 배열을 두 포인터로 한 번만 순회하므로, 시간 복잡도는 $O(N)$입니다.

## 참고 코드 (javascript)

```javascript
/**
 * @param {number[]} A - 정수 배열
 * @param {number} S - 최대 합의 기준값
 * @returns {number} 부분 배열의 개수
 */
function countSubarraysWithSumAtMostS(A, S) {
    let left = 0; // 왼쪽 포인터 (윈도우 시작점)
    let currentSum = 0;
    let count = 0;

    // 오른쪽 포인터를 배열 끝까지 이동시키며 윈도우를 확장합니다.
    for (let right = 0; right < A.length; right++) {
        currentSum += A[right];

        // 1. 조건 위반 처리: 합이 S를 초과하면, 왼쪽 포인터를 이동시켜 윈도우를 축소합니다.
        while (currentSum > S) {
            currentSum -= A[left];
            left++;
        }

        // 2. 카운트 증가: 현재 윈도우 [left, right]가 조건을 만족하므로,
        // 이 위치(right)를 끝점으로 하는 유효한 부분 배열의 개수는 (right - left + 1)개입니다.
        // 즉, A[0...right], A[1...right], ..., A[right...right]까지 총 right - left + 1개가 카운트됩니다. 
        count += (right - left + 1);
    }
    
    return count;
}

// --- 입출력 처리 부분 ---
function solve() {
    const fs = require('fs');
    let input;
    try {
        input = fs.readFileSync(0, 'utf8').trim().split('\n');
    } catch (e) {
        // 테스트 환경이 아닌 경우를 대비하여 빈 입력 처리
        return;
    }

    if (input.length < 2) return;
    
    const [N, S] = input[0].split(' ').map(Number);
    const A = input[1].split(' ').map(Number);

    const result = countSubarraysWithSumAtMostS(A, S);
    console.log(result);
}

solve();
```
