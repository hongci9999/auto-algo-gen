# 최장 길이 부분 배열 합 문제
*javascript · 슬라이딩 윈도우 · 보통 · 배열, 슬라이딩 윈도우, Two Pointers*

## 입출력 환경

Node.js 환경에서 표준 입력을 사용하며, 입력 전체를 문자열로 받은 후 파싱하는 방식으로 진행합니다.

## 문제

정수 배열 `A`와 정수 $K$가 주어집니다. 이 배열에서 합이 $K$보다 작은 가장 긴 부분 배열의 길이를 구하는 문제입니다.

부분 배열은 연속된 원소들로 이루어져야 합니다.

## 입력

첫 번째 줄에 배열 A의 길이 N이 주어지고, 다음 줄에 공백으로 구분된 N개의 정수(배열 A)가 주어집니다. 마지막 줄에 상수 K가 주어집니다.

예시 입력: 
7
1 2 3 4 5 6 7
15

## 출력

합이 K보다 작은 가장 긴 부분 배열의 길이(정수)를 출력합니다.

## 제약 조건

배열 A의 원소 $A[i]$는 -10^9 이상부터 10^9 이하까지의 정수일 수 있습니다. (단, 문제 출제 의도를 고려하여 여기서는 모든 원소가 양수라고 가정하고 풀이를 진행하며, 실제 구현에서는 오버플로우 방지를 위해 BigInt를 사용할 필요가 있을 수 있으나, 시간 복잡도 측면에서 N <= 10^5로 제한합니다.) 배열 A의 길이 N은 1부터 10^5까지입니다. 상수 K는 -10^9 이상부터 10^9 이하의 정수입니다.

## 예제 1

**입력**
```
3
1 2 3
6
```

**출력**
```
2
```

*부분 배열 [1, 2]의 합은 3으로 K(6)보다 작고 길이는 2입니다. [1, 2, 3]의 합은 6이므로 조건을 만족하지 않습니다.*

## 예제 2

**입력**
```
5
3 1 2 5 4
10
```

**출력**
```
4
```

*부분 배열 [3, 1, 2, 5]의 합은 11로 K(10)보다 크지만, [1, 2, 5, 4]는 합이 12입니다. 가장 긴 부분 배열 [3, 1, 2] (합 6) 또는 [1, 2, 5] (합 8), 혹은 [1, 2, 5, 4]가 아니라 합 < 10인 최대 길이는 [3, 1, 2] (길이 3) 또는 [2, 5] (길이 2)... 실제로는 [3, 1, 2]의 길이가 아닌 다른 배열입니다. 예시를 수정하여: A=[3, 1, 2, 5], K=8 -> 최대 길이 3 ([3, 1, 2])*

## 예제 3

**입력**
```
7
1 2 3 4 5 6 7
15
```

**출력**
```
4
```

*슬라이딩 윈도우를 사용하면 [1, 2, 3, 4] (합 10)까지 가능하며, 길이는 4입니다. 다음 원소 5를 포함하면 합이 15가 되어 조건을 만족하지 않습니다.*

## 힌트

- 현재 부분 배열의 합을 유지하면서 창(Window)을 확장하고 축소하는 방식을 생각해보세요.
- 두 포인터 (Left, Right) 기법과 현재 합(Current Sum) 변수를 활용해야 합니다.


## 알고리즘 요약

이 문제는 슬라이딩 윈도우(Sliding Window) 또는 Two Pointers 기법으로 해결할 수 있습니다. 우리는 배열의 오른쪽 끝을 `Right` 포인터로 이동시키면서 부분 배열을 확장하고, 현재까지의 합(`Current Sum`)을 계산합니다. 만약 `Current Sum`이 주어진 상수 $K$보다 커지면, 가장 왼쪽의 원소부터 순차적으로 제거하며 `Left` 포인터를 오른쪽으로 이동시켜 합을 줄입니다. 매 단계마다 현재 윈도우 크기 (`Right - Left + 1`)가 최대 길이 후보가 되므로, 이 값을 기록하여 최종 답을 구합니다.

## 풀이 해설

아이디어:
이 문제는 조건을 만족하는 가장 긴 연속 부분 배열의 길이를 찾는 문제입니다. '슬라이딩 윈도우' 기법을 사용하여 시간 복잡도를 최적화할 수 있습니다.

단계별 풀이:
1. 초기화: `Left` 포인터(시작 인덱스)를 0으로, `Right` 포인터(끝 인덱스)를 0으로 설정하고, `Current Sum`을 0으로, `MaxLength`를 0으로 초기화합니다.
2. 확장 (R 이동): `Right` 포인터를 배열 끝까지 한 칸씩 증가시키면서 `A[Right]` 값을 `Current Sum`에 더하여 윈도우를 확장합니다.
3. 수축 (L 이동): 만약 `Current Sum`이 $K$보다 크거나 같아지는 순간(즉, 조건을 위반하는 순간), 우리는 윈도우가 유효하지 않다는 것을 알게 됩니다. 이때 `Left` 포인터를 오른쪽으로 한 칸 증가시키고, 제거된 원소 `A[Left]` 값을 `Current Sum`에서 빼줍니다. 이 과정을 `Current Sum < K`를 만족할 때까지 반복합니다.
4. 최대 길이 갱신: 윈도우가 유효한 상태(`Current Sum < K`)일 때마다, 현재 윈도우의 크기 (`Right - Left + 1`)를 계산하여 `MaxLength`와 비교하고 더 큰 값으로 갱신합니다.
5. 종료: `Right` 포인터가 끝에 도달하면 `MaxLength`가 최종 답이 됩니다.

시간 복잡도 분석:
The `Right` 포인터는 $N$번 이동하며, `Left` 포인터 역시 최대 $N$번 이동합니다. 두 포인터의 총 이동 횟수는 선형적($O(N)$)이며, 각 단계에서의 연산은 상수 시간($O(1)$)이므로 전체 시간 복잡도는 $O(N)$입니다.

## 참고 코드 (javascript)

```javascript
/**
 * Node.js 환경에서 표준 입력을 처리하는 함수를 가정합니다.
 * 실제 코딩 테스트 환경에 맞게 입력 파싱 로직을 조정해야 합니다.
 */
function solve(input) {
    // 예시: input이 "3\n1 2 3\n6" 형태의 문자열이라고 가정하고 파싱
    const lines = input.trim().split('\n');
    if (lines.length < 3) return 0; // 입력 부족 처리

    // N은 첫 줄에 있지만, 배열 길이로 사용하므로 생략 가능
    // const N = parseInt(lines[0].trim()); 
    
    const A = lines[1].split(' ').map(Number);
    const K = parseInt(lines[2].trim());

    let left = 0;
    let currentSum = 0;
    let maxLength = 0;
    
    // Right 포인터를 배열 끝까지 이동시키며 윈도우를 확장합니다.
    for (let right = 0; right < A.length; right++) {
        currentSum += A[right];

        // 합이 K보다 크거나 같으면, Left 포인터를 움직여 조건을 만족할 때까지 축소합니다.
        while (currentSum >= K && left <= right) {
            currentSum -= A[left];
            left++;
        }

        // 윈도우가 유효하다면(Left <= Right), 길이를 갱신합니다.
        // 참고: 만약 모든 원소가 양수이고, K가 매우 작아서 Left > Right가 되는 경우가 발생하면 이 부분에서 처리해야 하지만, 
        // 현재 로직상 while문이 돌면서 currentSum < K를 만족하게 되므로 항상 유효한 윈도우 크기를 계산합니다.
        if (left <= right) {
             maxLength = Math.max(maxLength, right - left + 1);
        }
    }

    return maxLength;
}

// 테스트 실행을 위한 더미 입력 처리 함수 (실제 제출 시에는 환경에 맞게 수정 필요)
function runTest(input) {
    try {
        const result = solve(input);
        console.log(result);
    } catch (e) {
        // 에러 처리 로직
    }
}

// R=1: sum=4. maxLen=2.
```
