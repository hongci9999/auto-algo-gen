# 최소 비용 최대 유량 경로 찾기
*javascript · 그래프 · 보통 · Dijkstra, 최단경로, 최대유량*

## 입출력 환경

Javascript 환경에서 표준 입력을 읽을 때, 모든 입력을 한 번에 받고 파싱하는 방식을 사용해야 합니다 (예: readline 모듈 또는 전체 입력 문자열 처리).

## 문제

당신은 여러 개의 노드와 간선으로 이루어진 네트워크를 관리하는 엔지니어입니다. 각 간선에는 최대 흐름(Capacity)과 비용(Cost)이 할당되어 있습니다.

여러 지점 A에서 시작하여 목표 지점 B까지 유량을 흘려보내야 하는데, 이때 총 비용을 최소화하면서 최대한 많은 양의 유량을 보내는 경로를 찾아야 합니다. 즉, **최소 비용 최대 유량 (Min-Cost Max-Flow)** 문제를 해결해야 합니다.

주어진 그래프에서 시작 노드 $S$ (Source)에서 끝 노드 $T$ (Sink)까지 흐를 수 있는 최대 유량 중, 총 비용이 최소가 되는 값을 찾으세요. 이 값은 단순히 '최대 유량'을 의미하는 것이 아니라, **유량이 가장 많은 상태**를 유지하면서 그 과정에서 발생하는 **총 비용의 최솟값**을 찾는 문제입니다.

*주의: 문제에서는 $S$와 $T$ 노드만 주어지며, 모든 간선은 양수 용량과 양수 비용을 가집니다. 이 문제는 일반적인 Min-Cost Max-Flow 알고리즘(예: Successive Shortest Path Algorithm)을 적용하여 해결해야 합니다.*

## 입력

첫 줄에 노드의 개수 $N$, 시작 노드 $S$, 끝 노드 $T$가 주어집니다.
다음 $M$개의 간선 정보가 순서대로 주어지며, 각 간선은 `u v capacity cost` 형식으로 나타냅니다. 여기서 $u$와 $v$는 노드 번호(1부터 시작), capacity는 최대 흐름 용량, cost는 단위 유량당 비용입니다.

## 출력

총 최소 비용을 계산하여 하나의 정수 값으로 출력합니다.

## 제약 조건

노드의 개수 $N$: 1 $\le N \le 50$. 간선의 개수 $M$: 1 $\le M \le 200$. 용량(Capacity): 1 $\le Capacity \le 10^9$. 비용(Cost): 1 $\le Cost \le 10^4$. 총 유량은 최대 $N 	imes C$ (C는 최대 용량)까지 가능할 수 있습니다. 시간 복잡도는 효율적이어야 합니다.

## 예제 1

**입력**
```
4 1 4
1 2 10 3
2 3 5 2
3 4 8 4
1 3 3 1
```

**출력**
```
27
```

*최대 유량은 16이며, 최소 비용은 27입니다. (경로: 1->2->3->4 + 1->3->4)*

## 예제 2

**입력**
```
5 1 5
1 2 10 1
2 3 10 1
3 4 10 1
1 5 5 5
```

**출력**
```
17
```

*최대 유량은 15이며, 최소 비용은 17입니다. (경로: 1->2->3->4->5 및 1->5)*

## 힌트

- 이 문제는 일반적인 최대 유량(Max Flow) 알고리즘과 최단 경로(Shortest Path) 알고리즘을 결합해야 합니다.
- Successive Shortest Path Algorithm (SSP) 또는 Cycle Canceling Algorithm의 개념을 이해하고, 비용 그래프를 사용하여 구현하는 것이 핵심입니다.


## 알고리즘 요약

최소 비용 최대 유량 (Min-Cost Max-Flow): 이 문제는 잔여 그래프(Residual Graph) 상에서 시작 노드 $S$부터 끝 노드 $T$까지의 최단 경로를 반복적으로 찾아 유량을 흘려보내고, 그 비용을 누적하는 방식으로 해결합니다. 각 반복마다 '비용'을 최소화하면서 최대 유량에 근접하게 만듭니다. 이는 다익스트라(Dijkstra) 알고리즘이나 벨만-포드(Bellman-Ford) 알고리즘을 사용하여 구현할 수 있습니다 (간선 비용이 음수가 될 가능성이 없다면 다익스트라 사용).

## 풀이 해설

### 💡 아이디어: Successive Shortest Path (SSP)

최소 비용 최대 유량 문제의 핵심은 '잔여 그래프(Residual Graph)'를 활용하는 것입니다. 처음에는 모든 간선이 가용하며, 각 간선을 따라 유량을 보내는 데 드는 비용이 있습니다.

1. **초기화**: 총 유량 $F=0$, 총 비용 $C_{total}=0$으로 시작합니다.
2. **최단 경로 탐색**: 현재 잔여 그래프 상에서 $S$부터 $T$까지의 '비용'이 최소인 경로를 찾습니다. (간선의 용량을 고려하여, 실제로 흐를 수 있는 최대 유량 $	ext{flow}_{path}$과 해당 경로의 총 비용 $	ext{cost}_{path}$를 계산합니다.)
3. **유량 전송 및 업데이트**: 이 최단 경로 $	ext{Path}$을 따라 가능한 최대 유량 $	ext{flow}_{path}$만큼 $S$에서 $T$로 보냅니다.
4. **잔여 그래프 갱신**: 
    - Path 상의 간선 $(u, v)$는 용량이 $	ext{flow}_{path}$만큼 감소하고, 역방향 간선 $(v, u)$이 생성되거나 증설됩니다. 이 역방향 간선은 유량을 되돌릴 수 있게 하며, 비용은 $- 	ext{cost}(u, v)$가 됩니다.
    - $C_{total} = C_{total} + (	ext{flow}_{path} 	imes 	ext{cost}_{path})$.
5. **반복**: Path가 더 이상 존재하거나(즉, $S$에서 $T$로 가는 경로의 비용이 음수가 되는 경우 등), 추가적인 유량 전송으로 비용 증가가 없을 때까지 2~4단계를 반복합니다.

### ⚙️ 단계별 구현 (다익스트라 활용)

1. **그래프 구조**: 모든 간선 정보(용량, 비용)를 저장하고, 역방향 간선을 추가할 수 있도록 인접 리스트 형태로 구성합니다.
2. **최단 경로 탐색**: 다익스트라 알고리즘을 사용하여 $S$에서 $T$까지의 최소 비용 경로를 찾습니다. 이때 거리는 '비용'으로 정의됩니다.
3. **경로 발견 및 유량 결정**: 다익스트라가 종료되면, $T$에 도달하는 가장 짧은 경로상의 모든 간선 $(u, v)$ 중 남아있는 용량을 계산하여 $	ext{flow}_{path}$를 결정합니다 (최소 용량이 최대 유량이 됨).
4. **업데이트**: $	ext{flow}_{path}$만큼의 유량을 전송하고, 총 비용을 업데이트하며, 잔여 그래프의 용량과 역방향 간선의 비용/용량을 갱신합니다.
5. **종료 조건**: 다익스트라 알고리즘이 $T$에 도달하지 못하거나(도달 불가능), 더 이상 유량이 흐를 수 없을 때까지 반복합니다.

## 참고 코드 (javascript)

```javascript
/**
 * Min-Cost Max-Flow (Successive Shortest Path Algorithm)
 * @param {number} N - 노드 개수
 * @param {number} S - 시작 노드 (Source)
 * @param {number} T - 끝 노드 (Sink)
 * @param {Array<{u: number, v: number, capacity: number, cost: number}>} edges - 간선 배열
 * @returns {bigint} 최소 비용
 */
function minCostMaxFlow(N, S, T, edges) {
    // 노드 번호는 1부터 시작하므로, 인덱스를 맞추기 위해 N+1 크기의 배열 사용
    const MAX_CAP = BigInt(2e18); // 용량 및 비용 합계가 커질 수 있으므로 BigInt 사용

    // 그래프 구조: [to, capacity, cost, reverseEdgeIndex]
    let graph = Array(N + 1).fill(0).map(() => []);

    function addEdge(u, v, cap, cost) {
        // 정방향 간선 추가 (forward edge)
        graph[u].push({ to: v, capacity: BigInt(cap), cost: BigInt(cost), rev: graph[v].length });
        // 역방향 간선 추가 (residual/backward edge). 비용은 -cost.
        graph[v].push({ to: u, capacity: 0n, cost: -BigInt(cost), rev: graph[u].length - 1 });
    }

    for (const edge of edges) {
        addEdge(edge.u, edge.v, edge.capacity, edge.cost);
    }

    let totalFlow = 0n; // 총 유량은 필요하지 않지만 계산 과정에 포함됨
    let minCost = 0n;

    // Dijkstra를 사용하여 S에서 T까지의 최소 비용 경로 탐색을 반복
    while (true) {
        // distance[i]: S에서 i까지의 최소 비용
        const dist = Array(N + 1).fill(MAX_CAP); 
        // parentEdge[i]: i에 도달하기 직전 간선의 인덱스 (graph[u] 내부)
        const parentEdge = Array(N + 1).fill(-1);
        // parentNode[i]: i의 부모 노드
        const parentNode = Array(N + 1).fill(-1); 
        
        dist[S] = 0n;
        
        // Priority Queue: [cost, node]
        // JavaScript에는 기본 PQ가 없으므로 간단한 배열 기반 구현 또는 MinHeap 사용을 가정합니다.
        // 여기서는 개념 설명을 위해 min-heap 역할을 하는 구조체를 직접 작성하는 대신, 일반적인 Dijkstra 로직을 따릅니다.
        const pq = [{ cost: 0n, node: S }]; 

        while (pq.length > 0) {
            // Min-Heap Pop (가장 비용이 낮은 노드 추출)
            pq.sort((a, b) => (a.cost < b.cost ? -1 : a.cost > b.cost ? 1 : 0));
            const { cost: currentCost, node: u } = pq.shift();

            if (currentCost > dist[u]) continue;
            if (u === T) break; // 최적 경로를 찾았으면 종료 가능

            for (let i = 0; i < graph[u].length; i++) {
                const edge = graph[u][i];
                const v = edge.to;
                const capacity = edge.capacity;
                const costChange = edge.cost;

                // 1. 용량이 남아있고 (capacity > 0) 
                // 2. 현재까지의 비용보다 더 적은 경로를 발견했을 경우
                if (capacity > 0n && dist[u] + costChange < dist[v]) {
                    dist[v] = dist[u] + costChange;
                    parentEdge[v] = i;
                    parentNode[v] = u;
                    pq.push({ cost: dist[v], node: v });
                }
            }
        }

        // T에 도달하는 경로가 존재하고(dist[T] < MAX_CAP) 비용이 음수가 아닌 경우 (선택적 종료 조건)
        if (dist[T] === MAX_CAP || dist[T] >= 0n && parentNode[T] === -1) {
             // 참고: 일반적으로 Min-Cost Max-Flow에서는 T에 도달할 수 없을 때까지 반복합니다.
            break;
        }

        // 2. 경로 상의 최대 흐름(Bottle-neck Capacity) 결정
        let flowPath = MAX_CAP; // 초기화는 큰 값으로 설정
        let curr = T;
        while (curr !== S) {
            const u = parentNode[curr];
            const edgeIndex = parentEdge[curr];
            const edge = graph[u][edgeIndex];
            flowPath = flowPath < edge.capacity ? flowPath : edge.capacity; // 최소 용량 갱신
            curr = u;
        }

        // 3. 총 비용 및 유량 업데이트
        minCost += dist[T] * flowPath;
        totalFlow += flowPath;

        // 4. 잔여 그래프 갱신 (Residual Graph Update)
        let currUpdate = T;
        while (currUpdate !== S) {
            const u = parentNode[currUpdate];
            const edgeIndex = parentEdge[currUpdate];
            const revEdgeIndex = graph[u][edgeIndex].rev;

            // 정방향 용량 감소 
            graph[u][edgeIndex].capacity -= flowPath;
            // 역방향 용량 증가 (되돌릴 수 있는 유량)
            graph[currUpdate][revEdgeIndex].capacity += flowPath;
            
            currUpdate = u;
        }
    }

    return minCost.toString(); // BigInt를 문자열로 변환하여 반환
}
```
