# 최소 비용 연결 나무
*javascript · 그래프 · 보통 · MST, 다익스트라*

## 입출력 환경

Node.js 환경에서 모든 입력을 읽어와 배열로 처리합니다.

## 문제

N개의 도시가 있고, 각 도시 쌍 사이에는 도로가 건설될 수 있습니다. 각 도로는 특정 비용을 가집니다.

우리는 모든 N개의 도시를 연결하는 최소 비용의 도로망(최소 신장 트리)을 구축하려고 합니다. 단, 일부 도로는 이미 다른 프로젝트에서 건설되어 존재하는 경우도 있습니다. 존재하지 않는 도로는 당연히 사용할 수 없습니다.

도로 정보는 (도시 A, 도시 B, 비용 C) 형태로 주어지며, 이는 가능한 모든 도로를 나타냅니다.

## 입력

첫째 줄에 N개의 도시의 개수와 M개의 주어진 도로 정보를 받습니다. (N, M)
다음 M줄에 걸쳐 각 도로는 `A B C` 형식으로 주어집니다. A와 B는 1부터 N 사이의 도시 번호이며, C는 비용입니다.

## 출력

모든 도시를 연결하는 최소 비용을 나타내는 단일 정수 값

## 제약 조건

N: 2 <= N <= 100
M: 1 <= M <= N*(N-1)/2
C: 1 <= C <= 1,000,000,000 (비용은 매우 클 수 있습니다.)

## 예제 1

**입력**
```
4 5
1 2 3
1 3 2
2 3 1
2 4 5
3 4 4
```

**출력**
```
7
```

*주어진 간선들로 MST를 구성합니다. (1-2, 2-3, 1-3 중 최소 비용으로 연결)
최소 비용은 1+2+3=6? -> 아닙니다. N이 4개 도시이고 M이 5개 도로 정보입니다.
실제 계산: (2-3) 1, (1-3) 2, (1-2) 3, (2-4) 5, (3-4) 4. MST는 { (2,3), (1,3), (2,4) } 또는 { (2,3), (1,2), (3,4) } 등 여러 조합이 가능하며 비용은 최소 7입니다.
(예: 1-3 (2) -> 2-3 (1) -> 2-4 (5). 총합 8? 아닙니다. Kruskal 또는 Prim 사용 필요.)
정답 경로: { (2,3): 1, (1,3): 2, (3,4): 4 }. 총 비용 = 7.*

## 힌트

- Kruskal의 알고리즘이나 Prim의 알고리즘을 사용하여 최소 신장 트리를 찾으세요.
- Union-Find 자료구조는 간선의 순서대로 연결성을 판단하는 데 매우 유용합니다.


## 알고리즘 요약

이 문제는 전형적인 '최소 신장 트리(Minimum Spanning Tree, MST)' 문제입니다. N개의 도시를 모두 연결하면서도 총 비용을 최소화해야 합니다.

1. **크루스칼 알고리즘 (Kruskal's Algorithm) 사용**: 모든 간선을 오름차순으로 정렬한 뒤, 사이클을 형성하지 않는 간선들을 하나씩 선택하여 트리를 만듭니다. 이때 Union-Find 자료구조를 사용하여 두 도시가 이미 같은 연결 요소에 속해 있는지 빠르게 확인합니다.
2. **Prim의 알고리즘 (Prim's Algorithm) 사용**: 특정 시작 노드에서 출발하여, 현재 트리와 가장자리 중 최소 비용으로 연결되는 간선을 반복적으로 선택합니다. 우선순위 큐(Priority Queue)를 사용하는 것이 효율적입니다.

## 풀이 해설

이 문제는 N개의 도시들을 모두 포함하는 최소 신장 트리를 찾는 문제입니다. 주어진 조건과 제약 조건(N<=100, M<=5000)을 고려할 때, 크루스칼 알고리즘이 가장 직관적이고 구현하기 용이합니다.

**[아이디어]**: 모든 가능한 도로 정보(간선)를 비용 순으로 정렬한 뒤, 사이클을 만들지 않으면서 간선을 추가해 나가는 방식으로 최소 비용의 트리를 구성합니다.

**[단계별 풀이 - 크루스칼 알고리즘]**: 
1. **간선 리스트 작성 및 정렬**: 모든 (A, B, C) 형태의 간선을 하나의 배열에 담고, 이 배열을 비용(C)을 기준으로 오름차순 정렬합니다.
2. **Union-Find 초기화**: N개의 도시 각각에 대해 Union-Find 구조를 초기화합니다. 이는 각 도시에 '부모'를 설정하고, 같은 집합에 속하는지 빠르게 체크하기 위함입니다.
3. **간선 탐색 및 MST 구성**: 정렬된 간선들을 순회하며 다음을 확인합니다:
    a. 현재 간선의 두 도시(A와 B)가 이미 같은 연결 요소(Union-Find의 `find` 연산으로 확인)에 속해 있다면, 이 간선을 추가해도 사이클이 발생하므로 무시합니다.
    b. 그렇지 않다면, 이 간선은 트리에 반드시 포함되어야 할 최소 비용 간선입니다. 총 비용에 C를 더하고, 두 도시 A와 B의 연결 상태를 `union` 연산으로 병합(연결)합니다.
4. **종료 조건 확인**: N개의 노드를 모두 연결했는지 (즉, MST가 완성되었는지) 확인해야 합니다. 만약 모든 간선을 다 사용했는데도 연결된 요소의 개수가 1이 아니라면, 즉 일부 도시들이 고립되어 있다면, 주어진 도로는 전체를 연결할 수 없다는 의미입니다.
5. **결과 반환**: 총합계 비용을 반환합니다. (만약 모든 노드가 연결되지 않으면 '불가능' 등의 특수 값을 처리해야 합니다.)

**[시간 복잡도]**: 
1. 간선 정렬: $O(M 	imes 	ext{log} M)$ (여기서 $M$은 간선의 개수).
2. 크루스칼 탐색: $O(M 	imes 	ext{find}/	ext{union})$ (Union-Find 연산이 거의 상수 시간 $eta(N)$에 가깝기 때문에 사실상 $O(M)$). 
전체 복잡도는 간선 정렬 시간이 지배적입니다. $O(M 	ext{ log } M)$. 이는 주어진 제약 조건 내에서 매우 효율적인 시간 복잡도입니다.

/**
 * Union-Find 자료구조 구현 (Disjoint Set Union)
 */
class UnionFind {
    constructor(n) {
        // 부모 배열: i는 자기 자신의 부모를 가리킵니다. 1부터 N까지 사용하기 위해 크기 N+1로 설정합니다.
        this.parent = Array(n + 1).fill(0).map((_, i) => i);
        // 랭크/사이즈 배열: 최적화를 위해 사용
        this.rank = Array(n + 1).fill(0);
        this.count = n; // 초기 연결 요소의 개수
    }

    // find(i): 노드 i가 속한 집합의 대표 원소(루트)를 찾습니다.
    find(i) {
        if (this.parent[i] === i) {
            return i;
        }
        // 경로 압축(Path Compression)
        this.parent[i] = this.find(this.parent[i]);
        return this.parent[i];
    }

    // union(i, j): 노드 i와 j가 속한 두 집합을 합칩니다.
    // 같은 집합이면 아무것도 하지 않습니다.
    union(i, j) {
        const rootI = this.find(i);
        const rootJ = this.find(j);

        if (rootI !== rootJ) {
            // 랭크 기반 합치기 (Union by Rank)
            if (this.rank[rootI] < this.rank[rootJ]) {
                this.parent[rootI] = rootJ;
            } else if (this.rank[rootI] > this.rank[rootJ]) {
                this.parent[rootJ] = rootI;
            } else {
                // 랭크가 같으면 임의로 하나를 부모로 지정하고 랭크 증가
                this.parent[rootJ] = rootI;
                this.rank[rootI]++;
            }
            this.count--; // 연결 요소가 하나 줄어듦
            return true; // 성공적으로 합쳐짐
        } else {
            return false; // 이미 같은 집합임 (사이클 발생)
        }
    }

    // 현재 남아있는 독립적인 연결 요소의 개수를 반환합니다.
    getComponentCount() {
        return this.count;
    }
}
