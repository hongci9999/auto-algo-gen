# 최소 비용으로 트리를 연결하기
*javascript · 자료구조 · 보통 · MST, Union-Find*

## 입출력 환경

JavaScript 환경에서는 일반적으로 표준 입력 스트림을 사용하며, 여러 줄의 입력을 처리하기 위해 전체 입력을 읽은 후 파싱하는 방식을 사용합니다.

## 문제

N개의 도시가 있고, 각 도시 쌍 사이에는 연결할 수 있는 도로가 존재합니다. 각 도로는 연결 비용을 가집니다. 목표는 모든 도시를 연결하는 최소 비용의 트리를 만드는 것입니다. 주어진 도로 정보만으로 모든 도시를 연결할 수 있는지, 그리고 가능하다면 최소 비용은 얼마인지 구하세요.

만약 모든 도시를 연결할 수 없다면, 연결할 수 없는 상태를 나타내는 특정 값을 출력해야 합니다. 이 문제에서는 모든 도시를 연결할 수 없을 경우 -1을 출력합니다.

## 입력

첫 번째 줄은 도시의 개수 N (1 <= N <= 100).
두 번째 줄부터는 도로 정보가 주어집니다. 각 줄은 'u v w' 형식으로, u는 시작 도시, v는 끝 도시, w는 연결 비용입니다. (1 <= u, v <= N, 1 <= w <= 1000).
도로의 개수는 N과 무관하며, 최대 1000개입니다.

## 출력

모든 도시를 연결하는 최소 비용 트리의 총 비용을 출력합니다. 만약 모든 도시를 연결할 수 없다면 -1을 출력합니다.

## 제약 조건

N: 1부터 100까지. 도로 개수: 최대 1000개. 비용 w: 1부터 1000까지. 시간 복잡도는 O(E log E) 또는 유사해야 합니다.

## 예제 1

**입력**
```
4
1 2 3
1 3 2
2 3 1
2 4 5
3 4 4
```

**출력**
```
7
```

*최소 신장 트리(MST)를 구합니다. 연결된 간선은 (2,3,1), (1,3,2), (2,4,5)이며 총 비용은 1+2+5=8입니다. (주의: 예시 설명에 오류가 있을 수 있으니, 실제 MST 비용 계산을 따릅니다. 가장 적절한 경로는 1-3-2-4: 2+1+5=8입니다. 만약 문제에서 모든 간선을 사용해야 한다고 가정하면, 문제 조건에 맞게 최소 비용 트리를 찾습니다. (1,2)를 제외하면 1-3-2-4는 8입니다. 1-2-3-4는 3+1+4=8입니다. 1-3-2-4는 2+1+5=8입니다. 주어진 간선 중 4개의 노드를 연결하는 최소 비용 트리는 8입니다.)*

## 힌트

- 크루스칼 알고리즘(Kruskal's Algorithm) 또는 프림 알고리즘(Prim's Algorithm)을 사용합니다.
- Union-Find(Disjoint Set Union) 자료구조가 효율적입니다.
- 최소 신장 트리(MST)의 개념을 이해해야 합니다.


## 알고리즘 요약

이 문제는 모든 도시를 최소 비용으로 연결하는 최소 신장 트리(Minimum Spanning Tree, MST)를 찾는 문제입니다. 간선이 많은 경우 크루스칼 알고리즘을 사용하는 것이 효율적입니다. 크루스칼 알고리즘은 모든 간선을 비용 오름차순으로 정렬한 후, 사이클을 형성하지 않는 간선을 차례로 선택하여 트리를 구성합니다. Union-Find 자료구조를 사용하여 사이클 여부를 효율적으로 판별합니다. 최종적으로 트리에 포함된 간선의 비용 합을 반환하고, 만약 포함된 간선의 개수가 N-1개 미만이거나, 모든 노드가 하나의 집합으로 연결되지 않았다면 -1을 반환합니다.

## 풀이 해설

### 💡 문제 이해
주어진 N개의 도시와 그 사이의 연결 비용(간선)을 이용하여, 모든 도시를 연결하는 가장 저렴한 방법(최소 비용 트리)을 찾아야 합니다. 이것이 바로 최소 신장 트리(MST) 문제입니다.

### 🚀 알고리즘 (크루스칼 알고리즘)
크루스칼 알고리즘은 간선의 비용을 오름차순으로 정렬한 후, 사이클을 만들지 않는 간선을 하나씩 선택해 나가는 방식입니다.

**1. 간선 정렬:** 모든 간선 (u, v, w)을 비용 w가 낮은 순서대로 정렬합니다.
**2. Union-Find 초기화:** N개의 도시 각각을 독립된 집합으로 간주하고 Union-Find 자료구조를 초기화합니다. (각 노드는 자신의 부모를 가리키며, 초기에는 자신을 가리킵니다.)
**3. 간선 탐색 및 연결:** 정렬된 간선을 순회하며 다음을 수행합니다:
    a. **사이클 검사:** 간선 (u, v, w)에 대해 `find(u)`와 `find(v)`를 비교합니다. 만약 두 값이 같다면, u와 v는 이미 같은 집합에 속해 있다는 뜻이므로, 이 간선을 추가하면 사이클이 발생합니다. 따라서 이 간선은 무시합니다.
    b. **MST에 추가:** 두 값이 다르다면, 이 간선은 트리를 확장하는 데 필수적입니다. 비용 w를 총 비용에 더하고, `union(u, v)`를 수행하여 u와 v를 같은 집합으로 합칩니다.
**4. 결과 확인:** 모든 간선 탐색이 끝난 후, 총 비용을 반환합니다. 이때, 모든 도시가 연결되었는지 확인해야 합니다. N개의 도시를 연결하려면 정확히 N-1개의 간선이 필요합니다. 만약 선택된 간선의 개수가 N-1개보다 적다면, 모든 도시를 연결할 수 없다는 의미이므로 -1을 반환합니다.

### ⏱️ 시간 복잡도
1. 간선 정렬: O(E log E) (E는 간선의 개수)
2. Union-Find 연산: O(E * α(N)), 여기서 α(N)은 아커만 함수의 역함수(매우 느리게 증가하여 사실상 상수 시간으로 간주됨)입니다.
전체 시간 복잡도는 간선 정렬에 의해 결정되는 **O(E log E)**입니다. (E < N^2이므로, N=100, E=1000일 경우 매우 빠름)

### 🛠️ 구현 세부 사항
*   **Union-Find:** `parent` 배열을 사용하여 부모 노드를 관리하고, `find` 연산 시 경로 압축(Path Compression)을, `union` 연산 시 랭크(Rank) 또는 크기 기반 합치기(Union by Size)를 적용하여 최적화해야 합니다. (이 예제에서는 경로 압축만 적용해도 충분합니다.)
*   **결과 검증:** MST의 간선 개수가 N-1개인지 확인하는 것이 가장 확실한 방법입니다.

## 참고 코드 (javascript)

```javascript
/**
 * @param {number} N 도시의 개수
 * @param {Array<{u: number, v: number, w: number}>} edges 간선 목록
 * @returns {number} 최소 비용 또는 -1
 */
const solve = (N, edges) => {
    // 1. 간선을 비용 w를 기준으로 오름차순 정렬 (크루스칼의 핵심)
    edges.sort((a, b) => a.w - b.w);

    // 2. Union-Find 자료구조 초기화
    const parent = Array(N + 1).fill(0).map((_, i) => i);
    const rank = Array(N + 1).fill(0);

    // Find 연산 (경로 압축 적용)
    const find = (i) => {
        if (parent[i] === i) {
            return i;
        }
        parent[i] = find(parent[i]); // 경로 압축
        return parent[i];
    };

    // Union 연산 (랭크 기반)
    const union = (i, j) => {
        const rootI = find(i);
        const rootJ = find(j);

        if (rootI !== rootJ) {
            // 랭크가 낮은 쪽을 높은 쪽 아래에 붙임
            if (rank[rootI] < rank[rootJ]) {
                parent[rootI] = rootJ;
            } else if (rank[rootI] > rank[rootJ]) {
                parent[rootJ] = rootI;
            } else {
                // 랭크가 같으면 임의로 하나를 부모로 지정하고 랭크 증가
                parent[rootJ] = rootI;
                rank[rootI]++;
            }
            return true; // 성공적으로 합쳐짐
        }
        return false; // 이미 같은 집합에 속함 (사이클 발생)
    };

    let totalCost = 0;
    let edgesUsed = 0;

    // 3. 간선 탐색 및 MST 구성
    for (const edge of edges) {
        const { u, v, w } = edge;
        
        // 사이클이 발생하지 않는 경우에만 연결 (Union 시도)
        if (union(u, v)) {
            totalCost += w;
            edgesUsed++;
        }
    }

    // 4. 결과 확인: N개의 도시를 연결하려면 정확히 N-1개의 간선이 필요함
    if (edgesUsed === N - 1) {
        return totalCost;
    } else {
        // 만약 N=1인 경우 (도시가 하나만 있는 경우) 예외 처리
        if (N === 1) {
            return 0;
        }
        return -1;
    }
};

// ==================================================
// 입출력 처리 (실제 코딩테스트 환경 시뮬레이션)
// ==================================================

// 테스트 케이스 1: 모든 노드가 연결됨
const N1 = 4;
const edges1 = [
    { u: 1, v: 2, w: 3 },
    { u: 1, v: 3, w: 2 },
    { u: 2, v: 3, w: 1 },
    { u: 2, v: 4, w: 5 },
    { u: 3, v: 4, w: 4 }
];
console.log(solve(N1, edges1)); // 예상 출력: 8 (1-3(2) -> 2-3(1) -> 2-4(5). 총 8)

// 테스트 케이스 2: 일부 노드가 연결되지 않음
const N2 = 3;
const edges2 = [
    { u: 1, v: 2, w: 10 },
    { u: 2, v: 3, w: 10 }
];
console.log(solve(N2, edges2)); // 예상 출력: 20

// 테스트 케이스 3: 연결 불가능
const N3 = 3;
const edges3 = [
    { u: 1, v: 2, w: 10 }
];
console.log(solve(N3, edges3)); // 예상 출력: -1

// 테스트 케이스 4: 노드가 하나만 있는 경우
const N4 = 1;
const edges4 = [];
console.log(solve(N4, edges4)); // 예상 출력: 0
```
