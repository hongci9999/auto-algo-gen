# 가장 긴 부분 배열의 합
*javascript · 자료구조 · 보통 · 배열, 자료구조, Prefix Sum*

## 입출력 환경

Node.js 환경에서 입력을 받을 때는 'readline' 모듈이나 'fs' 모듈을 사용하여 전체 입력을 처리하고 파싱하는 것이 일반적입니다. 여기서는 모든 입력을 받아서 배열로 처리하는 방식으로 가정합니다.

## 문제

정수 배열 `arr`과 목표 합 `K`가 주어졌을 때, 합이 `K`가 되는 가장 긴 연속된 부분 배열의 길이를 구하는 문제입니다.

부분 배열의 합은 연속된 원소들만을 합한 값이어야 합니다. 만약 합이 `K`가 되는 부분이 존재하지 않는다면 0을 출력해야 합니다.

예시: arr = [1, 2, 3, 1], K = 6. 합이 6이 되는 부분 배열은 [2, 3, 1]로 길이가 3입니다.

## 입력

첫 번째 줄에 정수 N (배열의 길이)이 주어지며, 두 번째 줄에 N개의 정수 원소가 공백으로 구분되어 주어집니다. 세 번째 줄에 목표 합 K가 주어집니다.

## 출력

합이 K가 되는 가장 긴 부분 배열의 길이(정수)를 출력합니다.

## 제약 조건

1. N의 범위: 1 <= N <= 10^5
2. 원소 값의 범위: -10^4 <= arr[i] <= 10^4
3. K의 범위: -10^9 <= K <= 10^9
4. 시간 복잡도는 O(N) 또는 O(N log N) 이내여야 합니다.

## 예제 1

**입력**
```
5
1 2 3 1 1
6
```

**출력**
```
3
```

*부분 배열 [2, 3, 1]의 합이 6이며, 가장 긴 부분 배열입니다.*

## 예제 2

**입력**
```
4
1 2 -1 3
3
```

**출력**
```
3
```

*부분 배열 [1, 2, -1] 또는 [2, -1, 3]이 합 3을 만들며, 둘 다 길이가 3입니다.*

## 예제 3

**입력**
```
3
1 2 3
7
```

**출력**
```
0
```

*합이 7이 되는 부분 배열이 존재하지 않습니다.*

## 힌트

- 부분 배열의 합은 누적 합(Prefix Sum)의 개념을 활용할 수 있습니다.
- 누적 합을 저장하는 맵(Map) 자료구조를 사용하면 시간 복잡도를 최적화할 수 있습니다.


## 알고리즘 요약

Prefix Sum과 HashMap을 이용한 접근입니다. 배열의 인덱스 i까지의 누적 합을 P[i]라고 정의했을 때, 부분 배열 arr[j+1...i]의 합은 P[i] - P[j]가 됩니다. 우리가 원하는 합 K를 구하려면 P[i] - P[j] = K, 즉 P[j] = P[i] - K가 성립해야 합니다. 따라서, 현재 누적 합 P[i]에서 목표 합 K만큼 뺀 값(P[i] - K)이 이전에 이미 발생한 누적 합 P[j]와 일치하는지 HashMap을 통해 빠르게 확인하고, 최대 길이(i - j)를 갱신합니다.

## 풀이 해설

아이디어:
이 문제는 누적 합(Prefix Sum)과 해시 맵(HashMap)을 결합하여 O(N)의 시간 복잡도로 해결할 수 있습니다. 배열의 인덱스 0부터 i까지의 누적 합을 `currentSum`이라고 정의합니다.

단계:
1. **초기화:** 최대 길이를 `maxLength = 0`으로 설정하고, 현재 누적 합 `currentSum = 0`으로 설정합니다. 또한, 해시 맵 `sumMap`을 초기화하고, `sumMap[0] = -1`로 설정합니다. (이는 합이 0이 되는 경우, 즉 부분 배열이 배열의 시작점부터 K와 같을 때, 시작 위치를 -1로 지정하는 트릭입니다.)
2. **순회 및 계산:** 배열을 처음부터 끝까지 순회하며 `currentSum`을 업데이트합니다. `currentSum += arr[i]`
3. **검색:** 우리가 찾고 있는 조건은, `currentSum - K`가 이전에 이미 누적 합으로 존재했는지 확인하는 것입니다. 즉, `targetSum = currentSum - K`를 계산합니다.
4. **길이 갱신:** 만약 `sumMap`에 `targetSum`이 존재한다면, 이는 `targetSum`이 발생한 인덱스 `j`가 존재한다는 뜻입니다. 이때의 부분 배열의 길이는 현재 인덱스 `i`와 `sumMap[targetSum]`의 차이(`i - sumMap[targetSum]`)가 됩니다. 따라서 `maxLength = max(maxLength, i - sumMap[targetSum])`으로 갱신합니다.
5. **맵 저장:** 현재의 `currentSum`과 현재 인덱스 `i`를 `sumMap`에 저장합니다. (만약 같은 합이 여러 번 발생하더라도, 우리는 가장 *오래된* 인덱스를 저장하는 것이 아니라, 가장 *최근*의 인덱스를 저장해도 무방합니다. 하지만 이 문제의 경우, 더 긴 길이를 원하므로, 덮어써도 괜찮습니다.)

시간 복잡도: 배열을 한 번만 순회하므로 O(N)입니다. 공간 복잡도는 최악의 경우 O(N)입니다.

## 참고 코드 (javascript)

```javascript
/**
 * Node.js 환경에서 실행되는 JavaScript 코드
 * 입력은 표준 입력(stdin)으로 처리한다고 가정합니다.
 */

function solve(inputString) {
    // 입력 파싱: N, arr, K 순서로 배열을 만듭니다.
    const lines = inputString.trim().split('\n');
    if (lines.length < 3) return 0;
    
    // N은 사용되지 않으나 구조 유지를 위해 파싱
    const N = parseInt(lines[0].trim());
    const arr = lines[1].trim().split(/\s+/).map(Number);
    const K = parseInt(lines[2].trim());

    // Map을 사용하여 (누적 합) -> (가장 먼저 도달한 인덱스)를 저장합니다.
    // Key: 누적 합, Value: 인덱스
    const sumMap = new Map();
    
    // 초기 조건: 합 0은 인덱스 -1에서 시작했다고 간주합니다.
    sumMap.set(0, -1);

    let currentSum = 0;
    let maxLength = 0;

    for (let i = 0; i < N; i++) {
        currentSum += arr[i];
        
        // 1. 목표 누적 합 검색: targetSum = currentSum - K
        const targetSum = currentSum - K;
        
        if (sumMap.has(targetSum)) {
            // targetSum이 존재한다면, 해당 인덱스 j에서부터 현재 인덱스 i까지의 합이 K입니다.
            const j = sumMap.get(targetSum);
            const currentLength = i - j;
            maxLength = Math.max(maxLength, currentLength);
        }
        
        // 2. 현재 누적 합 저장: 이 합이 다음에 필요한 targetSum이 될 수 있습니다.
        // 이미 저장된 합이 있어도 덮어써도 무방하지만, 명확성을 위해 덮어쓰지 않거나, 덮어쓰는 경우도 고려할 수 있습니다.
        // 이 문제에서는 가장 최근의 인덱스를 저장하는 것이 일반적입니다.
        sumMap.set(currentSum, i);
    }

    return maxLength;
}

// --- Node.js 표준 입력 처리 시뮬레이션 --- 
// 실제 테스트 환경에서는 이 부분이 입력 로직에 따라 달라집니다.
// 예시 입력을 string으로 받아 처리한다고 가정합니다.
const inputExample = "5\n1 2 3 1 1\n6";
console.log(solve(inputExample));
```
