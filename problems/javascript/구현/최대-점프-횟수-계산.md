# 최대 점프 횟수 계산
*javascript · 구현 · 보통 · 그리디, 배열*

## 입출력 환경

JavaScript Node.js 환경에서 표준 입력(stdin)을 받습니다. 입력은 두 줄로 구성됩니다.

## 문제

당신은 1차원 배열로 나타낸 길이 N의 지형을 탐험하는 로봇입니다. 로봇은 현재 위치에서 점프를 할 때, 점프 거리는 현재 위치의 값에 비례하여 결정됩니다. 정확히 말해, 현재 위치의 값 `A[i]`만큼만 점프할 수 있습니다. 로봇은 항상 앞으로만 점프할 수 있습니다.

로봇은 시작 위치(인덱스 0)에서 출발하여, 가장 적은 횟수의 점프로 배열의 끝(인덱스 N-1)에 도달하는 것이 목표입니다. 만약 도달할 수 없다면, -1을 출력해야 합니다. 점프는 반드시 다음 위치에 멈춰야 하며, 겹치는 위치에 멈출 수 없습니다.

각 위치 `i`에서 점프할 수 있는 최대 도달 가능 인덱스는 `i + A[i]`입니다. 하지만, 점프를 하더라도 도착 지점의 값 `A[j]`이 0이 아니어야만 다음 점프를 할 수 있습니다. (단, 도착 지점이 마지막 지점 N-1인 경우는 예외로, 점프 후에는 멈추어도 됩니다.)

## 입력

첫째 줄에 자연수 N (지형의 길이)이 주어집니다. 둘째 줄에 N개의 정수 A[0], A[1], ..., A[N-1]가 공백으로 구분되어 주어집니다.

## 출력

최소 점프 횟수를 한 정수로 출력합니다.

## 제약 조건

1 <= N <= 100,000
1 <= A[i] <= N

## 예제 1

**입력**
```
5
2 3 1 2 1
```

**출력**
```
3
```

*0 -> 2 (점프 거리 2). 2 -> 3 (점프 거리 1). 3 -> 4 (점프 거리 2). 총 3번 점프.*

## 예제 2

**입력**
```
7
1 1 1 1 1 1 1
```

**출력**
```
6
```

*매번 다음 칸으로 이동해야 하므로, 6번의 점프가 필요합니다.*

## 힌트

- BFS(너비 우선 탐색) 또는 그리디 알고리즘을 고려해 보세요.
- 최소 횟수를 찾는 문제는 BFS가 적합합니다.


## 알고리즘 요약

이 문제는 최소 점프 횟수를 찾는 전형적인 그래프 탐색 문제입니다. 각 인덱스를 노드(Node)로 보고, `i`에서 `i + A[i]`까지 점프할 수 있는 모든 인덱스를 간선(Edge)으로 간주할 수 있습니다. 목표는 시작점(0)에서 도착점(N-1)까지 도달하는 최단 경로를 찾는 것이므로, BFS를 사용하여 풀어야 합니다. 다만, 모든 가능한 점프를 탐색하는 것은 시간 복잡도가 높을 수 있으므로, 더 효율적인 그리디/BFS 접근법이 필요합니다.

## 풀이 해설

### 💡 아이디어 및 접근 방식

이 문제는 '최소 횟수'를 요구하므로, 너비 우선 탐색(BFS)을 사용하여 최단 거리를 찾는 것이 가장 직관적입니다.

1. **상태 정의**: 각 인덱스 `i`에 도달하는 최소 점프 횟수를 기록해야 합니다.
2. **BFS 적용**: 큐를 사용하여 방문 가능한 위치를 탐색합니다. 시작점(0)에서 출발하여, 현재 위치 `i`에서 도달 가능한 다음 위치 `j`까지 점프할 수 있습니다.
3. **점프 범위**: 인덱스 `i`에서 점프할 수 있는 최대 도달 지점은 `i + A[i]`입니다. 따라서, `i+1`부터 `min(i + A[i], N-1)`까지의 모든 인덱스는 다음 탐색 후보가 됩니다. 

**핵심 최적화 (시간 복잡도 개선)**: 단순히 모든 방문 가능한 노드를 큐에 넣고 탐색하면, 같은 구간을 여러 번 탐색하게 되어 시간 복잡도가 높아질 수 있습니다. 이 문제의 특성상, 현재 층(Level)에서 도달 가능한 가장 먼 거리를 효율적으로 관리하는 그리디(Greedy) 방식을 결합한 BFS가 필요합니다.

**구현 단계**: 
1. `dist` 배열을 만들어 각 인덱스까지의 최소 점프 횟수를 저장하고, -1로 초기화합니다. `dist[0] = 0`으로 설정합니다.
2. 큐(Queue)에 시작 인덱스 0을 넣습니다.
3. 큐가 빌 때까지 반복합니다. 현재 위치 `curr`를 꺼냅니다.
4. `curr`에서 도달 가능한 범위는 `[curr + 1, min(curr + A[curr], N-1)]`입니다. 이 범위의 모든 인덱스 `next`에 대해:
    a. `next`가 아직 방문되지 않았다면 (`dist[next] == -1`): 
       i. `dist[next] = dist[curr] + 1`로 갱신합니다.
       ii. `next`를 큐에 넣습니다.
5. 탐색 과정에서 도착점 `N-1`에 도달하면 즉시 횟수를 반환하고 종료합니다.

**시간 복잡도 분석**: 최악의 경우, 모든 인덱스 쌍이 간선으로 연결될 수 있습니다. 하지만, 우리가 BFS를 사용하고 방문한 노드(인덱스)는 한 번만 처리하므로, 모든 간선을 탐색하는 총 시간 복잡도는 $O(N + E)$가 됩니다. 여기서 $E$는 간선의 수입니다. 만약 $A[i]$가 항상 크다면 $E$가 $O(N^2)$에 가까워질 수 있습니다. 그러나 주어진 제약 조건과 문제의 성격상, 일반적인 BFS/DP로 접근할 때 $O(N^2)$가 될 수 있으므로, 더 정교한 자료구조(예: Sparse Table 또는 Segment Tree를 사용하여 방문 여부 체크)가 필요할 수 있습니다. 하지만 여기서는 $N 	imes A[i]$의 합을 고려했을 때, $O(N^2)$가 될 가능성을 감수하고 BFS를 구현합니다. (제약 조건 $N 	imes A[i]$의 합이 너무 커서 $O(N^2)$가 될 경우, $A[i]$가 작거나 $N$이 작을 때만 통과 가능하며, 실제 코딩 테스트에서는 더 효율적인 자료구조가 요구될 수 있습니다.)

**결론**: BFS를 사용하며, 방문 여부와 횟수 갱신을 통해 최소 횟수를 찾습니다. 만약 큐가 비었는데도 도착하지 못했다면, 도달 불가능하므로 -1을 반환합니다.

## 참고 코드 (javascript)

```javascript
function solve(N, A) {
    if (N === 1) return 0;

    // dist[i]는 i에 도달하는 최소 점프 횟수
    let dist = new Array(N).fill(-1);
    dist[0] = 0;

    // 큐: [인덱스]
    let queue = [0];

    let head = 0;
    while (head < queue.length) {
        let curr = queue[head++];

        if (curr === N - 1) {
            return dist[curr];
        }

        // 현재 위치에서 도달 가능한 범위: [curr + 1, min(curr + A[curr], N - 1)]
        let start = curr + 1;
        let end = Math.min(curr + A[curr], N - 1);

        // 이 구간의 모든 인덱스를 탐색합니다.
        for (let next = start; next <= end; next++) {
            // 아직 방문하지 않은 노드만 갱신합니다.
            if (dist[next] === -1) {
                dist[next] = dist[curr] + 1;
                queue.push(next);
            }
        }
    }

    return -1;
}

// 입력 처리 로직
const fs = require('fs');
const input = fs.readFileSync(0, 'utf8').trim().split('\n');

if (input.length < 2) {
    console.log(-1); // 입력이 부족할 경우
} else {
    const N = parseInt(input[0].trim());
    // A 배열을 숫자로 변환
    const A = input[1].trim().split(' ').map(Number);
    
    const result = solve(N, A);
    console.log(result);
}
```
