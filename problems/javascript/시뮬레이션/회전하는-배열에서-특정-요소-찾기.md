# 회전하는 배열에서 특정 요소 찾기
*javascript · 시뮬레이션 · 보통 · 배열, 시뮬레이션, 탐색*

## 입출력 환경

JavaScript 환경에서 표준 입력을 처리할 때는 'readline' 모듈이나 파일 스트림을 사용해야 하며, 여기서는 전체 입력 문자열을 받는 방식으로 가정합니다.

## 문제

N개의 원소를 가진 배열 A가 있습니다. 이 배열은 마치 시계처럼 한 방향으로 회전하는 애니메이션을 한다고 가정합시다.

우리는 특정 값 X를 찾고자 합니다. 현재 배열의 인덱스 0에 위치한 값이 아닌, 어느 위치에서든 X가 존재할 수 있습니다.

배열 A는 오른쪽(양의 방향)으로 한 칸씩 회전하는 과정을 반복합니다. 즉, 원소 $A[i]$는 다음 단계에서 $A[(i+1) mod N]$로 이동하게 됩니다. (만약 배열이 왼쪽/역방향으로 회전한다면 $A[(i-1) mod N]$가 되지만, 여기서는 오른쪽으로 회전합니다.)

최초 상태의 배열 A와 목표 값 X가 주어졌을 때, X를 처음 발견하는 시점까지 몇 번의 회전이 필요한지 구하세요. 만약 X가 배열에 존재하지 않는다면 -1을 출력해야 합니다.

## 입력

첫째 줄에 정수 N과 정수 X가 공백으로 구분되어 주어집니다. (N: 배열 크기, X: 찾고자 하는 값)
둘째 줄에는 N개의 정수가 공백으로 구분되어 주어진 초기 배열 A의 원소들입니다.

## 출력

X를 처음 발견하는 회전 횟수를 출력합니다. X가 존재하지 않으면 -1을 출력합니다.

## 제약 조건

N: $2 	ext{부터 } 10^5$까지의 정수
X, $A[i]$: $-10^9$부터 $10^9$까지의 정수

## 예제 1

**입력**
```
5 3
1 2 3 4 5
```

**출력**
```
2
```

*초기 배열: [1, 2, 3, 4, 5]. 목표 X=3. 0회전 후 3은 인덱스 2에 있음.
1회전 후: [5, 1, 2, 3, 4]. 3이 발견됨 (인덱스 3).
2회전 후: [4, 5, 1, 2, 3]. 3이 발견됨 (인덱스 4). 
(문제 설명 오해 방지를 위해 '처음 발견하는 시점'을 'X가 인덱스 0에 오기까지의 회전 횟수'로 재정의합니다. 이 경우 1회전에 2, 2회전에 3이 인덱스 0에 옵니다.)
[실제 문제 의도 변경: X를 발견하는 시점 = 배열 전체에서 가장 왼쪽(인덱스 0)으로 이동할 때까지 필요한 최소 회전 횟수]
정확한 해석: 'X가 처음 나타나는 순간의 회전 횟수'는 인덱스가 아닌, 시간 경과를 의미합니다. A[i]에 있던 원소가 t번 회전 후 어느 위치로 가는지 추적하는 것이 핵심입니다.

**재해석 기반 예제:** X=3은 초기 인덱스 2에 있음. 매 단계마다 배열 전체가 오른쪽으로 움직인다고 가정하면, A[i]는 다음 단계에서 $A[(i+1) mod N]$로 이동합니다. 즉, 원소가 왼쪽(역방향 시계 방향)으로 한 칸씩 움직이는 것이 아니라, **배열 전체가 오른쪽으로 회전**하는 것입니다. (예: [1, 2, 3] -> [3, 1, 2])
초기: [1, 2, 3]. X=2. 
0회전: [1, 2, 3] (X 인덱스 1)
1회전: [3, 1, 2] (X 인덱스 2). -> 발견됨.
출력은 '몇 회전'인지? 즉, 1.*

## 예제 2

**입력**
```
4 1
5 1 2 3
```

**출력**
```
1
```

*초기: [5, 1, 2, 3]. X=1. 0회전 후 인덱스 1.
1회전 후: [3, 5, 1, 2]. X=1이 발견됨 (인덱스 2). 
(※ 문제 조건에 따라 'X를 처음 발견하는 시점'을 최소 회전 횟수로 해석하여, 가장 빨리 인덱스가 변하는 순간을 추적합니다. 이 예제에서는 0회전을 제외하고 첫 번째로 X가 포함된 상태를 반환합니다.)
[실제 출제 의도 반영]: 배열 전체가 오른쪽으로 한 칸씩 순환 이동할 때까지의 최소 회전 횟수.*

## 힌트

- 배열의 원소 위치 변화 패턴을 정확히 이해해야 합니다.
- N이 크므로 시뮬레이션은 O(1) 또는 O(log N)에 가까워야 합니다. 하지만 이 문제는 시간 복잡도보다는 논리적 추적이 중요합니다.


## 알고리즘 요약

회전하는 배열에서 특정 요소 X를 찾는 문제는, 원소의 위치 변화를 수학적으로 모델링하여 접근할 수 있습니다. 초기 인덱스 $i$에 있던 원소는 $k$번 회전 후 $(i - k) mod N$ 위치로 이동합니다 (배열이 오른쪽으로 순환). 따라서 X가 가장 먼저 발견되는 시점(최소 $k$)을 찾기 위해, 모든 가능한 초기 위치 $i$를 검사하고, $A[i] = X$인 경우 그 회전 횟수를 계산해야 합니다. 하지만 여기서는 '처음 발견하는' 순간이 중요하므로, 실제로 원소의 이동 경로를 시뮬레이션하며 가장 적은 $k$를 찾는 것이 효율적입니다.

## 풀이 해설

풀이 해설: 이 문제는 배열 전체가 오른쪽(시계 방향)으로 순환 이동할 때 X가 언제 처음 보이는지를 묻습니다. 즉, 매 단계마다 배열의 맨 앞 원소가 맨 뒤로 가고, 나머지 원소들이 앞으로 한 칸씩 당겨지는 과정입니다.

**1. 회전 메커니즘 이해:**
원래 배열 $A = [A_0, A_1, \dots, A_{N-1}]$가 1회전하면, 새로운 배열 $A' = [A_{N-1}, A_0, A_1, \dots, A_{N-2}]$가 됩니다.
즉, 초기 인덱스 $i$에 있던 원소는 $k$번 회전 후 $(i - k) mod N$ 위치로 이동합니다. (단, JavaScript의 `%` 연산자는 음수에 대해 부호가 붙을 수 있으므로, 실제로는 $((i - k) % N + N) % N$를 사용해야 합니다.)

**2. 목표 설정:**
우리는 X를 처음 발견하는 회전 횟수 $k 	ext{ (단, } k 	ext{는 } 0 	ext{부터 시작)}$를 찾아야 합니다.

**3. 최적화 전략:**
X가 배열에 존재하지 않으면 $-1$을 반환해야 하므로, 먼저 X가 존재하는지 확인합니다.
만약 $A[i] = X$인 초기 인덱스 $i$가 있다면, 이 원소는 0회전 시 이미 발견된 것일 수 있습니다. 하지만 문제의 의도가 '어떤 회전이 필요한가'라면, 우리는 모든 가능한 $k 	ext{ ( } 1 	ext{부터 } N-1)$에 대해 X가 인덱스 0 또는 특정 위치에 오는지 확인해야 합니다.

**4. 핵심 로직 (시뮬레이션):**
최소 회전 횟수를 찾기 위해, 우리는 현재 배열 $A_{current}$를 유지하며 매 단계마다 `A_current[0]`을 체크하고 업데이트합니다.
- 초기 상태 (k=0): X가 존재하는지 확인합니다. 만약 존재한다면, 이 값이 답이 될 수 있습니다. 하지만 문제의 난이도와 맥락상, $k 	ext{번째 회전 후 } X$를 찾는 것이 일반적입니다. **가장 보수적인 해석은 'X가 인덱스 0으로 이동하는 최소 횟수' 또는 '최초로 배열에 등장하는 순간의 횟수' 중 하나**입니다.
- 여기서는 가장 간단하고 명확한 '배열 전체를 오른쪽(시계) 방향으로 회전시키는 시뮬레이션'을 통해, X가 포함된 상태가 처음 나타나는 $k$를 반환합니다. (이때 k=0도 횟수로 인정합니다.)

**단계별 구현:**
1. 배열 A와 목표 값 X를 준비합니다.
2. 카운터 `revolutions`를 0으로 초기화하고, 현재 배열 $A_{current}$를 복사하여 사용합니다.
3. 루프를 돌면서 (최대 N번): 
    a. $A_{current}$에 X가 포함되어 있는지 확인합니다. 만약 포함되어 있다면, `revolutions` 값을 반환하고 종료합니다.
    b. $A_{current}$를 한 칸 오른쪽으로 회전시킵니다. 즉, 마지막 원소를 맨 앞으로 옮기고 나머지를 뒤로 한 칸씩 밀어냅니다.
    c. `revolutions`를 1 증가시킵니다.
4. 루프가 N번 다 돌았는데도 X를 찾지 못했다면, X는 존재하지 않는 것이므로 -1을 반환합니다. (참고: X가 존재하는 경우, 최대 N-1회전 내에 반드시 발견됩니다.)

**시간 복잡도:** 배열 크기 $N$이 주어지고, 각 회전마다 배열 전체를 순회해야 하므로 시간 복잡도는 $O(N^2)$입니다. 하지만 JavaScript의 슬라이싱/배열 조작을 통해 효율적으로 구현한다면 여전히 $O(N^2)$에 가깝습니다. 만약 더 높은 성능이 요구된다면, 원소의 위치 변화를 수학적으로 추적해야 하나, 이 문제는 시뮬레이션으로 충분히 해결 가능합니다.

## 참고 코드 (javascript)

```javascript
/**
 * @param {number} N - 배열 크기
 * @param {number} X - 찾고자 하는 값
 * @param {number[]} A - 초기 배열
 * @returns {number} 가장 먼저 발견하는 회전 횟수 (0부터 시작)
 */
const findRotationCount = (N, X, A) => {
    // 1. X가 애초에 존재하는지 먼저 확인합니다.
    if (!A.includes(X)) {
        return -1;
    }

    let currentArray = [...A];
    let revolutions = 0;

    // 최대 N-1회전까지 시뮬레이션 (N번의 상태 변화)
    while (revolutions < N) {
        // 현재 배열에 X가 존재하는지 확인합니다.
        if (currentArray.includes(X)) {
            return revolutions;
        }

        // 오른쪽으로 1회전 시뮬레이션: [A0, A1, ..., AN-1] -> [AN-1, A0, ..., AN-2]
        // 마지막 원소 (currentArray[N-1])를 추출합니다.
        const lastElement = currentArray[N - 1];
        
        // 나머지 배열을 슬라이스로 가져옵니다. (A0부터 AN-2까지)
        const remainingElements = currentArray.slice(0, N - 1);

        // 새로운 배열: [마지막 원소, ...나머지 원소]
        currentArray = [lastElement, ...remainingElements];
        
        revolutions++;
    }

    // 이론적으로 X가 존재한다면 이 부분에 도달하지 않아야 하지만 안전 장치로 -1을 반환합니다.
    return -1;
};

// === 입출력 처리 예시 (실제 코딩테스트 환경 가정) ===

function solve() {
    const fs = require('fs');
    // 표준 입력 전체를 읽어옵니다. 실제 제출 시 환경에 맞게 수정 필요.
    const input = fs.readFileSync(0, 'utf8').trim().split('\n');

    if (input.length < 2) return;

    // 첫 줄: N과 X
    const [N_str, X_str] = input[0].trim().split(' ').map(s => s.trim());
    const N = parseInt(N_str);
    const X = parseInt(X_str);

    // 둘째 줄: 배열 A
    const A = input[1].trim().split(' ').map(Number);

    const result = findRotationCount(N, X, A);
    console.log(result);
}
```
