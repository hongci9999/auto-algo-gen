# 회전하는 배열에서 특정 원소 찾기
*java · 이진 탐색/시뮬레이션 · 보통 · 배열, 이진탐색, 분할정복*

## 입출력 환경

Java에서는 BufferedReader와 StringTokenizer를 사용하여 입력을 받는 것이 효율적이다.

## 문제

N개의 정수 원소로 이루어진 배열 A가 있습니다. 이 배열은 일정한 규칙에 따라 회전합니다. 즉, 처음부터 i번째 위치의 원소가 (i+k) % N 번째 위치로 이동하는 것이 아니라, 전체 배열이 한 방향으로 연속적으로 회전하여 마치 순환 리스트처럼 동작한다고 가정할 수 있습니다.

현재 배열 A는 이미 `[A[0], A[1], ..., A[N-1]]` 형태로 저장되어 있지만, 실제로는 이 배열의 원소들이 논리적으로 회전된 상태입니다. 즉, 만약 원래 순서가 S라는 배열이었다면, 현재 배열은 S를 몇 칸 회전시킨 형태일 수 있습니다.

문제는 '원래' 배열 S에 특정 값 X가 있는지 확인하는 것이 아니라, **현재 A의 원소들 중에서** 주어진 값 X가 존재하는지 여부를 효율적으로 찾는 것입니다. 다만, 단순히 순차 탐색을 하는 것은 비효율적입니다. 이진 탐색과 유사한 아이디어를 사용하여 O(log N) 시간 복잡도로 해결해야 합니다.

배열 A는 다음과 같은 성질을 가집니다:
1. 배열 A는 정렬되어 있습니다 (오름차순).
2. 배열 A는 한 지점을 기준으로 회전되었습니다 (Rotated Sorted Array).

## 입력

첫째 줄에 N(배열의 길이)이 주어지고, 다음 줄에 N개의 정수 원소들이 공백으로 구분되어 주어진다.

## 출력

주어진 값 X가 배열 A 안에 존재하면 'YES', 그렇지 않으면 'NO'를 출력한다.

## 제약 조건

N은 1부터 10만 이하의 범위이다. 배열 A의 원소들은 -10^9에서 10^9 사이의 값을 가질 수 있다. 검색할 값 X 역시 같은 범위를 가진다. 시간 복잡도는 O(log N)으로 제한된다.

## 예제 1

**입력**
```
7
1 2 3 4 5 6 7
```

**출력**
```
YES
```

*회전하지 않은 일반적인 정렬 배열이며, X=4가 존재한다.*

## 예제 2

**입력**
```
9
10 20 30 40 50 60 70 80 90
```

**출력**
```
NO
```

*X=95를 검색했으나, 배열에 존재하지 않는다.*

## 예제 3

**입력**
```
7
30 40 50 10 20 30 40
```

**출력**
```
YES
```

*배열이 회전되어 있으며(회전점: 50->10), X=20가 존재한다.*

## 힌트

- 일반적인 이진 탐색을 적용하면 안 됩니다. 배열의 '회전'이라는 특성을 이용해야 합니다.
- 탐색 범위의 중간 지점을 확인하여, 어느 절반이 정렬된 상태를 유지하는지 파악하고 해당 방향으로 재귀적으로 탐색합니다.


## 알고리즘 요약

Rotated Sorted Array Search (회전된 정렬 배열 검색): 일반적인 이진 탐색을 변형하여 사용한다. 중간 원소(mid)와 시작/끝 원소를 비교하여, [start...mid] 구간 또는 [mid...end] 구간 중 어느 쪽이 오름차순을 유지하는지 판별하고, 목표 값 X가 해당 정렬된 구간에 속하는지 확인한 후 검색 범위를 좁혀나간다. 시간 복잡도는 O(log N)이다.

## 풀이 해설

1. **문제 이해 및 목표 설정**: 이 문제는 일반적인 정렬 배열이 아닌, 한 지점에서 끊어져 회전된(Rotated Sorted Array) 형태의 배열에서 특정 원소 X를 찾는 문제입니다.
2. **기본 아이디어 (Binary Search 변형)**: 시간 복잡도를 O(log N)으로 유지하기 위해 이진 탐색을 사용해야 합니다. 일반적인 이진 탐색은 `A[low] <= A[mid]` 이고 `A[mid] <= A[high]` 일 때만 작동합니다.
3. **회전점 활용 (절반 판별)**: 중간 원소(`mid`)를 기준으로, 현재 검색 구간이 왼쪽 절반(`low`부터 `mid`)에서 정렬되어 있는지, 오른쪽 절반(`mid`부터 `high`)에서 정렬되어 있는지를 판별해야 합니다.
    * **Case 1: 왼쪽 절반이 정렬된 경우**: 만약 `A[low] <= A[mid]` 이면, [low...mid] 구간은 오름차순입니다. 따라서 X가 [A[low], A[mid]] 범위 내에 있는지 확인합니다. 만약 있다면 오른쪽 탐색을 좁히고, 없다면 (회전점이 오른쪽에 있을 확률이 높으므로) 검색 범위를 `low = mid + 1`로 옮깁니다.
    * **Case 2: 오른쪽 절반이 정렬된 경우**: 그렇지 않다면 (`A[low] > A[mid]`), [mid...high] 구간은 오름차순입니다. X가 [A[mid], A[high]] 범위 내에 있는지 확인합니다. 만약 있다면 왼쪽 탐색을 좁히고, 없다면 검색 범위를 `high = mid - 1`로 옮깁니다.
4. **반복 및 종료**: 이 과정을 low > high 가 될 때까지 반복하며, 모든 경우를 처리할 수 있습니다.
5. **시간 복잡도**: 매 단계마다 탐색 범위가 절반씩 줄어들기 때문에 시간 복잡도는 O(log N)입니다.

public class Solution {
    // 재귀를 사용한 이진 탐색 구현
    private static boolean search(int[] nums, int low, int high, int target) {
        if (low > high) {
            return false;
        }

        while (low <= high) {
            int mid = low + (high - low) / 2;

            // 1. 목표 값과 중간 값이 일치하는지 확인
            if (nums[mid] == target) {
                return true;
            }

            // 2. 어느 절반이 정렬되어 있는지 판단
            // Case A: 왼쪽 절반(low ~ mid)이 오름차순인 경우
            if (nums[low] <= nums[mid]) {
                // 목표 값이 이 정렬된 범위 [nums[low], nums[mid]] 안에 있다면?
                if (target >= nums[low] && target <= nums[mid]) {
                    // 왼쪽 절반에서 검색을 계속한다.
                    high = mid - 1;
                } else {
                    // 목표 값이 이 정렬된 범위를 벗어났다면, 오른쪽 절반에 있을 수밖에 없다.
                    low = mid + 1;
                }

                }
            }
        }
        return false;
    }
