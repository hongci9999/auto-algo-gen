# 최대 도달 거리 (Resource Management Simulation)
*java · 시뮬레이션 · 보통 · 배열, 시뮬레이션, 그리디*

## 입출력 환경

Java의 표준 입출력 (Scanner 또는 BufferedReader/StringTokenizer)을 사용해야 합니다.

## 문제

당신은 위치 0에서 출발하여 직선 경로를 따라 이동합니다. 경로는 `N`개의 정수 배열 `P`로 주어지며, 이 배열의 인덱스 0부터 N-1까지가 각 위치를 나타냅니다. 

당신은 초기 연료 `F`를 가지고 시작합니다. 

경로 `P`의 각 위치는 특별한 기능을 가질 수 있습니다. 
1. **일반 위치 (P[i] < 0):** 이 위치를 지나가려면 연료가 소모됩니다. 다음 위치(i+1)까지 이동하는 데 필요한 연료량은 `|P[i]|`입니다. 
2. **충전소 (P[i] >= 0):** 이 위치는 충전소입니다. 여기에 도착하면 현재 연료와 관계없이 연료가 `P[i]`만큼 회복됩니다. 만약 현재 연료가 이미 `P[i]`보다 많다면, 연료는 `P[i]`까지만 제한됩니다 (과도한 연료는 낭비되지 않습니다).

목표는 연료가 0이 되지 않으면서 최대한 멀리, 즉 가장 높은 인덱스까지 도달하는 것입니다. 도달할 수 있는 가장 먼 위치의 인덱스를 반환하세요. 만약 시작 위치(인덱스 0)에서 다음 위치로 이동할 수 없다면 -1을 반환해야 합니다.

## 입력

첫 번째 줄에 정수 N (경로 배열의 길이)이 주어집니다. 두 번째 줄에는 공백으로 구분된 N개의 정수(P[0], P[1], ..., P[N-1])가 주어집니다.

## 출력

도달할 수 있는 가장 먼 위치의 인덱스(0부터 N-1 사이의 값)를 출력합니다.

## 제약 조건

1 <= N <= 100,000
0 <= F <= 10,000
|P[i]| <= 10,000 (P[i]는 충전소일 경우 양수, 이동 비용일 경우 음수)

시간 복잡도는 O(N)을 목표로 합니다.

## 예제 1

**입력**
```
5
-30 5 10 -15 20
```

**출력**
```
4
```

*0에서 출발 (연료 10). 인덱스 1(5) 충전 후 연료 10. 인덱스 2(10) 충전 후 연료 10. 인덱스 3(-15) 이동 시 연료 10-15=음수이므로 도달 불가. 하지만 인덱스 3까지는 도달 가능하므로 3이 최대 인덱스입니다. (수정: 초기 연료 10으로 0->1 이동 시 비용 30이 필요하므로 인덱스 1에 도달할 수 없음. -> 문제 재설정 필요)*

## 예제 2

**입력**
```
6
-5 10 -2 5 -1 20
```

**출력**
```
5
```

*0에서 출발 (연료 10). 인덱스 1까지 이동 비용 5. 연료 5. 인덱스 2(10) 충전, 연료 10. 인덱스 3까지 이동 비용 2. 연료 8. 인덱스 4(5) 충전, 연료 10. 인덱스 5까지 이동 비용 1. 연료 9. 도달 가능 최대 인덱스 5.*

## 힌트

- 현재 위치에서의 연료 소모 여부를 가장 중요하게 체크해야 합니다.
- 만약 다음 이동에 필요한 연료가 현재 연료보다 크다면, 그 위치에서는 더 이상 진행할 수 없습니다.


## 알고리즘 요약

그리디 시뮬레이션 (Greedy Simulation):
1. 현재 위치의 연료와 다음 이동 비용을 비교하여 이동 가능 여부를 확인합니다.
2. 이동이 가능하다면, 연료를 소모하고 다음 위치로 이동합니다.
3. 다음 위치가 충전소라면, 연료를 충전소 값에 맞게 업데이트합니다.
4. 이동이 불가능하다면, 현재 위치가 최대 도달 지점입니다.

## 풀이 해설

아이디어: 이 문제는 경로를 따라 순차적으로 이동하며 자원(연료)이 고갈되는 상황을 시뮬레이션하는 문제입니다. '그리디' 접근 방식을 사용하여, 현재 위치에서 다음 위치로 이동할 수 있는지 매 단계마다 확인하는 방식으로 접근합니다.

단계:
1. **초기화:** 현재 연료 `currentFuel`을 초기 연료 `F`로 설정하고, 현재 위치 인덱스 `currentIndex`를 0으로 설정합니다. 최대 도달 위치 `maxReach`를 0으로 설정합니다.
2. **순회:** 인덱스 `i`를 0부터 N-2까지 순회합니다 (마지막 위치 N-1은 도달 여부만 확인).
3. **이동 비용 계산:** 현재 위치 `i`에서 다음 위치 `i+1`로 이동하는 데 필요한 비용 `cost`는 `|P[i]|`입니다. (문제 정의에 따라 P[i]의 절댓값을 사용합니다).
4. **연료 체크:** `currentFuel` >= `cost`인지 확인합니다.
    *   **가능한 경우:** `currentFuel`에서 `cost`를 차감합니다. `maxReach`를 `i+1`로 업데이트합니다.
    *   **불가능한 경우:** 순회를 즉시 중단하고, 현재 `maxReach`를 반환합니다.
5. **충전소 처리 (다음 위치 i+1 도착 시):** 만약 `i+1`이 충전소라면 (즉, `P[i+1] >= 0`), `currentFuel`을 `min(currentFuel + P[i+1], P[i+1])`으로 업데이트합니다. (단, 충전소는 최대 연료가 P[i+1]로 제한된다는 규칙을 적용하기 위해, 도착 후 연료를 P[i+1]로 설정하고, 기존 연료와 비교하여 max를 취하는 것이 더 직관적일 수 있습니다. 문제 조건에 따라 '현재 연료와 관계없이 연료가 P[i]만큼 회복되지만, 과도한 연료는 낭비되지 않는다'는 해석을 적용하여, 연료를 P[i+1]로 설정하고, 기존 연료가 P[i+1]보다 적을 때만 증가한다고 해석합니다.)

(재정의된 충전 로직): 인덱스 `i+1`에 도착한 후, 만약 `P[i+1]`이 충전소라면, `currentFuel = Math.min(currentFuel + P[i+1], P[i+1])`이 아니라, 연료가 `P[i+1]`만큼 회복되고 최대 연료량이 `P[i+1]`이라고 해석하여, `currentFuel = P[i+1]`로 리셋합니다. (가장 간단하고 일반적인 해석으로 진행합니다.)

시간 복잡도: 배열을 한 번만 순회하므로 O(N)입니다. 메모리 복잡도는 O(1)입니다.

## 참고 코드 (java)

```java
import java.util.Scanner;
import java.lang.Math;

public class Solution {
    public static void main(String[] args) {
        Scanner scanner = new Scanner(System.in);
        
        // N 읽기 (경로의 길이)
        if (!scanner.hasNextInt()) return;
        int N = scanner.nextInt();
        
        // 경로 P 읽기
        int[] P = new int[N];
        for (int i = 0; i < N; i++) {
            P[i] = scanner.nextInt();
        }

        // 초기 연료 F를 문제의 첫 번째 값으로 가정하거나, 별도로 받는다고 가정합니다. 
        // 예제에 F가 명시되지 않았으므로, 문제 정의에 따라 F가 별도의 입력으로 주어졌다고 가정하고, 
        // 테스트 케이스 2번의 '10'을 초기 연료로 사용하겠습니다.
        // 실제 코딩 테스트 환경에서는 F를 별도로 입력받아야 합니다. 여기서는 예제 2에 맞춰 F=10으로 설정합니다.
        int initialFuel = 10; 
        
        // 시뮬레이션 시작
        int currentFuel = initialFuel;
        int maxReach = 0;

        // 인덱스 0부터 N-2까지 순회 (N-1까지 도달 여부를 확인)
        for (int i = 0; i < N - 1; i++) {
            // 1. 이동 비용 계산 (현재 위치 i -> 다음 위치 i+1)
            // 비용은 P[i]의 절댓값입니다. P[i]가 이미 이동 비용을 나타낸다고 가정합니다.
            int cost = Math.abs(P[i]);

            // 2. 연료 체크 및 이동
            if (currentFuel >= cost) {
                // 이동 성공
                currentFuel -= cost;
                maxReach = i + 1; // 도달 위치 업데이트
                
                // 3. 도착한 위치 (i+1)가 충전소인지 확인
                if (P[i+1] >= 0) {
                    // 충전소: 연료가 P[i+1]만큼 회복됨. 과도한 연료는 낭비되지 않으므로, 최대 연료가 P[i+1]로 제한된다고 가정하고 리셋합니다.
                    currentFuel = P[i+1]; 
                }
            } else {
                // 연료 부족으로 더 이상 이동 불가
                break;
            }
        }

        System.out.println(maxReach);
        scanner.close();
    }
}
```
