# 최소 비용 연결 마을
*java · 그래프 · 보통 · MST, Union-Find*

## 입출력 환경

Java에서 입출력 시 BufferedReader와 StringTokenizer를 사용하여 성능을 확보하는 것이 좋습니다.

## 문제

N개의 마을이 있습니다. 이 마을들은 간선들로 연결되어 있으며, 각 간선은 두 마을을 잇고 비용(가중치)을 가집니다.
우리는 모든 마을을 최소의 비용으로 연결하는 방법(트리 구조)을 찾아야 합니다. 즉, 모든 마을을 방문할 수 있도록 하는 최소 신장 트리(Minimum Spanning Tree, MST)를 구성해야 합니다. 이 때, 간선의 방향은 중요하지 않습니다.

이 문제에서는 크루스칼 알고리즘(Kruskal's Algorithm)을 사용하여 문제를 해결하는 것을 목표로 합니다.

## 입력

첫째 줄에 마을의 개수 N과 간선의 총 개수 M이 주어집니다. (N, M <= 10^5)
다음 M개의 줄에 걸쳐 간선 정보가 순서대로 주어집니다. 각 줄은 '시작 마을 끝 마을 비용' 형식으로 되어 있습니다.
(마을 번호는 1부터 N까지입니다.)

## 출력

모든 마을을 연결하는 최소 비용의 총합을 출력합니다.

## 제약 조건

N, M <= 10^5. 간선의 비용은 양수 정수이며, 최대 10^9 이하입니다. 시간 복잡도는 O(M log M) 또는 O(M * α(N)) 수준이 되어야 합니다.

## 예제 1

**입력**
```
3 3
1 2 10
2 3 5
1 3 8
```

**출력**
```
15
```

*간선 비용은 (1, 2)와 (2, 3)을 선택하여 총합 15를 만듭니다. (사이클 발생 간선 제외)*

## 예제 2

**입력**
```
4 5
1 2 3
1 3 5
2 3 7
2 4 8
3 4 6
```

**출력**
```
19
```

*가장 비용이 적은 간선들을 선택하여 모든 마을을 연결합니다. (예: (1,2), (1,3), (2,4) 등)*

## 힌트

- 간선의 가중치(비용)를 기준으로 오름차순 정렬하는 것이 중요합니다.
- Union-Find 자료구조를 사용하여 이미 같은 컴포넌트에 속한 마을을 다시 연결하려는 상황(사이클)을 감지해야 합니다.


## 알고리즘 요약

크루스칼 알고리즘 (Kruskal's Algorithm). 1. 모든 간선을 비용이 낮은 순서대로 정렬합니다. 2. 정렬된 간선들을 하나씩 탐색하며, 두 마을이 아직 같은 연결 컴포넌트에 속해 있는지 Union-Find 구조를 통해 확인합니다. 3. 만약 두 마을이 다른 컴포넌트에 속해 있다면(사이클을 형성하지 않는다면), 해당 간선을 MST에 포함시키고 두 마을의 부모 노드를 합칩니다 (Union). 4. 이 과정을 모든 간선에 대해 반복하여 비용의 총합을 구합니다.

## 풀이 해설

풀이 아이디어: 주어진 N개의 마을과 M개의 간선 정보가 있을 때, 최소 비용으로 모든 마을을 연결하는 방법은 최소 신장 트리(MST) 문제입니다. 이 문제를 해결하기 위해 크루스칼 알고리즘을 사용합니다.

단계:
1. **간선 구조체 정의 및 정렬**: 모든 간선 정보를 (비용, 시작점, 끝점) 튜플로 저장하고, 비용을 기준으로 오름차순으로 정렬합니다. 가장 적은 비용의 간선부터 검사하는 것이 핵심입니다.
2. **Union-Find 초기화**: N개의 마을 각각에 대해 독립적인 집합(컴포넌트)으로 Union-Find 구조를 초기화합니다. 이 구조는 각 마을이 현재 어떤 연결 그룹에 속해 있는지를 효율적으로 관리하게 해줍니다.
3. **탐색 및 MST 구성**: 정렬된 간선들을 처음부터 끝까지 순회하며 다음을 수행합니다:
    a. **사이클 검사 (Find)**: 현재 간선의 시작점과 끝점이 이미 같은 집합에 속해 있는지 `find` 연산을 통해 확인합니다. 만약 같다면, 이 간선을 사용하면 사이클이 발생하므로 건너<0xEB><0x9C><0x81>니다.
    b. **MST 포함 및 합치기 (Union)**: 두 점이 다른 집합에 속해 있다면(사이클을 형성하지 않는다면), 이 간선은 MST에 포함되어야 합니다. 따라서 총 비용에 해당 간선의 비용을 더하고, `union` 연산을 통해 두 마을의 집합을 하나로 합칩니다.
4. **결과 반환**: 모든 간선을 검사한 후 누적된 총 비용이 최소 연결 비용입니다.

시간 복잡도: 가장 많은 시간을 차지하는 부분은 M개의 간선을 정렬하는 과정(O(M log M))입니다. Union-Find 연산의 시간 복잡도는 사실상 상수 시간($	ext{O}(	ext{a}(N))$)에 가까우므로, 전체 시간 복잡도는 O(M log M)이 됩니다.

## 참고 코드 (java)

```java
import java.util.*;

// 간선 정보를 저장하는 클래스
class Edge implements Comparable<Edge> {
    int u, v; // 시작점과 끝점 (1-based)
    long weight; // 비용

    public Edge(int u, int v, long weight) {
        this.u = u;
        this.v = v;
        this.weight = weight;
    }

    // 오름차순 정렬을 위한 비교 메서드 (비용 기준)
    @Override
    public int compareTo(Edge other) {
        return Long.compare(this.weight, other.weight);
    }
}

// Union-Find 자료구조
class DSU { 
    private int[] parent;
    
    // 크기 기반 최적화를 위한 배열 (선택 사항)
    private int[] rank; 

    public DSU(int n) {
        parent = new int[n + 1]; // 1부터 N까지 사용
        rank = new int[n + 1];
        for (int i = 1; i <= n; i++) {
            parent[i] = i;
            rank[i] = 0;
        }
    }

    // 최적화된 Find 연산 (경로 압축)
    public int find(int i) {
        if (parent[i] == i) {
            return i;
        } else {
            parent[i] = find(parent[i]); // 경로 압축
        }
        return parent[i];
    }

    // Union 연산 (랭크 기반 병합)
    public boolean union(int i, int j) {
        int rootI = find(i);
        int rootJ = find(j);

        if (rootI != rootJ) {
            // 랭크가 낮은 쪽을 높은 쪽의 자식으로 붙임
            if (rank[rootI] < rank[rootJ]) {
                parent[rootI] = rootJ;
            } else if (rank[rootI] > rank[rootJ]) {
                parent[rootJ] = rootI;
            } else {
                // 랭크가 같으면, 한쪽의 부모를 다른 쪽으로 하고 랭크 증가
                parent[rootJ] = rootI;
                rank[rootI]++;
            }
            return true; // 성공적으로 합쳐짐 (사이클 아님)
        } else {
            return false; // 이미 같은 집합에 속함 (사이클 발생)
        }
    }
}
```
