# 최대 판매 수익 계산
*java · DP · 보통 · DP, 배열*

## 입출력 환경

Java에서 표준 입출력(Scanner 또는 BufferedReader)을 사용합니다.

## 문제

어떤 회사가 여러 제품 A, B, C를 판매합니다. 각 제품은 판매에 필요한 재료와 판매 가격을 가지고 있습니다. 이 회사는 최대 3개의 제품을 선택하여 판매할 수 있습니다. 하지만, 선택한 제품들 간에는 상호 배타적인 관계가 존재합니다. 만약 제품 A와 제품 B를 동시에 선택한다면, 두 제품의 판매에 필요한 재료가 부족하여 판매할 수 없습니다. 제품 A와 제품 C는 함께 판매 가능하지만, B와 C는 판매가 불가능합니다.

만약 주어진 제품 목록에서, 최대 3개의 제품을 선택하여 판매할 수 있는 최대 수익을 구하세요. (다만, 같은 종류의 제품을 여러 개 선택할 수는 없습니다.)

## 입력

첫째 줄에는 제품의 총 개수 N이 주어집니다. (1 <= N <= 10)
다음 N줄에는 각 제품의 판매 가격(int)과 해당 제품의 고유 ID(int)가 순서대로 주어집니다. 제품 ID는 1부터 N까지의 번호로 가정합니다. (여기서는 N이 최대 10이므로, ID는 1부터 N까지로 간주하고, 제품 A, B, C의 세 그룹을 임의로 분류하여 사용합니다.)

[가정] 문제의 제약 조건에 따라, 모든 제품은 다음 세 그룹 중 하나에 속한다고 가정하고, 그룹별로 판매 가능 여부를 판단합니다.
- 그룹 A: ID가 1, 2, 3인 제품들
- 그룹 B: ID가 4, 5, 6인 제품들
- 그룹 C: ID가 7, 8, 9인 제품들

실제 입력은 N개의 제품 목록만 주어지며, 이 목록을 바탕으로 그룹 A, B, C에 해당하는 제품들을 추출하여 판매 가능한 조합을 계산합니다.

## 출력

최대 판매 수익을 하나의 정수 값으로 출력합니다.

## 제약 조건

N: 1 <= N <= 10
판매 가격: 1 <= price <= 1000
(실제 제약 조건은 N이 작으므로 모든 조합을 탐색하는 것이 가능합니다.)

## 예제 1

**입력**
```
10
100 1
150 2
200 3
50 4
120 5
70 6
300 7
80 8
20 9
10 10
```

**출력**
```
650
```

*A(100+150+200)=450, B(50+120+70)=240, C(300+80+20)=400. 조합 A+C가 최대 (450+400=850)가 되어야 하지만, 문제 조건 상 A와 C는 가능하고 B는 나머지 제품이므로, A+C+B가 최대가 될 수 없습니다. A+C 조합이 최대 (850)입니다. (실제 예시에서는 A, B, C 그룹으로 나누고, A+C 조합만 고려합니다.)*

## 예제 2

**입력**
```
9
10 1
20 2
30 3
5 4
15 5
50 6
100 7
200 8
10 9
```

**출력**
```
450
```

*A+C 조합만 고려 가능합니다. A의 합: 60. C의 합: 310. 총합 370. (만약 A+B+C가 모두 가능한 경우라면 370+240=610이 될 수 있으나, 문제 조건에 따라 A+C만 선택합니다.)*

## 힌트

- 제품 그룹(A, B, C)을 먼저 분리하고, 각 그룹의 최대 합을 계산하는 것이 핵심입니다.
- 주어진 제약 조건(A-B 불가, B-C 불가)에 따라 가능한 조합(A+C)만 계산하면 됩니다.


## 알고리즘 요약

주어진 제품 목록에서 ID를 기준으로 세 그룹(A, B, C)으로 제품들을 분류합니다. 각 그룹별로 판매 가격의 합을 계산하여 그룹 A의 총합(SumA), 그룹 B의 총합(SumB), 그룹 C의 총합(SumC)을 구합니다. 문제의 제약 조건에 따라 최대 수익을 낼 수 있는 조합은 A와 C를 함께 선택하는 경우입니다. 따라서 최종 최대 수익은 SumA + SumC가 됩니다.

## 풀이 해설

풀이 과정은 크게 세 단계로 나뉩니다.

1. **데이터 분리 및 그룹화:** 입력받은 N개의 제품 목록을 순회하면서, 각 제품의 ID(1~N)를 기준으로 제품 A (ID 1, 2, 3), 제품 B (ID 4, 5, 6), 제품 C (ID 7, 8, 9)에 해당하는 제품들을 별도의 리스트 또는 변수에 분리합니다.

2. **그룹별 합계 계산:** 분리된 제품들 각각의 판매 가격을 모두 더하여 그룹 A의 총합(SumA), 그룹 B의 총합(SumB), 그룹 C의 총합(SumC)을 계산합니다.

3. **최대 수익 결정:** 문제에서 주어진 판매 제약 조건을 분석합니다. 
- A와 B 동시 선택 불가.
- B와 C 동시 선택 불가.
- A와 C는 함께 선택 가능.

이러한 제약 조건 하에서 최대 수익을 얻을 수 있는 조합은 오직 A와 C를 동시에 판매하는 경우입니다. 따라서 최종 최대 수익은 SumA + SumC가 됩니다. (만약 모든 제품이 하나의 그룹에만 속하거나, ID 범위가 1~3, 4~6, 7~9가 아닌 경우, 문제 조건을 명확히 재정의해야 하지만, 본 문제에서는 주어진 가정에 따라 A+C 조합을 채택합니다.)

**시간 복잡도:** 입력 크기 N이 매우 작기 때문에, N개의 제품을 한 번 순회하여 그룹화하고 합계를 계산하는 과정만 필요합니다. 따라서 시간 복잡도는 O(N)입니다.

## 참고 코드 (java)

```java
import java.util.Scanner;

public class Main {

    public static void main(String[] args) {
        Scanner scanner = new Scanner(System.in);
        
        // 첫째 줄: 제품의 총 개수 N
        if (!scanner.hasNextInt()) return;
        int N = scanner.nextInt();

        // 그룹별 최대 판매 가격 합계를 저장할 변수 초기화
        long sumA = 0;
        long sumB = 0;
        long sumC = 0;

        // N개의 제품 정보를 순회하며 그룹별 합계 계산
        for (int i = 0; i < N; i++) {
            // 판매 가격과 ID를 읽는다.
            if (!scanner.hasNextInt()) break;
            int price = scanner.nextInt();
            int id = scanner.nextInt();

            // ID를 기준으로 그룹 분류 및 합산
            if (id >= 1 && id <= 3) { // 그룹 A: ID 1, 2, 3
                sumA += price;
            } else if (id >= 4 && id <= 6) { // 그룹 B: ID 4, 5, 6
                sumB += price;
            } else if (id >= 7 && id <= 9) { // 그룹 C: ID 7, 8, 9
                sumC += price;
            }
            // ID 10 이상은 문제 가정에 따라 무시하거나, 별도 처리 필요
        }
        
        // 제약 조건에 따라 A와 C를 선택하는 것이 최대 수익을 낸다.
        // (A+B 불가, B+C 불가)
        long maxProfit = sumA + sumC;

        System.out.println(maxProfit);
        scanner.close();
    }
}
```
