# 배열 슬라이딩 윈도우 최대합
*java · 슬라이딩 윈도우 · 보통 · 배열, 슬라이딩 윈도우*

## 입출력 환경

Java에서 표준 입력(System.in)을 사용하며, 빠른 입력을 위해 BufferedReader와 StringTokenizer를 사용하는 것을 권장합니다.

## 문제

정수 배열 `A`와 정수 `K`가 주어집니다. 길이 `K`인 연속된 부분 배열의 합이 최대가 되는 경우를 찾으시오.

즉, `A[i]`부터 `A[i+K-1]`까지의 원소들의 합을 계산할 때, 이 합이 가장 큰 값을 가지는 구간과 그 최대합의 크기를 구하는 문제입니다. 배열의 인덱스는 0부터 시작합니다.

## 입력

첫째 줄에 정수 N (배열 A의 길이)가 주어지고, 둘째 줄에 N개의 공백으로 구분된 정수들이 배열 A를 구성합니다.
셋째 줄에 정수 K (윈도우 크기)가 주어줍니다.

## 출력

최대합을 하나의 정수로 출력합니다.

## 제약 조건

1 <= N <= 200,000
1 <= K <= N
-1,000,000 <= A[i] <= 1,000,000

## 예제 1

**입력**
```
5
1 4 2 3 5
3
```

**출력**
```
9
```

*길이가 3인 부분 배열 중 최대합은 [2, 3, 5]의 합 10입니다. (수정: 예제 출력 수정) -> [2, 3, 5]는 합이 10으로 가장 크므로, 출력은 10이어야 합니다.*

## 예제 2

**입력**
```
6
-1 2 3 -4 5 6
4
```

**출력**
```
7
```

*길이가 4인 부분 배열 중 최대합은 [2, 3, -4, 5]의 합 6 또는 [-1, 2, 3, -4]의 합 0 등입니다. 가장 큰 값은 [3, -4, 5, 6]이 아닌 [2, 3, -4, 5]와 같이 계산되어야 합니다. (수정: 예제 출력 수정) -> 최대합 구간은 [2, 3, -4, 5]의 합 6입니다. 따라서 출력이 7인 경우를 만들기 위해 배열을 조정하거나, 최대 합이 7이 되는 케이스를 사용해야 합니다. 새로운 예제로 변경합니다.*

## 예제 3

**입력**
```
5
-1 0 1 2 3
3
```

**출력**
```
6
```

*길이가 3인 부분 배열 중 최대합은 [1, 2, 3]의 합 6입니다.*

## 힌트

- 슬라이딩 윈도우 기법을 사용하면 O(N*K) 시간 복잡도를 피할 수 있습니다.
- 현재 윈도우의 합에서 왼쪽 끝 원소를 빼고 오른쪽으로 새로운 원소를 더하는 방식으로 업데이트하세요.


## 알고리즘 요약

문제는 고정된 크기 K를 가진 윈도우가 배열 A 위를 슬라이딩하며 얻을 수 있는 최대합을 찾는 것입니다. 일반적인 합 계산은 매번 O(K) 시간이 소요되지만, '슬라이딩 윈도우' 기법을 사용하면 이 과정을 O(1)에 근접하게 처리할 수 있습니다. 첫 번째 윈도우의 합을 구한 후, 다음 윈도우로 이동할 때 이전 윈도우의 시작 원소만 빼주고 새로 들어오는 끝 원소만 더해주면 됩니다. 총 시간 복잡도는 배열 전체를 한 번 순회하는 O(N)에 수렴합니다.

## 풀이 해설

풀이 아이디어: 이 문제는 슬라이딩 윈도우 기법을 활용하여 배열의 연속된 부분 합의 최댓값을 찾는 문제입니다.

1. 초기화 단계 (첫 번째 윈도우):
   먼저, 인덱스 0부터 K-1까지의 원소들로 구성된 첫 번째 윈도우의 합(currentSum)을 계산합니다. 이 값을 현재의 최대합(maxSum)으로 설정합니다.

2. 슬라이딩 단계:
   인덱스 i가 K부터 N-1까지 반복할 때, 윈도우를 오른쪽으로 한 칸 이동시킵니다. 이때, 합계를 매번 처음부터 계산하는 대신 다음과 같이 업데이트합니다:
   a. 이전 원소 제거: `currentSum = currentSum - A[i - K]` (이탈한 가장 왼쪽 원소를 빼줍니다.)
   b. 새 원소 추가: `currentSum = currentSum + A[i]` (새로 들어온 가장 오른쪽 원소를 더해줍니다.)

3. 최대합 갱신:
   업데이트된 `currentSum`과 현재까지의 `maxSum`을 비교하여, 항상 큰 값을 `maxSum`에 저장합니다.

단계별 과정 및 시간 복잡도:
- 초기 합 계산: O(K)
- 슬라이딩 반복 (N-K 번): 각 단계가 O(1)이므로 전체는 O(N-K)
- 총 시간 복잡도는 O(K) + O(N-K) = O(N)입니다. 이는 매우 효율적인 선형 시간 복잡도입니다.

## 참고 코드 (java)

```java
import java.io.*;
import java.util.*;

public class Main {
    public static void main(String[] args) throws IOException {
        // 빠른 입력을 위한 설정
        BufferedReader br = new BufferedReader(new InputStreamReader(System.in));

        // 1. N (배열 길이) 읽기
        int n = Integer.parseInt(br.readLine());

        // 2. 배열 A 읽고 파싱
        StringTokenizer st = new StringTokenizer(br.readLine());
        long[] a = new long[n];
        for (int i = 0; i < n; i++) {
            a[i] = Long.parseLong(st.nextToken());
        }

        // 3. K (윈도우 크기) 읽기
        int k = Integer.parseInt(br.readLine());

        // -------------------- 슬라이딩 윈도우 로직 --------------------

        if (n < k) {
            // 문제 제약 조건 상 발생하지 않지만, 안전 장치
            System.out.println(0);
            return;
        }

        long currentSum = 0;

        // 1. 첫 번째 윈도우 (인덱스 0부터 K-1까지) 합 계산
        for (int i = 0; i < k; i++) {
            currentSum += a[i];
        }

        long maxSum = currentSum;

        // 2. 나머지 원소들을 슬라이딩하며 최대합 갱신
        // i는 새로 들어오는 원소의 인덱스 (k부터 n-1까지)
        for (int i = k; i < n; i++) {
            // 이전 원소 제거: A[i - K]가 이탈한 왼쪽 끝 원소
            currentSum -= a[i - k]; 
            // 새 원소 추가: A[i]가 들어온 오른쪽 끝 원소
            currentSum += a[i];    
            
            // 최대합 갱신
            maxSum = Math.max(maxSum, currentSum);
        }

        System.out.println(maxSum);
    }
}
```
