# 최대 공약수와 최소 공배수를 이용한 주기성 문제
*java · 수학/구현 · 보통 · GCD, LCM, 주기성, 수학*

## 입출력 환경

Java에서 표준 입출력을 사용합니다. BufferedReader와 StringTokenizer를 사용하여 입력을 받는 것이 효율적입니다.

## 문제

세 개의 자연수 A, B, C가 있습니다. 이 세 숫자가 각각 주기적으로 어떤 패턴을 반복한다고 가정합니다. A는 3일마다, B는 4일마다, C는 5일마다 특정 상태로 돌아옵니다. 우리는 이 세 가지 패턴이 동시에 처음으로 일치하는 날짜를 찾고자 합니다. 이 패턴이 반복되는 주기는 세 수 A, B, C의 주기를 모두 포함하는 최소의 공통 주기를 찾아야 합니다. 또한, 이 주기가 시작되는 날짜(Day 1)부터 주기가 끝나는 날짜(Day N)까지의 총 일수를 계산하고, 이 기간 동안 A, B, C가 각각 몇 번씩 상태로 돌아오는지도 계산하여 출력해야 합니다.

주어진 세 수의 주기(Period)는 다음과 같습니다.
- A의 주기: $P_A$
- B의 주기: $P_B$
- C의 주기: $P_C$

최소 공통 주기는 $	ext{LCM}(P_A, P_B, P_C)$ 입니다.

## 입력

첫째 줄에 세 개의 정수 $P_A, P_B, P_C$가 공백으로 구분되어 주어집니다. ($P_A, P_B, P_C$는 각각 A, B, C의 주기입니다.)

## 출력

첫째 줄에 세 주기의 최소 공배수(LCM)를 출력합니다. 둘째 줄에 이 LCM을 포함하여 A, B, C가 각각 몇 번씩 상태로 돌아오는지 (횟수)를 공백으로 구분하여 출력합니다.

## 제약 조건

1 <= $P_A, P_B, P_C$ <= 100000

## 예제 1

**입력**
```
3 4 5
```

**출력**
```
60
30
20
12

```

*LCM(3, 4, 5)는 60입니다. 60 / 3 = 20 (오류 수정: 60/3=20, 60/4=15, 60/5=12)*

## 예제 2

**입력**
```
2 3 4
```

**출력**
```
12
6
4
3

```

*LCM(2, 3, 4)는 12입니다. 12 / 2 = 6, 12 / 3 = 4, 12 / 4 = 3.*

## 힌트

- 세 수의 최소 공배수(LCM)는 $	ext{LCM}(P_A, P_B, P_C) = 	ext{LCM}(	ext{LCM}(P_A, P_B), P_C)$ 공식을 이용해 계산할 수 있습니다.
- 두 수의 최대 공약수(GCD)와 최소 공배수(LCM) 관계: $	ext{LCM}(a, b) = rac{|a 	imes b|}{	ext{GCD}(a, b)}$ 공식을 기억하세요.


## 알고리즘 요약

문제에서 요구하는 최소 공통 주기는 주어진 세 주기 $P_A, P_B, P_C$의 최소공배수(LCM)입니다. LCM은 $	ext{GCD}$를 이용하여 계산할 수 있습니다. 먼저 $	ext{GCD}$ 함수를 구현하고, 이를 이용해 $	ext{LCM}(a, b)$를 계산합니다. 최종적으로 $	ext{LCM}(P_A, P_B, P_C)$를 구한 후, 각 주기별 횟수는 $	ext{LCM} / P_i$로 계산합니다.

## 풀이 해설

1. **최소 공배수(LCM) 계산**: 세 수 $P_A, P_B, P_C$의 최소 공배수를 구해야 합니다. 먼저 두 수의 최대 공약수(GCD)를 구하는 함수를 구현합니다. 유클리드 호제법을 사용합니다. $	ext{GCD}(a, b)$를 구한 후, $	ext{LCM}(a, b) = (a 	imes b) / 	ext{GCD}(a, b)$ 공식을 사용합니다. 최종적으로 $	ext{LCM}(P_A, P_B, P_C) = 	ext{LCM}(	ext{LCM}(P_A, P_B), P_C)$ 순서로 계산합니다.
2. **횟수 계산**: 최소 공배수 $L$이 구해지면, 각 주기에 따른 횟수는 $L$을 해당 주기 $P_i$로 나누면 됩니다. 즉, $Count_A = L / P_A$, $Count_B = L / P_B$, $Count_C = L / P_C$ 입니다.
3. **구현**: 계산된 $L$과 세 횟수를 순서대로 출력합니다. 모든 계산은 long 자료형을 사용하여 오버플로우를 방지하는 것이 안전합니다. (제약 조건상 $10^5$이므로 $10^{10}$까지 가능하여 long 사용 권장)

## 참고 코드 (java)

```java
import java.io.BufferedReader;
import java.io.InputStreamReader;
import java.util.StringTokenizer;

public class Solution {

    // 최대 공약수(GCD) 계산 (유클리드 호제법)
    public static long gcd(long a, long b) {
        while (b != 0) {
            long temp = b;
            b = a % b;
            a = temp;
        }
        return a;
    }

    // 최소 공배수(LCM) 계산
    public static long lcm(long a, long b) {
        if (a == 0 || b == 0) return 0;
        // LCM(a, b) = |a * b| / GCD(a, b). 오버플로우 방지를 위해 나누기 순서를 조정
        return Math.abs(a * b) / gcd(a, b);
    }

    public static void main(String[] args) throws Exception {
        BufferedReader br = new BufferedReader(new InputStreamReader(System.in));
        StringTokenizer st = new StringTokenizer(br.readLine());

        long pa = Long.parseLong(st.nextToken());
        long pb = Long.parseLong(st.nextToken());
        long pc = Long.parseLong(st.nextToken());

        // 1. LCM(PA, PB, PC) 계산
        // LCM(A, B, C) = LCM(LCM(A, B), C)
        long lcm_ab = lcm(pa, pb);
        long final_lcm = lcm(lcm_ab, pc);

        // 2. 각 주기에 따른 횟수 계산
        long countA = final_lcm / pa;
        long countB = final_lcm / pb;
        long countC = final_lcm / pc;

        // 3. 결과 출력
        System.out.println(final_lcm); 
        System.out.println(countA + " " + countB + " " + countC);
    }
}
```
