# 최대 동시 수강 인원
*java · 자료구조 · 보통 · 정렬, Sweep Line*

## 입출력 환경

Java에서 입력을 받을 때는 BufferedReader와 StringTokenizer를 사용하는 것이 효율적입니다. 표준 입력(System.in)으로부터 모든 데이터를 읽어 처리하세요.

## 문제

학교에 N개의 강좌가 있습니다. 각 강좌는 특정 시작 시간과 종료 시간을 가집니다. (시간은 1부터 시작하며, 주어진 구간 [시작, 끝]을 사용합니다.)

만약 한 순간에 동시에 수강해야 하는 최대 인원이 몇 명인지 구하는 문제가 주어졌다고 가정합시다.

즉, 모든 강좌가 진행되는 시간 축 위에서 어느 시점에 가장 많은 강좌가 겹치는지 그 '최대 중첩도'를 구하세요. 이 값이 최소한 필요한 강의실 개수가 됩니다.

(주의: 구간 [시작, 끝]은 시작 시간에 포함되고 종료 시간이 지나야 끝나므로, 끝 시간과 다음 시작 시간이 같은 경우 (예: [1, 3], [3, 5])는 인원이 겹치지 않습니다.)

## 입력

첫 번째 줄에 N이 주어집니다. (N은 강좌의 개수)
다음 N개의 줄에 걸쳐 각 강좌의 시작 시간 $S$와 종료 시간 $E$가 공백으로 구분되어 주어집니다. (S, E는 양의 정수입니다.)

## 출력

필요한 최소 강의실 개수인 최대 중첩도를 하나의 정수로 출력합니다.

## 제약 조건

1 <= N <= 200,000
1 <= S <= E <= 300,000
시간 복잡도는 O(N log N)을 목표로 합니다.

## 예제 1

**입력**
```
3
1 5
2 6
4 7
```

**출력**
```
3
```

*시간 4~5 사이에는 세 개의 강좌(1-5, 2-6, 4-7)가 동시에 진행되어 최대 3개의 강의실이 필요합니다.*

## 예제 2

**입력**
```
4
1 3
3 5
5 8
10 12
```

**출력**
```
1
```

*모든 강좌가 서로 이어지거나 떨어져 있어, 한 번에 최대 1개의 강의실만 필요합니다. (끝 시간이 다음 시작 시간과 같으면 인원수 계산 시 제외됩니다.)*

## 힌트

- 시간 축 상에서 '사건(Event)'을 정의하는 것이 유용합니다.
- 모든 강좌의 시작점과 끝점을 기준으로 이벤트를 생성하고, 이 이벤트들을 시간 순으로 정렬하여 순회하세요.


## 알고리즘 요약

Sweep Line (스윕 라인) 알고리즘. 모든 구간의 시작점과 종료점을 '사건'으로 간주하고, 이를 시간 순서대로 정렬합니다. 시작점에 도달하면 현재 인원수를 +1하고, 종료점에 도달하면 -1합니다. 이 과정에서 기록된 최대 인원수가 답이 됩니다.

## 풀이 해설

문제는 주어진 구간들(강좌) 중 가장 많은 수가 동시에 겹치는 시점을 찾는 문제입니다. 이는 전형적인 스윕 라인 알고리즘을 적용할 수 있습니다.

1. 이벤트 정의: 각 강좌 [S, E]는 두 개의 사건을 발생시킵니다. 시작 시간 S에서는 인원이 +1 증가하고, 종료 시간 E에서 인원이 -1 감소합니다. (문제 조건에 따라 끝나는 순간부터 다음 강좌가 시작한다고 가정하여, 종료 시점을 포함하는 구간으로 처리합니다.)
2. 이벤트 배열 생성: 모든 강좌에 대해 (시간, 타입) 쌍의 리스트를 만듭니다. 여기서 타입은 +1(시작) 또는 -1(종료)입니다.
3. 정렬 기준 설정: 이 이벤트들을 시간 순서대로 오름차순 정렬합니다. 만약 같은 시간에 시작점과 끝점이 겹치는 경우, 반드시 '시작(+1)'이 먼저 처리되어야 합니다. (예: [1, 3] 종료 후 [3, 5] 시작 시, 먼저 -1을 처리하면 0명이 되고, 나중에 +1을 처리하여 다시 1명이 됩니다. 하지만 만약 정렬 순서가 바뀌면 계산 오류가 날 수 있습니다.) 따라서, 시간이 같으면 반드시 시작 이벤트(+1)를 종료 이벤트(-1)보다 우선 처리하도록 정렬 조건을 설정해야 합니다.
4. 스윕(Sweep): 정렬된 이벤트를 처음부터 순회하면서 현재 인원수(`current_count`)를 업데이트합니다. 매 단계마다 `current_count`와 최대값(`max_count`)을 비교하며 최대값을 갱신합니다.
5. 시간 복잡도: 이벤트 개수는 $2N$개이므로, 정렬에 $O(N 	o N 	ext{개의 이벤트}) 	imes O(	ext{로그 } N)$이 소요됩니다. 따라서 전체 시간 복잡도는 $O(N 	ext{ log } N)$입니다.

## 참고 코드 (java)

```java
import java.io.*;
import java.util.*;

// Event class to hold time and type (+1 for start, -1 for end)
class Event implements Comparable<Event> {
    int time;
    int type; // 1: Start (+1), -1: End (-1)

    public Event(int time, int type) {
        this.time = time;
        this.type = type;
    }

    @Override
    public int compareTo(Event other) {
        // 1. 시간 순서로 정렬 (오름차순)
        if (this.time != other.time) {
            return Integer.compare(this.time, other.time);
        }
        // 2. 같은 시간에 이벤트가 발생할 경우, 시작(+1) 이벤트를 종료(-1) 이벤트보다 먼저 처리해야 합니다.
        //    즉, 타입 값이 큰 것이 우선권을 가집니다 (1 > -1).
        return Integer.compare(other.type, this.type);
    }
}

public class Main {
    public static void main(String[] args) throws IOException {
        BufferedReader br = new BufferedReader(new InputStreamReader(System.in));
        // 첫 줄: N (강좌 개수)
        int n = Integer.parseInt(br.readLine());

        List<Event> events = new ArrayList<>();

        for (int i = 0; i < n; i++) {
            StringTokenizer st = new StringTokenizer(br.readLine());
            int start = Integer.parseInt(st.nextToken());
            int end = Integer.parseInt(st.nextToken());

            // 시작 이벤트: +1
            events.add(new Event(start, 1));
            // 종료 이벤트: -1 (문제 조건상 끝나는 시점부터는 인원수가 줄어든다고 가정)
            events.add(new Event(end, -1)); 
        }

        // 모든 이벤트를 정렬합니다.
        Collections.sort(events);

        int currentCount = 0;
        int maxOverlap = 0;

        // 스윕 라인 방식으로 순회하며 최대 중첩도를 계산합니다.
        for (Event event : events) {
            currentCount += event.type;
            maxOverlap = Math.max(maxOverlap, currentCount);
        }

        System.out.println(maxOverlap);
    }
}
```
