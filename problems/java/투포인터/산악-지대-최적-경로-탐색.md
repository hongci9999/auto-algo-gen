# 산악 지대 최적 경로 탐색
*java · 투포인터 · 보통 · 투포인터, 슬라이딩 윈도우, 배열*

## 입출력 환경

Java 환경에서 빠른 입출력을 위해 BufferedReader와 StringTokenizer를 사용하는 것이 권장됩니다.

## 문제

당신은 산악 지대를 탐험하는 탐험가입니다. 이 지대는 여러 개의 칸으로 나뉘어 있으며, 각 칸에는 통과하는 데 필요한 비용(높이)이 기록되어 있습니다. 당신에게는 최대 예산 $K$가 주어졌습니다. 당신은 연속된 칸들로 이루어진 경로를 선택해야 하며, 이 경로를 통과하는 총 비용은 예산 $K$를 초과할 수 없습니다.

당신의 목표는 총 비용이 $K$를 넘지 않으면서, 가장 긴 연속 경로를 찾는 것입니다. 즉, 조건을 만족하는 가장 긴 길이의 연속된 부분 배열의 길이를 구하세요.

## 입력

첫째 줄에 정수 $N$ (배열의 길이)과 최대 예산 $K$가 공백으로 구분되어 주어집니다. (1 <= N <= 100,000, 0 <= K <= 10^9)
둘째 줄에 $N$개의 정수 $costs$가 공백으로 구분되어 주어집니다. (1 <= costs[i] <= 10^9)

## 출력

조건을 만족하는 가장 긴 경로의 길이(정수)를 한 줄에 출력합니다.

## 제약 조건

N: 1부터 100,000까지. K, costs[i]: 0부터 10^9까지. 시간 복잡도는 O(N)을 목표로 합니다.

## 예제 1

**입력**
```
3 4
1 3 2
```

**출력**
```
2
```

*배열 [1, 3, 2], K=4. [1, 3]의 합이 4로 최대 길이 2입니다. [1, 3, 2]는 합이 6으로 초과합니다.*

## 예제 2

**입력**
```
4 7
5 1 4 2
```

**출력**
```
3
```

*배열 [5, 1, 4, 2], K=7. [1, 4, 2]의 합이 7로 최대 길이 3입니다.*

## 예제 3

**입력**
```
5 10
1 1 1 1 1
```

**출력**
```
5
```

*모든 칸을 지나도 합이 5로 K=10 이하입니다. 따라서 최대 길이 5입니다.*

## 힌트

- 이 문제는 '슬라이딩 윈도우' 기법을 사용하여 해결할 수 있습니다.
- 윈도우의 합이 예산을 초과할 때, 윈도우를 어떻게 축소해야 하는지 생각해보세요.


## 알고리즘 요약

슬라이딩 윈도우 (Sliding Window) / 투 포인터 기법을 사용합니다. 두 포인터(left, right)를 사용하여 현재 경로(윈도우)를 유지하며, 현재 윈도우의 합이 예산 K를 초과하는지 확인합니다. 초과한다면 왼쪽 포인터를 이동시키고, 여유하다면 오른쪽 포인터를 이동시키면서 최대 길이를 갱신합니다.

## 풀이 해설

이 문제는 투 포인터(Two Pointers) 기법, 특히 슬라이딩 윈도우(Sliding Window)를 적용하여 $O(N)$ 시간 복잡도로 해결할 수 있습니다.

**1. 아이디어:**
우리는 배열의 시작점부터 끝점까지 순차적으로 윈도우를 확장하고, 윈도우의 합이 최대 예산 $K$를 넘지 않도록 관리합니다. 윈도우의 왼쪽 끝(left)과 오른쪽 끝(right)을 포인터로 사용합니다.

**2. 단계:**
*   `left` 포인터를 0으로, `currentSum`을 0으로 초기화합니다. `maxLength`는 0으로 초기화합니다.
*   `right` 포인터를 배열의 끝까지 한 칸씩 이동시키면서 (반복문):
    *   현재 `costs[right]`를 `currentSum`에 더하여 윈도우를 확장합니다.
    *   **조건 확인:** 만약 `currentSum`이 예산 $K$를 초과하게 되면:
        *   윈도우가 너무 커졌다는 의미이므로, 왼쪽 포인터(`left`)를 이동시키면서 `costs[left]`만큼 `currentSum`에서 빼줍니다.
        *   이 과정을 `currentSum <= K`가 될 때까지 반복합니다. (이때 `left` 포인터도 함께 증가합니다.)
    *   **결과 갱신:** `currentSum`이 $K$ 이하로 유지되면, 현재 윈도우의 길이(`right - left + 1`)를 계산하여 `maxLength`와 비교하고 더 큰 값으로 갱신합니다.
*   모든 `right` 포인터 이동이 끝나면, `maxLength`가 정답입니다.

**3. 시간 복잡도:**
오른쪽 포인터(`right`)는 $N$번 움직이고, 왼쪽 포인터(`left`) 역시 최대 $N$번 움직입니다. 각 포인터는 배열을 한 번만 순회하므로, 전체 시간 복잡도는 $O(N)$입니다. 공간 복잡도는 $O(1)$입니다.

## 참고 코드 (java)

```java
import java.util.Scanner;
import java.util.Arrays;

public class Solution {
    public static void main(String[] args) {
        // 표준 입력 처리를 위해 Scanner를 사용하거나, 더 나은 성능을 위해 BufferedReader를 사용할 수 있습니다.
        // 여기서는 테스트 용이성을 위해 Scanner를 사용하며, 실제 제출 시 BufferedReader로 변경하는 것을 권장합니다.
        Scanner scanner = new Scanner(System.in);

        // 입력 예시: 3 4\n1 3 2
(N, K가 첫 줄, costs가 두 번째 줄)

        // N과 K를 입력받습니다.
        if (!scanner.hasNextInt()) return;
        int N = scanner.nextInt();
        long K = scanner.nextLong();

        // costs 배열을 입력받습니다.
        long[] costs = new long[N];
        for (int i = 0; i < N; i++) {
            costs[i] = scanner.nextLong();
        }
        
        // 슬라이딩 윈도우 구현
        long currentSum = 0;
        int left = 0;
        int maxLength = 0;

        for (int right = 0; right < N; right++) {
            // 1. 윈도우 확장: 오른쪽 포인터 이동
            currentSum += costs[right];

            // 2. 조건 확인 및 윈도우 축소: 합이 K를 초과하면 왼쪽 포인터 이동
            while (currentSum > K) {
                // 현재 costs[left]를 합에서 제거하고 left를 오른쪽으로 이동
                currentSum -= costs[left];
                left++;
            }
            
            // 3. 결과 갱신: 현재 윈도우의 길이 계산 및 최대 길이 갱신
            // 현재 윈도우의 길이는 right - left + 1 입니다.
            int currentLength = right - left + 1;
            maxLength = Math.max(maxLength, currentLength);
        }

        System.out.println(maxLength);
        scanner.close();
    }
}
```
