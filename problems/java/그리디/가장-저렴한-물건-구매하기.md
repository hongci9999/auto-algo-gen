# 가장 저렴한 물건 구매하기
*java · 그리디 · 보통 · 정렬, 그리디, 배열*

## 입출력 환경

Java 환경에서는 BufferedReader와 StringTokenizer를 사용하여 입력을 처리하는 것이 효율적입니다.

## 문제

어떤 상점에서 N개의 물건이 판매되고 있습니다. 각 물건은 고유한 가격을 가지고 있으며, 구매자는 총 예산(B)을 가지고 있습니다. 구매자는 예산 내에서 최대한 많은 수의 물건을 구매하는 것을 목표로 합니다. 물건을 구매할 때, 가장 저렴한 물건부터 순서대로 구매하는 것이 항상 최적의 전략입니다. 주어진 N개의 물건 가격과 예산을 이용하여, 구매할 수 있는 최대 물건의 개수를 구하세요.

물건의 가격은 양의 정수이며, 예산 역시 양의 정수입니다.

## 입력

첫 번째 줄에 물건의 개수 N과 총 예산 B가 공백으로 구분되어 주어집니다. (N B)
두 번째 줄부터 N줄에 걸쳐 각 물건의 가격이 한 줄에 하나씩 주어집니다.

## 출력

구매할 수 있는 최대 물건의 개수를 정수 형태로 출력합니다.

## 제약 조건

1 <= N <= 100,000
1 <= B <= 10,000,000
1 <= 가격 <= 1,000,000
시간 복잡도: O(N log N) 또는 O(N)

## 예제 1

**입력**
```
5 100
10
20
5
30
15
```

**출력**
```
5
```

*가격: 5, 10, 15, 20, 30. 합계 80. 예산 100으로 5개 모두 구매 가능.*

## 예제 2

**입력**
```
4 50
30
40
10
20
```

**출력**
```
3
```

*가격 오름차순: 10, 20, 30, 40. 10+20+30 = 60 (초과). 10+20 = 30. 30에 30 추가 불가. 10+20+? -> 10+20=30. 남은 예산 20. 30은 구매 불가. 10, 20 구매 후 30 구매 불가능. 10+20=30. 다음 30 구매 시 60 (초과). 따라서 10, 20, 30 중 2개를 사야 함. (10+20+30=60). -> 10, 20, 그리고 다음 가장 작은 30을 사야 하지만, 예산이 50이므로, 10, 20, 30 중 2개를 사야 합니다. (10+20=30, 10+30=40, 20+30=50). 최대 3개 구매 가능 (10+20+30=60이므로 3개 구매 불가). 10+20=30. 남은 20. 30은 구매 불가. 따라서 10, 20, 그리고 30 중 하나를 더 사야 하는데, 예산이 50이므로 10, 20, 30 중 3개를 사려고 하면 60이 필요하여 불가능. 따라서 2개만 살 수 있습니다. (10+40=50, 20+30=50). 최대 2개만 가능합니다. (오류 수정: 10, 20, 30, 40. 10+20=30. 남은 20. 30은 구매 불가. 10, 20, 30 중 2개를 구매하는 것이 최적. 10+40=50, 20+30=50. 최대 2개.)*

## 힌트

- 최대한 많은 개수를 사기 위해서는, 항상 비용이 가장 적게 드는 물건부터 구매해야 합니다.
- 문제 해결의 핵심은 '정렬'입니다. 모든 물건의 가격을 오름차순으로 정렬하세요.


## 알고리즘 요약

그리디 알고리즘을 사용합니다. 물건을 구매할 때 개수를 최대화하는 것이 목표이므로, 항상 현재 예산으로 구매할 수 있는 물건 중 가장 가격이 저렴한 물건을 선택하는 것이 최적입니다. 따라서, 모든 물건의 가격을 오름차순으로 정렬한 후, 정렬된 순서대로 가격을 누적 합산하며 예산 B를 초과하지 않는지 확인합니다. 초과하지 않는 물건의 개수가 최대 구매 개수입니다.

## 풀이 해설

1. 아이디어 파악: 이 문제는 주어진 예산(B)으로 최대한 많은 물건을 구매하는 최대 개수를 찾는 문제입니다. 개수를 최대화하려면, 가장 저렴한 물건들을 우선적으로 구매해야 합니다. 이는 전형적인 그리디(Greedy) 접근 방식입니다.
2. 단계별 풀이:
   a. 입력 받기: 물건의 개수 N과 예산 B를 입력받고, N개의 물건 가격 배열을 준비합니다.
   b. 정렬: 준비된 물건 가격 배열을 오름차순으로 정렬합니다. (가장 저렴한 물건이 배열의 시작에 위치하게 됩니다.)
   c. 순차적 구매 시뮬레이션: 정렬된 배열을 처음부터 끝까지 순회하면서, 현재까지의 누적 비용에 다음 물건의 가격을 더합니다. 이 합계가 예산 B를 초과하지 않는 동안에만 구매 가능한 물건으로 간주합니다.
   d. 개수 카운트: 예산 B를 초과하는 순간 루프를 멈추고, 그때까지 성공적으로 구매한 물건의 개수를 반환합니다.
3. 시간 복잡도: 전체 시간 복잡도는 주로 배열을 정렬하는 단계에 의해 결정됩니다. N개의 원소를 정렬하는 데 O(N log N)의 시간이 걸리며, 이후 순회하는 과정은 O(N)이므로, 최종 시간 복잡도는 O(N log N)입니다.

## 참고 코드 (java)

```java
import java.io.BufferedReader;
import java.io.InputStreamReader;
import java.io.IOException;
import java.util.StringTokenizer;
import java.util.Arrays;

public class Main {

    public static void main(String[] args) {
        BufferedReader br = new BufferedReader(new InputStreamReader(System.in));
        try {
            // 첫 줄: N (물건 개수), B (예산)
            StringTokenizer st = new StringTokenizer(br.readLine());
            int N = Integer.parseInt(st.nextToken());
            long B = Long.parseLong(st.nextToken());

            // 물건 가격을 저장할 배열
            int[] prices = new int[N];

            // 나머지 N줄: 각 물건의 가격 입력
            for (int i = 0; i < N; i++) {
                // 각 가격은 한 줄에 하나씩 들어옴
                prices[i] = Integer.parseInt(br.readLine());
            }

            // 1. 그리디 전략을 위해 가격 배열을 오름차순으로 정렬
            Arrays.sort(prices); 

            long currentCost = 0;
            int count = 0;
            
            // 2. 정렬된 순서대로 구매 가능하면 구매
            for (int i = 0; i < N; i++) {
                int nextPrice = prices[i];
                
                // 예산 초과 여부 확인
                if (currentCost + nextPrice <= B) {
                    currentCost += nextPrice;
                    count++;
                } else {
                    // 예산을 초과했으므로 더 이상 구매할 수 없음
                    break;
                }
            }

            System.out.println(count);

        } catch (IOException e) {
            // 예외 처리
        }
    }
}
```
