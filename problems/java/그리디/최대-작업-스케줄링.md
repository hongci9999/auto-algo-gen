# 최대 작업 스케줄링
*java · 그리디 · 보통 · 정렬, 그리디*

## 입출력 환경

Java에서는 입력을 효율적으로 처리하기 위해 BufferedReader와 StringTokenizer를 사용하는 것이 권장됩니다.

## 문제

당신은 여러 개의 작업(Task) 목록을 받았습니다. 각 작업은 시작 시간과 종료 시간으로 정의됩니다. 두 작업이 겹치지 않으려면, 한 작업의 종료 시간이 다른 작업의 시작 시간보다 같거나 커야 합니다. 주어진 작업들 중에서 서로 겹치지 않으면서 가장 많은 작업을 수행할 수 있는 최대 개수를 구하세요.

단, 시간은 정수이며, 작업의 종료와 다음 작업의 시작은 동일해도 겹치지 않는 것으로 간주합니다.

## 입력

첫 번째 줄에 작업의 총 개수 N이 주어집니다. 이후 N개의 줄에 걸쳐 각 작업의 시작 시간 $S$와 종료 시간 $E$가 공백으로 구분되어 주어집니다. (S E)

## 출력

서로 겹치지 않는 최대 작업 개수를 정수 하나로 출력합니다.

## 제약 조건

1. $1 	ext{ <= } N 	ext{ <= } 100,000$
2. $0 	ext{ <= } S, E 	ext{ <= } 10^9$ (시간은 long형으로 처리해야 합니다.)
3. 시간 복잡도는 $O(N 	ext{ log } N)$ 이내여야 합니다.

## 예제 1

**입력**
```
3
1 3
2 5
4 6
```

**출력**
```
2
```

*작업 (1, 3)을 선택한 후, 다음으로 시작 시간이 3 이상인 (4, 6)을 선택하여 총 2개의 작업을 수행할 수 있습니다.*

## 예제 2

**입력**
```
5
0 10
1 2
3 4
5 6
7 9
```

**출력**
```
4
```

*가장 먼저 끝나는 작업들부터 선택하는 그리디 접근법을 사용해야 합니다. (1, 2) -> (3, 4) -> (5, 6)을 선택하고, 마지막에 (7, 9)를 선택할 수 있습니다.*

## 힌트

- 문제의 성격이 '최대 개수'를 찾는 최적화 문제입니다.
- 이러한 종류의 문제는 '그리디 알고리즘'의 대표적인 예시입니다.


## 알고리즘 요약

활동 선택 문제(Activity Selection Problem)로, 그리디(Greedy) 알고리즘을 적용합니다. 핵심 아이디어는 '가장 빨리 끝나는 작업'을 우선적으로 선택하는 것입니다. 모든 작업을 종료 시간 기준으로 오름차순 정렬한 후, 첫 번째 작업을 선택하고, 이후 선택하는 작업은 직전 작업의 종료 시간보다 같거나 늦게 시작하는 것 중에서 가장 빨리 끝나는 것을 선택하는 과정을 반복합니다.

## 풀이 해설

풀이 해설: 아이디어 및 단계
1. **문제 분석 및 아이디어:** 이 문제는 주어진 제약 조건 하에서 최대 개수를 찾는 그리디 알고리즘 문제입니다. 일반적으로 활동 선택 문제에서, 모든 가능한 선택지 중 '가장 빨리 끝나는 것'을 선택하는 것이 최적의 선택입니다. 왜냐하면 빨리 끝날수록 남은 시간(리소스)이 많아져 다음 작업을 선택할 여지가 커지기 때문입니다.
2. **단계 1: 데이터 구조화 및 정렬:** 입력받은 모든 작업 (시작 시간, 종료 시간)을 저장합니다. 이 작업 목록 전체를 **종료 시간(End Time)을 기준으로 오름차순 정렬**합니다. (종료 시간이 같으면 시작 시간을 기준으로 정렬하는 것이 좋습니다.)
3. **단계 2: 그리디 선택:** 최대 개수를 저장할 카운터(`count`)를 1로 초기화하고, 직전에 선택된 작업의 종료 시간(`lastEndTime`)을 첫 번째 작업의 종료 시간으로 설정합니다.
4. **단계 3: 순회 및 비교:** 정렬된 작업 목록을 처음부터 순회합니다. 현재 작업 $i$의 시작 시간 $S_i$가 `lastEndTime`보다 크거나 같다면, 이 작업은 겹치지 않으므로 선택 가능합니다. 따라서 `count`를 1 증가시키고, `lastEndTime`을 현재 작업 $i$의 종료 시간 $E_i$로 업데이트합니다. 그렇지 않다면, 이 작업은 건너<0xEB><0x9C><0x81>니다.
3. **시간 복잡도:** 작업 $N$개에 대해 정렬하는 과정이 필요하므로, 시간 복잡도는 $O(N 	ext{ log } N)$이 됩니다. 이후 순회는 $O(N)$이므로 전체 시간 복잡도는 $O(N 	ext{ log } N)$입니다.

## 참고 코드 (java)

```java
import java.io.BufferedReader;
import java.io.InputStreamReader;
import java.io.IOException;
import java.util.Arrays;
import java.util.Comparator;
import java.util.StringTokenizer;

// 작업 정보를 담을 클래스
class Task {
    long start;
    long end;

    public Task(long start, long end) {
        this.start = start;
        this.end = end;
    }
}

public class Main {

    public static void main(String[] args) throws IOException {
        // 효율적인 입력을 위한 설정
        BufferedReader br = new BufferedReader(new InputStreamReader(System.in));
        
        // 첫 줄에서 작업 개수 N 읽기
        String line = br.readLine();
        if (line == null || line.isEmpty()) return;
        int N = Integer.parseInt(line.trim());
        
        Task[] tasks = new Task[N];
        
        // 작업 데이터 읽기
        for (int i = 0; i < N; i++) {
            StringTokenizer st = new StringTokenizer(br.readLine());
            long start = Long.parseLong(st.nextToken());
            long end = Long.parseLong(st.nextToken());
            tasks[i] = new Task(start, end);
        }

        // 1. 그리디 알고리즘의 핵심: 종료 시간(End Time) 기준으로 정렬
        // Comparator를 사용하여 T.end를 기준으로 오름차순 정렬
        Arrays.sort(tasks, Comparator.comparingLong(t -> t.end));

        // 2. 그리디 선택 및 카운팅
        int count = 0;
        // 직전에 선택된 작업의 종료 시간을 저장할 변수. 초기값은 매우 작은 값으로 설정
        long lastEndTime = -1; 

        for (int i = 0; i < N; i++) {
            Task currentTask = tasks[i];
            
            // 현재 작업의 시작 시간이 마지막 작업의 종료 시간보다 크거나 같으면 (겹치지 않으면)
            if (currentTask.start >= lastEndTime) {
                // 작업을 선택하고 카운트를 증가시킵니다.
                count++;
                // 마지막 종료 시간을 현재 작업의 종료 시간으로 업데이트합니다.
                lastEndTime = currentTask.end;
            }
        }

        System.out.println(count);
    }
}
```
