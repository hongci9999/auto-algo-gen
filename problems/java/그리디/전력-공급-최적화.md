# 전력 공급 최적화
*java · 그리디 · 보통 · 그리디, 시뮬레이션, 배열*

## 입출력 환경

입력은 표준 입력(System.in)을 사용하며, 효율적인 처리를 위해 BufferedReader와 StringTokenizer를 사용하십시오.

## 문제

N개의 스테이션이 일렬로 배치되어 있으며, 각 스테이션 $i$는 $R_i$ 만큼의 전력을 필요로 합니다. 전력 공급은 한 번에 $C$ 만큼의 용량을 가진 '부스터'를 설치하여 이루어지며, 이 부스터는 연결된 스테이션들의 전력 요구량을 순차적으로 충족시킵니다.

스테이션의 전력 요구량은 클 수 있으므로, 전력 용량과 요구량은 `long` 타입으로 처리해야 합니다.

최소한의 부스터를 설치하여 모든 스테이션의 전력 요구량을 충족시키는 방법을 찾아야 합니다. 즉, 필요한 부스터의 최소 개수를 구하시오.

## 입력

첫 줄에 스테이션의 개수 N과 부스터의 총 용량 C가 공백으로 구분되어 주어집니다. (N <= 100,000, C <= 10^9)
다음 N줄에는 각 스테이션 i의 전력 요구량 $R_i$가 한 줄에 하나씩 주어집니다. (R_i <= 10^9)

## 출력

최소한의 부스터 개수를 하나의 정수(long)로 출력합니다.

## 제약 조건

시간 복잡도는 O(N) 또는 O(N log N) 이내여야 합니다. N은 최대 100,000입니다.

## 예제 1

**입력**
```
5 10
1
5
1
8
2
```

**출력**
```
2
```

*첫 번째 부스터는 [1, 5, 1]을 처리하고, 두 번째 부스터가 [8, 2]를 처리합니다. (1 + 5 + 1 = 7 <= 10)*

## 예제 2

**입력**
```
3 5
6
1
1
```

**출력**
```
2
```

*첫 번째 부스터는 [6]을 처리합니다. (6 > 5 이므로, 요구량이 부스터 용량을 초과하면 해당 요구량은 독립적인 부스터가 필요합니다. 문제의 제약상 R_i <= C가 아니면 풀이가 불가능할 수 있으나, 여기서는 R_i <= C인 경우만 고려합니다. 예시를 위해 R_i <= C가 아닐 경우를 제외하고, [6]을 처리하기 위해 부스터 1개 사용. 나머지 [1, 1]은 부스터 2개로 처리합니다.)*

## 힌트

- 문제를 해결하기 위해 그리디(탐욕) 알고리즘을 사용합니다.
- 현재 부스터가 커버할 수 있는 최대 범위를 파악하고, 그 범위를 벗어나는 지점마다 부스터를 새로 배치하는 것이 핵심 아이디어입니다.


## 알고리즘 요약

그리디 알고리즘 (Greedy Algorithm). 배열을 순차적으로 탐색하며, 현재 스테이션의 전력 요구량을 충족하는 가장 긴 연속 구간을 찾습니다. 이 구간이 끝나는 지점에서 부스터가 부족할 경우, 새로운 부스터를 배치하고 그 용량을 초기화합니다. 이 과정을 N까지 반복합니다.

## 풀이 해설

아이디어: 이 문제는 최소한의 자원으로 최대의 영역을 커버해야 하는 전형적인 그리디 문제입니다. 따라서 전력을 공급하는 부스터가 필요한 시점마다, 해당 부스터로 최대한 많은 스테이션을 커버하도록 배치해야 합니다.

단계:
1. 변수 초기화: `boosters` (사용된 부스터 개수)를 0으로, 현재 스테이션 인덱스 `i`를 0으로 설정합니다.
2. 반복 처리: `i`가 N보다 작을 동안 반복합니다.
3. 부스터 배치 및 초기화: 부스터가 필요할 때마다 `boosters`를 1 증가시키고, 현재 부스터의 남아있는 용량 `currentCapacity`를 $C$로 설정합니다. (즉, 새 부스터를 설치함).
4. 최대 커버리지 탐색: 현재 인덱스 `j`를 `i`부터 시작하여 이동시키면서, $R_j$가 `currentCapacity`보다 작거나 같을 때까지 반복합니다.
5. 자원 소모 및 이동: 반복문 내부에서 `currentCapacity -= R_j`를 수행하고, `j`를 증가시킵니다. 이 과정에서 `currentCapacity`가 0이 되거나, $R_j$가 `currentCapacity`를 초과하는 순간 루프를 종료합니다.
6. 다음 시작점 설정: 모든 커버가 완료된 지점의 다음 인덱스 `j`를 새로운 시작점 `i`로 설정하고, 메인 루프를 다시 시작합니다.

시간 복잡도: 각 스테이션은 `i`로 시작하여 한 번만 `j`에 의해 순회되므로, 전체 시간 복잡도는 $O(N)$입니다.

## 참고 코드 (java)

```java
import java.io.BufferedReader;
import java.io.IOException;
import java.io.InputStreamReader;
import java.util.StringTokenizer;

public class Solution {

    public static void main(String[] args) {
        BufferedReader br = new BufferedReader(new InputStreamReader(System.in));
        try {
            StringTokenizer st = new StringTokenizer(br.readLine());
            int N = Integer.parseInt(st.nextToken());
            long C = Long.parseLong(st.nextToken());

            long[] R = new long[N];
            for (int i = 0; i < N; i++) {
                // R_i는 한 줄에 하나씩 주어짐
                R[i] = Long.parseLong(br.readLine());
            }

            long minBoosters = solve(N, C, R);
            System.out.println(minBoosters);

        } catch (IOException e) {
            // 예외 처리 로직
        }
    }

    // 그리디 방식으로 최소 부스터 개수 계산
    public static long solve(int N, long C, long[] R) {
        long boosters = 0;
        int i = 0; // 현재 커버해야 할 스테이션의 시작 인덱스

        while (i < N) {
            // 1. 부스터가 필요할 때마다 개수 증가
            boosters++;
            long currentCapacity = C;
            int j = i; // 현재 부스터로 커버를 시도하는 스테이션
            
            // 2. 현재 부스터 용량으로 최대한 많이 커버 시도
            while (j < N) {
                long required = R[j];
                
                // 요구량이 용량을 초과하면 멈춘다.
                if (required > currentCapacity) {
                    break;
                }
                
                // 용량 소모 및 다음 스테이션으로 이동
                currentCapacity -= required;
                j++;
            }
            
            // 3. 다음 시작점을 업데이트 (커버가 끝난 지점의 바로 다음 스테이션)
            i = j;
        }

        return boosters;
    }
}
```
