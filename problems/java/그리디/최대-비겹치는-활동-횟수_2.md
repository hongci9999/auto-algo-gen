# 최대 비겹치는 활동 횟수
*java · 그리디 · 보통 · 정렬, 그리디*

## 입출력 환경

Java 환경에서는 입출력 속도를 위해 BufferedReader와 StringTokenizer를 사용하는 것이 권장됩니다.

## 문제

여러 개의 활동이 주어집니다. 각 활동은 시작 시간과 종료 시간을 가집니다. 두 활동이 겹치지 않으면서 참여할 수 있는 최대 활동의 횟수를 구하는 문제입니다. 활동 [S1, E1]과 [S2, E2]가 주어진 경우, 두 활동이 겹치지 않으려면, 한 활동의 종료 시간이 다른 활동의 시작 시간보다 작거나 같아야 합니다 (즉, E1 < S2 또는 E2 < S1). 활동 시간은 정수이며, 시간 순서상 겹치지 않는 것이 중요합니다.

주의: 활동 [S1, E1]과 [S2, E2]가 시간상 겹치지 않는다는 것은, E1 < S2 또는 E2 < S1을 의미합니다. 만약 E1 = S2라면, 활동이 바로 이어지므로 겹치지 않는 것으로 간주합니다.

## 입력

첫 줄에는 활동의 총 개수 N이 주어집니다. 다음 N줄에는 각 활동의 시작 시간(S)과 종료 시간(E)이 공백으로 구분되어 주어집니다.

## 출력

참여할 수 있는 최대 활동의 횟수를 하나의 정수로 출력합니다.

## 제약 조건

1 <= N <= 100,000
1 <= Start <= End <= 1,000,000,000
시간 범위가 크므로 long 타입을 사용해야 합니다.

## 예제 1

**입력**
```
5
1 4
2 3
4 5
6 8
7 9
```

**출력**
```
3
```

*가장 먼저 끝나는 활동을 선택하는 그리디 방식이 최적입니다. (2, 3) -> (4, 5) -> (6, 8) 또는 (7, 9)를 선택할 수 있습니다. (2, 3), (4, 5), (6, 8)이 최대입니다.*

## 예제 2

**입력**
```
4
1 10
2 3
4 5
6 7
```

**출력**
```
3
```

*가장 먼저 끝나는 활동들을 선택해야 합니다. (2, 3), (4, 5), (6, 7)을 선택하는 것이 최대입니다.*

## 힌트

- 선택해야 할 활동을 정렬하는 기준이 핵심입니다. 어떤 기준으로 정렬해야 할까요?
- 최대한 많은 활동을 선택하려면, 매번 '가장 빨리 끝나는' 활동을 선택하는 것이 유리합니다.


## 알고리즘 요약

그리디 알고리즘과 정렬을 이용합니다. 활동들을 종료 시간(End Time)을 기준으로 오름차순 정렬한 후, 첫 번째 활동을 선택하고, 이후 활동 중 현재 선택된 활동의 종료 시간보다 시작 시간이 크거나 같은 활동을 순차적으로 선택합니다.

## 풀이 해설

풀이 해설:
1. 아이디어 (Greedy Choice):
   최대 활동 횟수를 확보하기 위한 그리디 전략은 '현재 시점에서 가장 일찍 끝나는 활동'을 선택하는 것입니다. 이렇게 함으로써 남은 시간 간격이 최대화되어 이후의 활동들을 선택할 여지를 가장 많이 남기게 됩니다.
2. 단계:
   a. 입력 받기: 모든 활동 [시작 시간, 종료 시간]을 저장합니다.
   b. 정렬: 저장된 활동들을 **종료 시간(End Time)**을 기준으로 오름차순 정렬합니다. (만약 종료 시간이 같다면, 시작 시간 순으로 정렬해도 무방합니다.)
   c. 탐색 및 선택: 첫 번째 활동을 선택하고 횟수를 1로 초기화합니다. 현재 선택된 활동의 종료 시간을 `last_finish_time` 변수에 저장합니다. 이후 정렬된 리스트를 순회하며, 현재 활동의 시작 시간(S)이 `last_finish_time`보다 크거나 같은 경우에만 해당 활동을 선택하고, 횟수를 1 증가시키며, `last_finish_time`을 현재 활동의 종료 시간(E)으로 업데이트합니다.
3. 시간 복잡도:
   시간 복잡도는 주로 정렬 단계에 의해 결정됩니다. N개의 활동을 정렬하는 데 O(N log N)이 걸리며, 이후 순회하는 과정은 O(N)이므로, 전체 시간 복잡도는 O(N log N)입니다.

## 참고 코드 (java)

```java
import java.io.BufferedReader;
import java.io.InputStreamReader;
import java.util.Arrays;
import java.util.Comparator;
import java.util.StringTokenizer;

class Activity {
    long start;
    long end;

    public Activity(long start, long end) {
        this.start = start;
        this.end = end;
    }
}

public class Main {
    public static void main(String[] args) {
        BufferedReader br = new BufferedReader(new InputStreamReader(System.in));
        try {
            // 1. 활동 개수 N 읽기
            String line = br.readLine();
            if (line == null || line.isEmpty()) {
                System.out.println(0);
                return;
            }
            int N = Integer.parseInt(line.trim());

            Activity[] activities = new Activity[N];

            // 2. 모든 활동 정보 읽기
            for (int i = 0; i < N; i++) {
                StringTokenizer st = new StringTokenizer(br.readLine());
                long start = Long.parseLong(st.nextToken());
                long end = Long.parseLong(st.nextToken());
                activities[i] = new Activity(start, end);
            }

            // 3. 정렬 (종료 시간 기준 오름차순)
            // 가장 빨리 끝나는 활동부터 처리해야 그리디 선택이 가능합니다.
            Arrays.sort(activities, Comparator.comparingLong(a -> a.end));

            // 4. 그리디 알고리즘 적용
            int count = 0;
            // 마지막으로 선택된 활동의 종료 시간을 저장합니다. 초기값은 매우 작은 값으로 설정합니다.
            long lastFinishTime = Long.MIN_VALUE;

            for (int i = 0; i < N; i++) {
                Activity current = activities[i];
                
                // 현재 활동의 시작 시간이 lastFinishTime보다 크거나 같으면 (겹치지 않으면)
                // 선택할 수 있습니다. (E1 = S2 인 경우도 허용)
                if (current.start >= lastFinishTime) {
                    count++;
                    lastFinishTime = current.end;
                }
            }

            System.out.println(count);

        } catch (Exception e) {
            // 예외 처리 (대부분의 코딩 테스트 환경에서는 필요 없음)
        }
    }
}
```
