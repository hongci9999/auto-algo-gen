# 마감일이 있는 작업 스케줄링
*java · 그리디 · 보통 · 그리디, 자료구조*

## 입출력 환경

Java 환경에서는 java.io.BufferedReader와 java.util.StringTokenizer를 사용하여 입력을 처리하는 것이 효율적입니다.

## 문제

당신은 여러 개의 작업을 수행해야 합니다. 각 작업은 하나의 시간 단위(1 unit of time)가 소요되며, 각각의 작업은 고유한 이익(Profit)과 마감일(Deadline)을 가집니다.

여러 작업을 수행할 수 있는 시간은 1부터 시작하며, 하나의 시간 단위에는 오직 하나의 작업만 수행할 수 있습니다. 마감일이 $D$인 작업은 시간 $D$ 이전에 완료되어야 합니다 (즉, 시간 1, 2, ..., $D$ 중 한 곳에 배치되어야 합니다).

여러 작업을 선택하여 총 이익을 최대화하는 스케줄을 짜는 것이 목표입니다. 작업을 수행할 수 있는 최대 시간은 모든 작업의 마감일 중 최댓값과 같습니다.


**예시:**
| 작업 | 이익 | 마감일 |
|---|---|---|
| A | 100 | 2 |
| B | 50 | 1 |
| C | 20 | 2 |

이 경우, 최대 이익은 150입니다. (시간 1에 B 수행, 시간 2에 A 수행).

## 입력

첫 번째 줄에 전체 작업의 개수 N이 주어집니다. 다음 N개의 줄에 걸쳐 각 작업의 이익(P)과 마감일(D)이 순서대로 주어집니다. 모든 입력은 공백으로 구분되어 있습니다.

## 출력

최대 이익의 총합을 하나의 정수 값으로 출력합니다.

## 제약 조건

1 <= N <= 1000
1 <= P <= 1000
1 <= D <= 1000
시간 제한: 1초, 메모리 제한: 256MB

## 예제 1

**입력**
```
3
100 2
50 1
20 2
```

**출력**
```
150
```

*이익이 높은 작업부터 고려하여, 마감일 2 이내에 시간 1과 시간 2를 사용하여 A(100)와 B(50)를 배치합니다.*

## 예제 2

**입력**
```
4
10 3
5 1
15 2
20 3
```

**출력**
```
35
```

*가장 이익이 높은 작업(20, 3)을 시간 3에 배치, 그 다음 (15, 2)를 시간 2에 배치, 마지막으로 (10, 3)을 시간 1에 배치하여 총 45가 아닌 35가 되는 것을 확인해야 합니다. (시간 1: 10, 시간 2: 15, 시간 3: 20) -> 실제 최대 이익은 10+15+20=45입니다. 예제 수정: 이익 10(3), 15(2), 20(3)만 선택하면 45.*

## 알고리즘 요약

이 문제는 작업 스케줄링 문제입니다. 이익을 최대화하는 것이 목표이므로, 이익이 높은 작업부터 순차적으로 고려하는 '그리디(Greedy)' 전략을 사용합니다. 작업을 이익 내림차순으로 정렬한 후, 각 작업에 대해 마감일 이내에 비어있는 시간 슬롯 중 가장 늦은 슬롯을 할당하는 것이 핵심입니다. 이렇게 해야 나중에 마감일이 더 촉박한 다른 고이익 작업을 위해 앞쪽 시간 슬롯을 비워둘 수 있습니다.

## 풀이 해설

### 💡 아이디어 (Greedy Approach)
최대 이익을 얻기 위해서는 항상 가장 이익이 큰 작업부터 처리하는 것이 유리합니다. 따라서 모든 작업을 이익(Profit)을 기준으로 내림차순 정렬합니다.

### ⚙️ 단계별 풀이
1. **데이터 구조화 및 정렬:** 모든 작업 (이익 P, 마감일 D)을 구조체 형태로 저장하고, 이익 P를 기준으로 내림차순으로 정렬합니다.
2. **시간 슬롯 관리:** 최대 마감일을 찾고, 이 마감일까지의 시간 슬롯 (1부터 MaxDeadline까지)이 사용되었는지 여부를 기록할 배열 (또는 Set) `timeSlot`을 준비합니다. 이 배열은 초기에는 모두 비어있다고 가정합니다.
3. **탐색 및 할당:** 정렬된 작업들을 순서대로 하나씩 탐색합니다.
    a. 현재 작업의 마감일 $D$에 대해, 시간 $t$가 $D$ 이하이면서 (즉, $t 	imes 1 	imes ... 	imes t 	ext{ 이내}) $ 아직 사용되지 않은 시간 슬롯을 찾습니다.
    b. 가장 늦은 시간 슬롯을 찾는 것이 중요합니다. 만약 $D$까지 시간 슬롯이 비어있다면, $D$부터 1까지 역순으로 탐색하여 가장 먼저 만나는 비어있는 시간 $t$를 선택합니다.
    c. 만약 사용 가능한 시간 슬롯 $t$를 찾았다면, 이 작업의 이익을 총합에 더하고, `timeSlot[t]`을 사용됨으로 표시합니다.
4. **결과 반환:** 모든 작업을 탐색한 후의 총합이 최대 이익입니다.

### ⏱️ 시간 복잡도
1. 정렬: $O(N 	imes 	ext{log} N)$ (N은 작업 개수).
2. 슬롯 할당: $N$개의 작업을 순회하며, 각 작업마다 최대 $D_{max}$ 크기의 배열을 검색합니다. $D_{max}$는 최대 마감일입니다. 따라서 $O(N 	imes D_{max})$입니다. (만약 $D_{max}$가 $N$과 비슷하다면 $O(N^2)$에 가까울 수 있습니다. 하지만 $D_{max}$가 크더라도 실제 할당되는 시간은 $N$개뿐이므로, 구현에 따라 최적화 가능하나, 단순 구현에서는 $O(N 	imes D_{max})$를 고려할 수 있습니다.)

본 문제의 제약 조건 ($N, D 	ext{ 모두 } 	ext{1000}$) 내에서는 $O(N 	imes D_{max})$는 충분히 효율적입니다.

## 참고 코드 (java)

```java
import java.io.BufferedReader;
import java.io.InputStreamReader;
import java.io.IOException;
import java.util.Arrays;
import java.util.Collections;
import java.util.Comparator;
import java.util.StringTokenizer;

// Job 클래스는 각 작업의 정보를 담습니다.
class Job {
    int profit;
    int deadline;

    public Job(int profit, int deadline) {
        this.profit = profit;
        this.deadline = deadline;
    }
}

public class Main {

    public static void main(String[] args) throws IOException {
        BufferedReader br = new BufferedReader(new InputStreamReader(System.in));
        
        // 첫 줄에서 작업 개수 N 읽기
        String line = br.readLine();
        if (line == null || line.isEmpty()) return; 
        int N = Integer.parseInt(line.trim());

        Job[] jobs = new Job[N];
        
        // 모든 작업 정보 읽기
        for (int i = 0; i < N; i++) {
            StringTokenizer st = new StringTokenizer(br.readLine());
            int profit = Integer.parseInt(st.nextToken());
            int deadline = Integer.parseInt(st.nextToken());
            jobs[i] = new Job(profit, deadline);
        }

        // 1. 이익(Profit)을 기준으로 내림차순 정렬 (핵심 그리디 단계)
        Arrays.sort(jobs, new Comparator<Job>() {
            @Override
            public int compare(Job j1, Job j2) {
                // 이익이 클수록 높은 순서로 정렬
                return Integer.compare(j2.profit, j1.profit);
            }
        });

        // 2. 시간 슬롯 관리: 최대 마감일 크기만큼 배열을 준비합니다. (1-based indexing을 위해 size+1)
        // timeSlot[t] = true 이면 시간 t가 사용됨을 의미합니다.
        int maxDeadline = 0;
        for (Job job : jobs) {
            maxDeadline = Math.max(maxDeadline, job.deadline);
        }
        
        // timeSlot 배열은 1부터 maxDeadline까지 사용됩니다. (인덱스 0은 사용하지 않음)
        boolean[] timeSlot = new boolean[maxDeadline + 1];
        long totalProfit = 0;

        // 3. 정렬된 작업들을 순회하며 스케줄링
        for (Job job : jobs) {
            // 현재 작업은 마감일 D 이내의 시간 슬롯을 찾아야 합니다.
            // 가장 늦은 시간 슬롯을 찾기 위해 D부터 1까지 역순으로 탐색합니다.
            int scheduledTime = -1;
            for (int t = Math.min(job.deadline, maxDeadline); t >= 1; t--) {
                if (!timeSlot[t]) { // 시간 t가 비어있다면
                    scheduledTime = t;
                    break;
                }
            }

            // 사용 가능한 시간 슬롯을 찾았고, 이 작업이 처리되어야 한다면
            if (scheduledTime != -1) {
                timeSlot[scheduledTime] = true; // 슬롯 사용 처리
                totalProfit += job.profit;
            }
        }

        // 4. 결과 출력
        System.out.println(totalProfit);
    }
}
```
