# 최소 간격 유지 최대 개수
*java · 그리디 · 보통 · 정렬, 그리디, 배열*

## 입출력 환경

자바 환경에서 입력을 받을 때는 BufferedReader와 StringTokenizer를 사용하여 효율적으로 처리하는 것을 권장합니다.

## 문제

N개의 점이 1차원 직선 위에 주어져 있습니다. 이 점들 중 일부를 선택하여 최대 개수를 만들고자 합니다. 단, 선택된 임의의 두 점 사이의 거리는 최소한 K 이상이어야 합니다.

주어진 점들의 좌표는 이미 배열 형태로 주어지며, 이 점들을 모두 사용해야 하는 것은 아닙니다. 점들을 선택하는 순서나 방법은 자유롭습니다.

따라서, 주어진 점들 중 최소 간격 K를 유지하면서 최대 몇 개의 점을 선택할 수 있는지 그 개수를 구하세요. (점의 좌표는 정수형입니다.)

## 입력

첫 번째 줄에 정수 N과 정수 K가 공백으로 구분되어 주어집니다. (N: 점의 개수, K: 최소 간격)
두 번째 줄에는 N개의 정수형 점 좌표 A[1], A[2], ..., A[N]이 공백으로 구분되어 주어집니다.

## 출력

최대 선택 가능한 점의 개수(정수)를 한 줄로 출력합니다.

## 제약 조건

1 ≤ N ≤ 10^5
1 ≤ K ≤ 10^9
좌표 값은 1 이상 10^9 이하의 정수입니다.

## 예제 1

**입력**
```
5 2
1 2 3 4 5
```

**출력**
```
3
```

*점들을 정렬하고, 1을 선택한 후 다음으로 3을 선택하고, 5를 선택하여 총 3개를 얻습니다.*

## 예제 2

**입력**
```
4 15
10 30 20 40
```

**출력**
```
2
```

*점들을 정렬하면 {10, 20, 30, 40}이 됩니다. 10을 선택한 후, 다음으로 30을 선택하면 간격이 20(>=15)이므로 유효합니다. 30 다음으로는 40을 선택할 수 있지만, 10, 30, 40을 선택할 경우 30과 40 사이는 10(<15)이므로 안 됩니다. 최적은 {10, 30} 또는 {10, 40}입니다.*

## 힌트

- 선택의 순서가 중요하므로, 먼저 점들을 오름차순으로 정렬해야 합니다.
- 이 문제는 그리디(Greedy) 알고리즘을 적용하여 점들을 하나씩 선택해 나가는 방식으로 접근할 수 있습니다.


## 알고리즘 요약

점들을 오름차순으로 정렬합니다. 그리고 첫 번째 점을 무조건 선택합니다. 현재 선택된 마지막 점의 위치를 기준으로, 다음으로 선택할 수 있는 가장 먼 점을 찾아 선택합니다. 이 과정을 반복하여 최대 개수를 구합니다.

## 풀이 해설

풀이 해설: 아이디어 → 단계 → 시간복잡도

1. 아이디어 (Greedy Approach):
이 문제는 최소 간격 K를 유지하면서 최대 개수를 뽑는 문제입니다. 그리디 알고리즘을 사용하면 최적의 해를 찾을 수 있습니다. 가장 직관적인 그리디 전략은 '현재까지 선택한 점 중 가장 늦게 선택된 점'을 기준으로, 다음으로 선택할 점을 최대한 멀리 떨어져 있는 점으로 선택하는 것입니다. 이렇게 함으로써 남은 점들에 대한 선택의 자유도를 최대화할 수 있습니다.

2. 단계:
단계 1: 정렬 (Sorting)
주어진 N개의 점 좌표들을 오름차순으로 정렬합니다. 이 과정은 필수적입니다.
단계 2: 그리디 탐색 (Greedy Traversal)
최대 개수 카운트를 1로 초기화하고, 첫 번째 점을 선택된 점으로 설정합니다. 현재 선택된 마지막 점의 인덱스(또는 위치)를 `last_index`로 기록합니다.
단계 3: 반복 및 선택
`last_index` 다음부터 점들을 순회하면서, 현재 점 $A[i]$와 마지막 선택된 점 $A[last_index]$의 차이 $A[i] - A[last_index]$가 K 이상인지 확인합니다.
만약 차이가 K 이상이라면, 이 점 $A[i]$를 선택하고, 카운트를 1 증가시키며, `last_index`를 현재 인덱스 $i$로 업데이트합니다. 이후 다음 점을 탐색합니다.
단계 4: 종료
모든 점을 탐색할 때까지 반복한 후, 최종 카운트 값을 반환합니다.

3. 시간 복잡도:
*   정렬: $O(N 	imes 	ext{log} N)$ (N은 점의 개수)
*   탐색: $O(N)$ (한 번만 순회)
총 시간 복잡도는 $O(N 	imes 	ext{log} N)$입니다. 이는 $N=10^5$까지 충분히 효율적입니다.

## 참고 코드 (java)

```java
import java.io.*;
import java.util.*;

public class Main {

    public static void main(String[] args) throws IOException {
        // 효율적인 입력을 위해 BufferedReader 사용
        BufferedReader br = new BufferedReader(new InputStreamReader(System.in));
        StringTokenizer st = new StringTokenizer(br.readLine());

        int N = Integer.parseInt(st.nextToken());
        long K = Long.parseLong(st.nextToken());

        // 점 좌표 배열을 저장합니다.
        long[] points = new long[N];
        st = new StringTokenizer(br.readLine());
        for (int i = 0; i < N; i++) {
            points[i] = Long.parseLong(st.nextToken());
        }

        // 1. 점들을 오름차순으로 정렬합니다. (O(N log N))
        Arrays.sort(points); 

        // 2. 그리디 알고리즘을 사용하여 최대 개수를 찾습니다. (O(N))
        int count = 1; // 최소한 첫 번째 점은 선택합니다.
        int lastIndex = 0; // 마지막으로 선택된 점의 인덱스

        for (int i = 1; i < N; i++) {
            // 현재 점과 마지막 선택된 점의 차이가 K 이상인지 확인합니다.
            if (points[i] - points[lastIndex] >= K) {
                // 조건을 만족하면 선택하고, 카운트와 인덱스를 업데이트합니다.
                count++;
                lastIndex = i;
            }
        }

        System.out.println(count);
    }
}
```
