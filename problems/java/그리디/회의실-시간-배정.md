# 회의실 시간 배정
*java · 그리디 · 보통 · 그리디, 정렬, 구간*

## 입출력 환경

Java 환경에서 표준 입력(System.in)을 통해 데이터를 읽고, 결과를 표준 출력(System.out)으로 작성해야 합니다. 입력 데이터는 공백으로 구분된 정수 쌍입니다.

## 문제

N개의 회의가 예정되어 있습니다. 각 회의는 시작 시간과 종료 시간을 가지는 구간 [시작, 종료]로 표현됩니다.
주어진 회의 목록 중에서 서로 겹치지 않는 최대 개수의 회의를 선택하여 스케줄을 짜려고 합니다. 
서로 겹치지 않는다는 것은 한 회의의 종료 시간이 다음 회의의 시작 시간보다 같거나 빨라야 함을 의미합니다. (예: [1, 3]과 [3, 5]는 겹치지 않음)

최대 개수의 회의를 선택하는 방법을 찾고, 그 개수를 출력하세요.

## 입력

첫 줄에 회의의 총 개수 N이 주어지고, 이후 N줄에 걸쳐 각 회의의 시작 시간(s)과 종료 시간(e)이 공백으로 구분되어 주어집니다. (s <= e)

## 출력

선택할 수 있는 최대 회의 개수를 하나의 정수로 출력합니다.

## 제약 조건

1. N의 범위: 1부터 100,000까지
2. 시간 범위: 시작 시간과 종료 시간은 1부터 10^9까지의 정수입니다.
3. 시간 복잡도: O(N log N) 이하를 목표로 합니다.

## 예제 1

**입력**
```
3
1 4
0 2
2 3
```

**출력**
```
2
```

*종료 시간이 가장 빠른 순으로 정렬하면 [0, 2], [2, 3], [1, 4]가 됩니다. 최대 2개의 회의([0, 2]와 [2, 3])가 가능합니다.*

## 예제 2

**입력**
```
4
1 5
2 3
6 8
4 6
```

**출력**
```
3
```

*최적의 스케줄은 [2, 3], [4, 6], [6, 8]이거나 [2, 3], [1, 5] 대신 [1, 5]를 선택하지 않고 [2, 3]을 선택하여 최대 3개를 만듭니다.*

## 힌트

- 이 문제는 그리디 알고리즘으로 해결할 수 있습니다.
- 어떤 기준으로 정렬해야 '가장 적은 시간'을 사용하는 활동을 선택할 수 있을까요?


## 알고리즘 요약

그리디 알고리즘 (Greedy Algorithm). 활동 선택 문제에서 가장 핵심적인 그리디 선택 기준은 '종료 시간이 가장 빠른 활동'을 우선적으로 선택하는 것입니다. 모든 활동을 종료 시간 기준으로 정렬한 뒤, 첫 번째 활동을 선택하고, 다음 활동 중 현재 선택된 활동의 종료 시간보다 늦게 시작하는 활동이면서 가장 이른 종료 시간을 가지는 활동을 순차적으로 선택합니다.

## 풀이 해설

### 💡 아이디어 (Greedy Choice)
활동 선택 문제(Activity Selection Problem)는 그리디 알고리즘의 대표적인 예시입니다. 핵심 아이디어는 '현재 시점에서 가장 빠르게 끝나는 활동을 선택하는 것'입니다. 이렇게 해야 다음 활동을 위한 여유 시간(남은 시간)을 최대화할 수 있기 때문입니다.

### 📚 단계별 풀이
1. **데이터 구조화**: 입력받은 모든 회의들을 (시작 시간, 종료 시간) 쌍의 배열 또는 리스트에 저장합니다.
2. **정렬**: 이 배열 전체를 '종료 시간(End Time)'을 기준으로 오름차순 정렬합니다. 만약 종료 시간이 같다면, 시작 시간을 기준으로 오름차순 정렬합니다.
3. **탐욕적 선택 (Greedy Selection)**: 
    a. 첫 번째 회의(가장 빨리 끝나는 회의)를 무조건 선택하고, 카운트를 1 증가시킵니다.
    b. 현재 선택된 회의의 종료 시간(lastFinishTime)을 기록합니다.
    c. 배열을 순회하면서, 현재 검사하는 회의의 시작 시간(currentStart)이 lastFinishTime보다 크거나 같은 경우 (즉, 겹치지 않는 경우)에만 해당 회의를 선택하고, lastFinishTime을 이 회의의 종료 시간으로 업데이트하며 카운트를 1 증가시킵니다.
4. **결과 반환**: 최종 카운트 값을 반환합니다.

### ⏱️ 시간 복잡도
*   **정렬**: N개의 회의를 종료 시간 기준으로 정렬하는 데 $O(N 	imes 	ext{log} N)$ 시간이 소요됩니다.
*   **순회**: 정렬된 배열을 한 번만 순회하므로 $O(N)$ 시간이 소요됩니다.
*   **총 시간 복잡도**: $O(N 	ext{ log } N)$, 이는 주어진 제약 조건 내에서 충분히 빠릅니다.

## 참고 코드 (java)

```java
import java.util.*;
import java.io.*;

class Meeting {
    long start;
    long end;

    public Meeting(long start, long end) {
        this.start = start;
        this.end = end;
    }
}

public class Solution {

    public static void main(String[] args) {
        // 표준 입력을 처리하기 위해 BufferedReader 사용
        BufferedReader br = new BufferedReader(new InputStreamReader(System.in));
        
        try {
            // 첫 줄에서 N (회의 개수) 읽기
            String line = br.readLine();
            if (line == null || line.isEmpty()) return; 
            int N = Integer.parseInt(line.trim());
            
            List<Meeting> meetings = new ArrayList<>();
            
            // 다음 N줄에서 회의 정보 읽기
            for (int i = 0; i < N; i++) {
                String[] parts = br.readLine().split("\s+");
                long start = Long.parseLong(parts[0]);
                long end = Long.parseLong(parts[1]);
                meetings.add(new Meeting(start, end));
            }
            
            // 1. 정렬: 종료 시간을 기준으로 오름차순 정렬 (가장 핵심 단계)
            // 종료 시간이 같으면 시작 시간을 기준으로 정렬하는 것이 일반적이지만, 여기서는 종료 시간만 기준으로 해도 충분합니다.
            meetings.sort(Comparator.comparingLong(m -> m.end));
            
            // 2. 그리디 선택을 통한 최대 개수 계산
            int count = 0;
            // 마지막으로 선택된 회의의 종료 시간. 매우 작은 값으로 초기화하여 첫 회의가 무조건 선택되도록 합니다.
            long lastFinishTime = Long.MIN_VALUE;

            for (Meeting meeting : meetings) {
                // 현재 회의의 시작 시간이 마지막으로 선택된 회의의 종료 시간보다 크거나 같은지 확인
                // (즉, 겹치지 않는지 확인)
                if (meeting.start >= lastFinishTime) {
                    // 겹치지 않으면 선택
                    count++;
                    // lastFinishTime을 현재 회의의 종료 시간으로 업데이트
                    lastFinishTime = meeting.end;
                }
            }

            System.out.println(count);
            
        } catch (IOException e) {
            // 예외 처리 (실제 코딩 테스트 환경에서는 필요 없을 수 있음)
            // e.printStackTrace();
        }
    }
}
```
