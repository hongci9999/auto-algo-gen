# 회의 시간 최대화
*java · 그리디 · 보통 · 그리디, 정렬*

## 입출력 환경

Java에서 입력을 처리할 때는 BufferedReader와 StringTokenizer를 사용하는 것이 효율적입니다.

## 문제

당신은 회의실 관리 시스템을 개발하는 개발자입니다. 주어진 N개의 회의 목록이 있습니다. 각 회의는 시작 시간과 종료 시간을 가집니다. 단, 회의가 겹치지 않도록 최대 몇 개의 회의를 선택할 수 있는지 구하는 것이 목표입니다.

회의가 겹친다는 것은 두 회의의 시간 구간이 하나라도 겹치는 경우를 의미합니다. 만약 회의 A가 [시작A, 종료A]이고 회의 B가 [시작B, 종료B]일 때, 종료A와 시작B가 같은 경우 (즉, A가 끝나고 B가 바로 시작하는 경우)는 겹치지 않는 것으로 간주합니다.

각 회의는 (시작 시간, 종료 시간) 쌍으로 주어집니다. 시간은 1부터 10^9 사이의 정수입니다.

## 입력

첫 번째 줄에 회의의 총 개수 N이 주어집니다. 
다음 N개의 줄에 각각 '시작 시간'과 '종료 시간'이 공백으로 구분되어 주어집니다.

## 출력

선택 가능한 최대 회의 개수(정수)를 출력합니다.

## 제약 조건

N: 1 ≤ N ≤ 100,000
시작/종료 시간: 1 ≤ 시간 ≤ 10^9
시간 복잡도: O(N log N) 이하 권장

## 예제 1

**입력**
```
3
1 4
2 5
4 6
```

**출력**
```
2
```

*시간이 겹치는 (1, 4)와 (2, 5)는 선택 불가. (1, 4)와 (4, 6)은 선택 가능.*

## 예제 2

**입력**
```
4
1 3
2 4
3 5
6 7
```

**출력**
```
3
```

*최적의 선택 순서: (1, 3) -> (3, 5) -> (6, 7). 총 3개.*

## 힌트

- 모든 회의를 무작정 선택하는 것이 아니라, '종료 시간'을 기준으로 우선순위를 정해야 합니다.
- 그리디 알고리즘을 사용하며, 정렬 기준을 신중하게 선택해야 합니다.


## 알고리즘 요약

그리디 알고리즘 (Greedy Algorithm). 활동 선택 문제(Activity Selection Problem)의 전형적인 예시입니다. 최대의 활동을 선택하려면, 매번 '가장 빨리 끝나는 활동'을 선택하는 것이 최적의 선택입니다. 따라서 모든 회의를 종료 시간 기준으로 오름차순 정렬한 후, 순차적으로 선택하며 다음 회의의 시작 시간이 이전 회의의 종료 시간보다 크거나 같은지 확인합니다.

## 풀이 해설

풀이 아이디어:
이 문제는 전형적인 '활동 선택 문제(Activity Selection Problem)'입니다. 주어진 회의들을 겹치지 않게 최대 개수를 선택하는 문제입니다. 이러한 유형의 문제는 그리디 알고리즘을 적용하여 해결할 수 있습니다.

그리디 전략:
최대 개수를 확보하기 위해서는, 현재 선택 가능한 활동 중 가장 빨리 끝나는 활동을 선택하는 것이 항상 최적의 선택입니다. 만약 빨리 끝나는 활동을 선택하지 않고 더 늦게 끝나는 활동을 선택하면, 그 활동이 차지하는 시간 때문에 이후에 선택할 수 있는 활동의 범위가 줄어들기 때문입니다.

풀이 단계:
1. **데이터 구조화 및 정렬:** 모든 회의를 (시작 시간, 종료 시간) 쌍으로 저장하고, 이 목록 전체를 **종료 시간(End Time)을 기준으로 오름차순 정렬**합니다. (만약 종료 시간이 같다면, 시작 시간이 빠른 순서로 정렬해도 무방합니다.)
2. **선택 과정:** 첫 번째 회의(가장 빨리 끝나는 회의)를 무조건 선택하고 카운트를 1로 초기화합니다.
3. **순차 탐색:** 정렬된 목록을 두 번째 회의부터 순회합니다. 현재 회의의 시작 시간이 이전에 선택된 회의의 종료 시간보다 크거나 같으면, 이 회의는 선택 가능합니다. 이 회의를 선택하고, 이전 선택된 회의의 종료 시간을 현재 회의의 종료 시간으로 업데이트하며 카운트를 1 증가시킵니다.
4. **결과:** 모든 회의를 순회한 후의 카운트가 최대 회의 개수입니다.

시간 복잡도:
- 정렬 과정: $O(N 	imes 	ext{log} N)$ (N은 회의 개수)
- 탐색 과정: $O(N)$
- 총 시간 복잡도: $O(N 	ext{ log } N)$

## 참고 코드 (java)

```java
import java.io.BufferedReader;
import java.io.InputStreamReader;
import java.io.IOException;
import java.util.Arrays;
import java.util.Comparator;
import java.util.StringTokenizer;

// 회의 정보를 담는 클래스
class Meeting {
    int start;
    int end;

    public Meeting(int start, int end) {
        this.start = start;
        this.end = end;
    }
}

public class Solution {

    public static void main(String[] args) {
        // 효율적인 입출력을 위해 BufferedReader 사용
        BufferedReader br = new BufferedReader(new InputStreamReader(System.in));
        
        try {
            // 첫 줄: 회의 개수 N 읽기
            String line = br.readLine();
            if (line == null || line.isEmpty()) return; 
            int N = Integer.parseInt(line.trim());

            if (N == 0) {
                System.out.println(0);
                return;
            }

            Meeting[] meetings = new Meeting[N];
            
            // 다음 N줄: 회의 정보 읽기
            for (int i = 0; i < N; i++) {
                StringTokenizer st = new StringTokenizer(br.readLine());
                int start = Integer.parseInt(st.nextToken());
                int end = Integer.parseInt(st.nextToken());
                meetings[i] = new Meeting(start, end);
            }

            // 1. 그리디 전략에 따라 종료 시간(end) 기준으로 정렬
            // Comparator를 사용하여 오름차순 정렬 (종료 시간 기준)
            Arrays.sort(meetings, Comparator.comparingInt(m -> m.end));

            // 2. 최대 선택 개수 계산
            int count = 1; // 첫 번째 회의는 무조건 선택
            int lastEndTime = meetings[0].end;

            for (int i = 1; i < N; i++) {
                Meeting currentMeeting = meetings[i];
                
                // 현재 회의의 시작 시간이 이전에 선택된 회의의 종료 시간보다 크거나 같은지 확인
                if (currentMeeting.start >= lastEndTime) {
                    // 선택 가능하므로 카운트 증가 및 종료 시간 갱신
                    count++;
                    lastEndTime = currentMeeting.end;
                }
            }

            System.out.println(count);

        } catch (IOException e) {
            // 예외 처리 로직 생략
        }
    }
}
```
