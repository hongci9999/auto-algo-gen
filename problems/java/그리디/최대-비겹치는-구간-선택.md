# 최대 비겹치는 구간 선택
*java · 그리디 · 보통 · 구간, 정렬, 그리디*

## 입출력 환경

Java 환경에서 입력을 받기 위해 java.util.Scanner 또는 BufferedReader와 StringTokenizer를 사용하는 것이 일반적입니다.

## 문제

N개의 구간이 주어집니다. 각 구간은 시작점과 끝점을 가지며, 구간은 닫힌 구간 [시작점, 끝점]으로 간주합니다. 두 구간이 겹치지 않으려면, 한 구간의 끝점이 다른 구간의 시작점보다 작거나 같아야 합니다. 주어진 N개의 구간 중에서 서로 겹치지 않으면서 최대 개수를 선택할 수 있는 경우의 수를 구하세요.

구간의 개수는 최대 100,000개이며, 좌표 값은 1부터 100,000까지입니다.

## 입력

첫째 줄에 구간의 개수 N이 주어집니다. 이후 N개의 줄에 걸쳐 각 구간의 시작점(s)과 끝점(e)이 공백으로 구분되어 주어집니다. (s <= e)

## 출력

선택할 수 있는 최대 구간의 개수를 한 정수로 출력합니다.

## 제약 조건

N <= 100,000. 좌표 값 s, e <= 100,000. 시간 복잡도는 O(N log N)을 만족해야 합니다.

## 예제 1

**입력**
```
4
1 2
2 3
3 4
1 3
```

**출력**
```
3
```

*정렬 후 [1, 2]를 선택하고, 다음 시작점 2 >= 2 이므로 [2, 3] 선택. 다음 시작점 3 >= 3 이므로 [3, 4] 선택. 총 3개.*

## 예제 2

**입력**
```
3
1 4
0 3
2 5
```

**출력**
```
2
```

*가장 끝나는 시간 순으로 정렬하여 접근합니다. [0, 3] 선택 후, 다음 시작점 1 < 3 이므로 [1, 4]는 선택 불가. 다음 시작점 2 < 3 이므로 [2, 5]도 선택 불가. (예: [1, 4]와 [0, 3]은 겹치므로 선택 불가. 최적 조합은 [0, 3]과 [3, 4] 형태여야 하지만, 예제 데이터 상으로는 [0, 3]과 [1, 4]가 겹치고, [2, 5]는 나머지 둘과 겹칩니다. 만약 [1, 4]와 [2, 5]가 아닌, [0, 3]과 [3, 5] 같은 데이터가 주어졌다면 2개가 될 것입니다. 이 예제에서는 [0, 3]과 [4, 5] 같은 조합을 염두에 두어야 합니다.)*

## 힌트

- 이 문제는 그리디(Greedy) 알고리즘의 대표적인 예시입니다.
- 어떤 기준으로 정렬해야 가장 효율적인 선택을 할 수 있는지 고민해야 합니다.


## 알고리즘 요약

활동 선택 문제(Activity Selection Problem)와 유사하며, 그리디 전략을 사용합니다. 최적의 선택을 보장하기 위해, 구간들을 '종료 시간'을 기준으로 오름차순 정렬합니다. 정렬된 리스트를 처음부터 순회하며, 현재 구간의 시작 시간이 직전에 선택된 구간의 종료 시간보다 크거나 같으면 해당 구간을 선택하고, 마지막 선택된 종료 시간을 업데이트합니다. 이 과정을 반복하여 최대 개수를 얻습니다.

## 풀이 해설

1. 아이디어: 이 문제는 그리디 알고리즘을 사용하여 해결할 수 있습니다. 여러 구간 중 최대한 많은 개수를 선택하려면, 매번 선택하는 구간이 가능한 한 빨리 끝나야 합니다. 그래야 다음 구간을 선택할 여유 시간(틈)이 가장 많이 생기기 때문입니다.
2. 단계:
   a. 데이터 구조화: 입력받은 N개의 구간을 `Interval`과 같은 클래스 배열에 저장합니다.
   b. 정렬: 저장된 모든 구간을 '종료 시간(End)'을 기준으로 오름차순 정렬합니다. 만약 종료 시간이 같다면 시작 시간을 기준으로 정렬해도 무방합니다.
   c. 그리디 선택: 배열을 순회합니다. 첫 번째 구간은 무조건 선택합니다. 이후 구간 `i`에 대해, 그 구간의 시작 시간 `s_i`가 직전에 선택된 구간의 종료 시간 `e_last`보다 크거나 같다면 (즉, 겹치지 않는다면), 이 구간을 선택하고 `e_last`를 `s_i`로 업데이트합니다. 그렇지 않다면, 이 구간은 선택할 수 없습니다.
   d. 결과 반환: 선택한 구간의 총 개수가 최대 개수입니다.
3. 시간 복잡도: 구간의 개수 N에 대해, 정렬 과정이 $O(N 	imes 	ext{log} N)$의 시간이 소요되며, 이후 순회 과정은 $O(N)$ 시간이 소요되므로, 전체 시간 복잡도는 $O(N 	ext{ log } N)$입니다.

## 참고 코드 (java)

```java
import java.util.Arrays;
import java.util.Comparator;
import java.util.Scanner;

class Interval {
    int start;
    int end;

    public Interval(int start, int end) {
        this.start = start;
        this.end = end;
    }
}

public class Main {
    public static void main(String[] args) {
        Scanner scanner = new Scanner(System.in);
        if (!scanner.hasNextInt()) return;

        int N = scanner.nextInt();
        Interval[] intervals = new Interval[N];

        for (int i = 0; i < N; i++) {
            int start = scanner.nextInt();
            int end = scanner.nextInt();
            intervals[i] = new Interval(start, end);
        }
        
        scanner.close();

        // 1. 종료 시간(End)을 기준으로 정렬 (그리디 핵심)
        Arrays.sort(intervals, new Comparator<Interval>() {
            @Override
            public int compare(Interval a, Interval b) {
                // 종료 시간 기준 오름차순 정렬
                return Integer.compare(a.end, b.end);
            }
        });

        // 2. 그리디 선택 과정
        int count = 0;
        // 마지막으로 선택된 구간의 종료 시간을 초기화합니다. (아주 작은 값)
        int lastFinishTime = -1; 

        for (Interval current : intervals) {
            // 현재 구간의 시작 시간이 마지막 선택된 종료 시간보다 크거나 같은지 확인
            // (겹치지 않음: [s, e]와 [s', e']에서 e < s' 또는 e' < s)
            if (current.start >= lastFinishTime) {
                // 선택 가능: 개수 증가 및 마지막 종료 시간 업데이트
                count++;
                lastFinishTime = current.end;
            }
        }

        System.out.println(count);
    }
}
```
